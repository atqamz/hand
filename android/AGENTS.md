# Hand's Companion

The Android app of Hand: native Jetpack Compose screens over a Rust core, Android only. It dials a host's `hand-iroh` sidecar over iroh, reads the Board's `/api/v1` and draws it, and opens the Board's pages in a plain `WebView` where no native screen exists yet. Status: the iroh dialer, the loopback proxy, pairing, the alert feed and its foreground service, the session store and the native fleet, Needs, Tasks, Decision, Pair and fallback screens are built; the signed release build is built, and publishing it is not. See the roadmap in `README.md`.

## Rules

- Smallest correct change. Delete before adding. Follow what the surrounding code does.
- No code comments. Names, types and tests carry what the code does. Keep only lines a tool reads, such as linter directives.
- No dependency, abstraction, compatibility layer or configuration without a concrete need. The pull request that adds a dependency says why the standard library or an existing crate does not do. Pin Rust dependencies exactly (`=x.y.z`) and commit `Cargo.lock`.
- Tests carry behaviour. Docs carry only what code cannot say: why, measurements, external constraints, failure modes, manual steps.
- Before committing, run `cargo fmt --all --check`, `cargo clippy --locked --workspace --all-targets --target aarch64-linux-android -- -D warnings` and `cargo test --locked --workspace` with `HAND_IROH_BIN` set to a sidecar built from `iroh/` in this checkout, as `README.md` says. A change to `src-tauri/` or the Gradle project also builds the debug APK with `./gradlew :app:assembleDebug` and runs `./gradlew :app:verifyPaparazziUniversalDebug` in `src-tauri/gen/android` (`README.md`).
- Commits are small, imperative, lowercase-first, without a trailing period. Never bypass hooks or signing.

## Layout

- `core/`: `hand-android-core`, plain Rust. The iroh dialer, the loopback proxy, the session store, pairing, the alert feed and the HTTP exchange go here, with tests that run on the host. Its sidecar tests need `HAND_IROH_BIN`; they skip without it.
- `src-tauri/`: the JNI crate. `src/host.rs` is the one JNI entry that starts the core for the service and the Activity, and the calls back into Kotlin (Keystore sealing, cookie read, notifications). It owns the core's tokio runtime and holds no logic of the app. Its only target is Android, so `cargo clippy` for it runs with `--target aarch64-linux-android`.
- `src-tauri/gen/android/app/src/main/java/.../HandActivity.kt` and the files beside it are the native Compose screens and the launcher. `app/src/test/snapshots/` holds Paparazzi's stored images; replace them only with `./gradlew :app:recordPaparazziUniversalDebug`, never by hand.
- `src-tauri/gen/android/`: the Android project, edited by hand. `app/build.gradle.kts` runs `cargo build --locked --target <abi>` as `cargoDebug` and `cargoRelease`, and the variant API takes their output as the generated `jniLibs` folder, so `:app:assembleDebug` and `:app:assembleUniversalRelease` build the library. `NDK_HOME` must point at the NDK; the task derives the clang, linker and `llvm-ar` paths from it.

## Android

- Two keys. The committed debug key `src-tauri/gen/android/app/debug.keystore` (public password `android`) signs every debug build, and CI fails when a debug APK's signer SHA-256 is not that key's. The release key lives only in the `release` GitHub environment's secrets (`RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD`, never repository-level) and, as a backup, with the operator. No release key, keystore, password or `keystore.properties` goes into the repository, a pull request, a log, a report or any other CI job; `.gitignore` keeps `*.jks`, `*.p12`, `*.pfx`, `*.keystore` and `keystore.properties` out. Never print one, never `set -x` near one, never pass one on a command line. Gradle has no release signing config: the key meets only `apksigner`, in the last step of the release job, so no build script, proc macro or Gradle plugin sees it.
- Release: a tag `android-vMAJOR.MINOR.PATCH` runs `.github/workflows/android-release.yaml` in the `release` environment and leaves a draft release with `--latest=false`, so it never takes Hand's latest. The tag, `version` and `versionCode` in `android/version.properties` agree (`versionCode = MAJOR*1000000 + MINOR*1000 + PATCH`), the APK is arm64-v8a only, and its signer must equal `release-key.sha256`. The job fails when that file is not one line of 64 lowercase hex digits or the APK's signer digest differs. Only the maintainer tags, publishes a draft after trying its APK on the phone, and releases.
- R8 is on for the release variant. Rust reaches Kotlin by name through JNI (`Core`, `AppHost`), so `proguard-rules.pro` keeps `Core` and `AppHost` whole, and `android/scripts/check-jni-keep.sh` fails CI when a class, native or method that `src-tauri/src` names is missing from the release APK. A new JNI call needs a keep rule in the same change.
- Cleartext: the web view opens the Board at `http://localhost:PORT`, by the name `localhost`, never at `http://127.0.0.1:PORT` or `http://[::1]:PORT`: a real phone refused the IP forms. `res/xml/network_security_config.xml` forbids cleartext everywhere and permits it for the host `localhost` without subdomains. Do not set `usesCleartextTraffic`, add `cleartextTrafficPermitted="true"` elsewhere or add another domain.
- iOS is deferred. Add nothing for it.
- Pin the toolchain in one place each: Rust in `rust-toolchain.toml`, the composite action `.github/actions/build-signed-apk/action.yml` that `android-release.yaml` and `android.yaml`'s `main-apk` job run, and `README.md` (move them together), Gradle, the Android Gradle plugin, the AndroidX and Compose libraries and Paparazzi in `src-tauri/gen/android`.

## Contract with Hand

Hand is the Board on the host. This app is the dialer of its `hand-iroh` sidecar, so every fact below is Hand's and changes there first. The contract is `docs/companion.md` with its vectors in `docs/companion-vectors.json`, and the sidecar is `iroh/`, both beside this folder in one checkout: a change to either is tested against the other in the same pull request, and `core/` reads the vectors by path, so `core/` builds only inside this repository. `docs/companion-app.md` describes the peer listener and the sidecar. When one of them disagrees with this file, they win; fix this file.

- Transport: iroh, pinned to the sidecar's version (`iroh = "=1.4.1"` there), ALPN `hand-board`. The app dials the host's endpoint ID, through a relay or directly. Endpoint IDs are not secrets and iroh admits any dialer that completes the handshake; the Board decides who is paired.
- Streams: one bidirectional QUIC stream per loopback TCP connection, and bidirectional only: the sidecar allows no unidirectional stream. At most 12 streams are open on a connection, and new ones are accepted at 20 a second after a burst of 12. Finishing the send side is the upload's end of file, and the Board's end of file finishes the stream.
- The dialer sends HTTP bytes and nothing else. It never writes the peer preface (`HAND-PEER 1 PEERID SECRET`): the sidecar writes it to the Board, with the secret the Companion never holds and the Companion's endpoint ID.
- Idle and limits: the sidecar resets a stream that moves no byte for 60 seconds by default and closes a connection on which no stream moved a byte for as long. A connection is closed with code 1 when the sidecar is full and 2 when idle; a stream is reset with code 3 when the Board is unreachable, 4 when idle and 5 when the Board's connection broke. The app reconnects on resume and after code 2, and never retries code 1 in a tight loop.
- Identity: the Companion's iroh key is its identity. The Board binds a paired device to `iroh:<endpoint ID>`, so the key stays out of logs and backups. An unpaired key reaches only `/<fleet id>/pair` and the files that page loads, under small byte and request limits.
- Pairing link: it carries the host's endpoint ID, a relay URL, the fleet ID and a one-time code, in the URL fragment so that no server sees it (`handboard://c#v1.…` in the design). The contract document is the only source of its grammar. Never log, persist or send the fragment, and never put it in a crash report.
- Several hosts: one Companion may hold any number of hosts, one connection each from one iroh endpoint (`Dialers`). The fleet ID is the key and the host an attribute of its fleets: every request, feed loop and live stream finds its dialer from the fleet, a fleet ID is held once (a pairing that names one another host holds is refused with `fleet_held`, before the host is asked when the link's fleet is that one), and `Sessions::header_for` is the only reader of a host's cookies: no call joins the cookies of every host, so a fleet's secret reaches only a stream on its own host's connection. Every host sees the same Companion endpoint ID. Forget on one host (`Core.forgetHost`) removes that host locally and sends nothing to it.
- Native pairing: `POST /<fleet id>/api/v1/pair` with `{code, name}`, on a second dialer, so every held pairing stays usable until the Board answers. A pairing adds the host, or its fleets to the host it names; it forgets nothing. The code, the device secret and the pending link never leave Rust: Kotlin passes the link and the name in, and gets IDs, names and sentences out. The answer is stored only if it has the contract's shape (`cookie_value` matches `^[1-9][0-9]*\.[0-9a-f]{64}$`). The store write is one sealed write that either happens whole or changes nothing, and the web view's jar is cleared only after it. The sentences for each error code are the contract's.
- The session store is the only source of pairings. When `sessions/sessions.sealed` is missing, the first read — `Sessions::listed`, `hosts`, `cookie`, or `Sessions::pair` (which calls the import directly before it writes) — imports the `laptop` and `laptop-relay` files and the web view's `hand_phone_` cookies once, writes the store and deletes the files; a store that exists and still has the files takes the relay from them and deletes them. Every later call reads the store and never the jar or the files, so the jar the fallback fills cannot change a pairing.
- Alert feed: `GET /<fleet id>/alerts/feed?after=<seq>&wait=25`, one long poll per paired fleet, each holding one of the 12 streams. The request is HTTP bytes only, with `Host: localhost`, only the cookie `hand_phone_<fleet id>` and `Connection: close`; the answer is read by its `Content-Length`, at most 64 KiB, never chunked. The core refuses an answer for another fleet, a wrong version, a replay on a first poll, a seq that does not grow, a cursor that is not the last seq, or more than 50 alerts, and treats it as a failed poll, which backs off 1 s doubling to 5 minutes; a resume or `Core.networkChange` ends a backoff wait and resets it. A `link` is kept only when `parse_open` accepts it for the polled fleet; the alert is shown without it otherwise. The cursor in `<app data>/alerts/<fleet id>.cursor` moves only after the sink has posted every alert of an answer, because the next request is the Board's receipt. A 403 "no longer paired" stops that fleet, keeps its cursor, notifies once and is tried again after 5 minutes or when the cookie value changes; a second one in a row deletes the cursor. A missing cookie stops the fleet and deletes its cursor. Forget bumps a generation that the loop checks before each notification and each cursor write. The cookie is read from the core's sealed session store each poll and never logged; the feed client needs neither an Activity nor Android, so a foreground service can host it. The store (`core/src/sessions.rs`) is one file sealed with the Keystore key that seals the iroh key and written by rename; its one import is described above. Forget clears the jar before the store. An unreadable file is renamed to `sessions.sealed.bad`, replacing an older one so only the latest bad file is kept, and the app starts empty.

- Idle duty cycle: after 2 minutes of screen-off with no charger, counted by an `ELAPSED_REALTIME_WAKEUP` alarm so suspended time counts, `AlertService` (`IdleCycle`, pure Kotlin) stops the feed loops and the live stream and closes the iroh endpoint (`Core.sleep`); it keeps the proxy listener and the key, so the loopback port and the endpoint ID stay. A `setAndAllowWhileIdle` alarm every 5 minutes (`PollReceiver`, no exact-alarm permission) calls `Core.poll`, which binds the endpoint again, runs `Feed::once` for every paired fleet with `wait=0` (the same cursor, notification and refusal rules as the live loop, and the same `more` follow-up) with a 30 second deadline on the polling alone, and closes it; the hosts run concurrently, each inside its own 28 second deadline, so a dead host takes none of another host's time. One endpoint serves every host: `Dialers::close` and `Dialers::open` mark and swap it under every dialer, and a dialer made while asleep starts down. A poll that reached no fleet doubles the next alarm gap, 5 to 40 minutes; an answer or a wake resets it. Screen on, unlock or a charger call `Core.wake` and `Core.watch`: a new endpoint, the live feed from the stored cursor; a failed `Core.wake` is retried by an alarm after 30 seconds, at most 3 times. `Companion` holds a lock across sleep, wake and poll, so a wake that lands in a poll waits for it: at most 30 seconds plus the bind before the polling and the close after it. `Dialer::close` makes every dial fail at once with `Lost` and leaves the notice and the backoff alone; `Dialer::open` swaps the endpoint and clears them. The poll and the sleep hold a 60 second partial wake lock. `Core.sleep` pauses the supervisor and keeps its memory of refused fleets, so the second refusal across idle cycles still deletes the cursor; only a service stop clears it. A refused fleet is polled again at the next alarm, always at least 5 minutes later, or when its cookie changes; the live loop's 5 minute retry runs on the monotonic clock and only while the app is awake. The metrics line carries `state`, `sleeps`, `wakes` and `polls`.
- Live stream: `GET /<fleet id>/api/v1/events` is one held stream for the fleet on screen, a chunked `text/event-stream` with no envelope and no `?since=`. It sends `hello`, `status` and a snapshot `timeline` on connect, then `status` when it changed, `timeline` upserts, `touched` topics and refs, `resync` for an event over 64 KiB, and `beat` every 15 s of silence; a reconnect gets a fresh snapshot. Each event's `data` is one JSON object on one line, and `beat` has no data. The app keeps the send side open, treats 35 s without a byte as lost, reconnects with the dialer's backoff, and holds the stream only while the fleet's screen is started. Events cross JNI as `live(fleet, topic, json)` with the payload untouched; the link crosses as `link(fleet, state, since)` with states `live`, `reconnecting`, `stopped` and `unpaired`; a `stopped` end makes the app poll again, an `unpaired` end stops the fleet, and the app filters links by the fleet it holds.

Lock order: `Companion::store` is always taken before the pairing mutex, which is taken before the session store's data mutex; the `Dialers` mutex (and `proxy::Slot`'s) comes last, is a leaf, and is never held across an await (the compiler refuses it: `Route` needs a `Send` future). The sites that take `store` are `forget_all`, `forget_host` and `settle` in `core/src/companion.rs`. A store write and the store clear must not interleave, so a new site takes `store` first; one that takes it while holding `pairing`, the data mutex or the `Dialers` mutex deadlocks and no test can catch it.
