# Hand's Android Companion

The phone app of Hand: a Tauri 2 shell around a Rust core, Android only. It dials a laptop's `hand-iroh` sidecar over iroh and shows the Board in a web view. Status: roadmap steps 1 to 4 are built (the iroh dialer, the loopback proxy and web view, pairing from an intent, a paste or a QR scan), and so are the alert feed client and the foreground service that turns its alerts into notifications; the signed release build is built, and publishing it is not. See the roadmap in `README.md`.

## Rules

- Smallest correct change. Delete before adding. Follow what the surrounding code does.
- No code comments. Names, types and tests carry what the code does. Keep only lines a tool reads, such as linter directives.
- No dependency, abstraction, compatibility layer or configuration without a concrete need. The pull request that adds a dependency says why the standard library or an existing crate does not do. Pin Rust dependencies exactly (`=x.y.z`) and commit `Cargo.lock`.
- Tests carry behaviour. Docs carry only what code cannot say: why, measurements, external constraints, failure modes, manual steps.
- Before committing, run `cargo fmt --all --check`, `cargo clippy --locked --workspace --all-targets --target aarch64-linux-android -- -D warnings` and `cargo test --locked --workspace` with `HAND_IROH_BIN` set to a sidecar built from `iroh/` in this checkout, as `README.md` says. A change to `src-tauri/` also builds the debug APK and runs `./gradlew :app:verifyPaparazziUniversalDebug` in `src-tauri/gen/android` (`README.md`).
- Commits are small, imperative, lowercase-first, without a trailing period. Never bypass hooks or signing.

## Layout

- `core/`: `hand-android-core`, plain Rust with no Tauri in it. The iroh dialer, the loopback proxy and the pairing logic go here, with tests that run on the host. Its sidecar tests need `HAND_IROH_BIN`; they skip without it.
- `src-tauri/`: the Tauri shell. It registers commands that call the core and holds no logic of its own. `src/host.rs` is the one JNI entry that starts the core for the service and the Activity, and the calls back into Kotlin (Keystore sealing, cookie read, notifications). Its only target is Android, so `cargo clippy` for it runs with `--target aarch64-linux-android`: a host build would need the desktop web view libraries.
- `src-tauri/gen/android/app/src/main/java/.../HandActivity.kt` and the files beside it are the native Compose screens and the launcher in every build type; `MainActivity` (Tauri) has no manifest entry of its own, only the alias `.MainActivity` to `HandActivity` for the old home-screen icon, and goes in A7. `app/src/test/snapshots/` holds Paparazzi's stored images; replace them only with `./gradlew :app:recordPaparazziUniversalDebug`, never by hand.
- `web/`: the bundled first screen. Static files, no build step, no npm.
- `src-tauri/gen/android/`: made once by `cargo tauri android init`, committed and edited by hand since. Running `init` again overwrites our edits to `AndroidManifest.xml`, `app/build.gradle.kts` (including its `signingConfigs` block) and `res/xml/network_security_config.xml`; redo them from the Android rules below.
- Capabilities: the IPC capability, if any is ever added, names the bundled page only, never the Board's origin.

## Android

- Two keys. The committed debug key `src-tauri/gen/android/app/debug.keystore` (public password `android`) signs every debug build, and CI fails when a debug APK's signer SHA-256 is not that key's. The release key lives only in the `release` GitHub environment's secrets (`RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD`, never repository-level) and, as a backup, with the operator. No release key, keystore, password or `keystore.properties` goes into the repository, a pull request, a log, a report or any other CI job; `.gitignore` keeps `*.jks`, `*.p12`, `*.pfx`, `*.keystore` and `keystore.properties` out. Never print one, never `set -x` near one, never pass one on a command line. Gradle has no release signing config: the key meets only `apksigner`, in the last step of the release job, so no build script, proc macro or Gradle plugin sees it.
- Release: a tag `android-vMAJOR.MINOR.PATCH` runs `.github/workflows/android-release.yaml` in the `release` environment and leaves a draft release with `--latest=false`, so it never takes Hand's latest. The tag, `version` and `bundle.android.versionCode` in `src-tauri/tauri.conf.json` agree (`versionCode = MAJOR*1000000 + MINOR*1000 + PATCH`, a literal in that file), the APK is arm64-v8a only, and its signer must equal `release-key.sha256`. The job fails when that file is not one line of 64 lowercase hex digits or the APK's signer digest differs. Only the maintainer tags, publishes a draft after trying its APK on the phone, and releases.
- R8 is on for the release variant. Rust reaches Kotlin by name through JNI (`Core`, `AppHost`, the two Tauri plugins), so `proguard-rules.pro` keeps `Core` and `AppHost` whole, and `android/scripts/check-jni-keep.sh` fails CI when a class, native or method that `src-tauri/src` names is missing from the release APK. A new JNI call needs a keep rule in the same change.
- Cleartext: the web view opens the Board at `http://localhost:PORT`, by the name `localhost`, never at `http://127.0.0.1:PORT` or `http://[::1]:PORT`: a real phone refused the IP forms. `res/xml/network_security_config.xml` forbids cleartext everywhere and permits it for the host `localhost` without subdomains. Do not set `usesCleartextTraffic`, add `cleartextTrafficPermitted="true"` elsewhere or add another domain.
- iOS is deferred. Add nothing for it.
- Pin the toolchain in one place each: Rust in `rust-toolchain.toml`, `tauri-cli` in `.github/workflows/android.yaml`, the composite action `.github/actions/build-signed-apk/action.yml` that `android-release.yaml` and `android.yaml`'s `main-apk` job run, and `README.md` (move them together with the `tauri` and `tauri-build` crates), Gradle, the Android Gradle plugin, the AndroidX and Compose libraries and Paparazzi in `src-tauri/gen/android`.

## Contract with Hand

Hand is the Board on the laptop. This app is the dialer of its `hand-iroh` sidecar, so every fact below is Hand's and changes there first. The contract is `docs/companion.md` with its vectors in `docs/companion-vectors.json`, and the sidecar is `iroh/`, all beside this folder in one checkout: a change to either is tested against the other in the same pull request, and `core/` reads the vectors by path, so `core/` builds only inside this repository. `docs/phone.md` describes the peer listener and the sidecar. When one of them disagrees with this file, they win; fix this file.

- Transport: iroh, pinned to the sidecar's version (`iroh = "=1.4.1"` there), ALPN `hand-board`. The app dials the laptop's endpoint ID, through a relay or directly. Endpoint IDs are not secrets and iroh admits any dialer that completes the handshake; the Board decides who is paired.
- Streams: one bidirectional QUIC stream per loopback TCP connection, and bidirectional only: the sidecar allows no unidirectional stream. At most 12 streams are open on a connection, and new ones are accepted at 20 a second after a burst of 12. Finishing the send side is the upload's end of file, and the Board's end of file finishes the stream.
- The dialer sends HTTP bytes and nothing else. It never writes the peer preface (`HAND-PEER 1 PEERID SECRET`): the sidecar writes it to the Board, with the secret the phone never holds and the phone's endpoint ID.
- Idle and limits: the sidecar resets a stream that moves no byte for 60 seconds by default and closes a connection on which no stream moved a byte for as long. A connection is closed with code 1 when the sidecar is full and 2 when idle; a stream is reset with code 3 when the Board is unreachable, 4 when idle and 5 when the Board's connection broke. The app reconnects on resume and after code 2, and never retries code 1 in a tight loop.
- Identity: the phone's iroh key is its identity. The Board binds a paired device to `iroh:<endpoint ID>`, so the key stays out of logs and backups. An unpaired key reaches only `/<fleet id>/pair` and the files that page loads, under small byte and request limits.
- Pairing link: it carries the laptop's endpoint ID, a relay URL, the fleet ID and a one-time code, in the URL fragment so that no server sees it (`handboard://c#v1.…` in the design). The contract document is the only source of its grammar. Never log, persist or send the fragment, and never put it in a crash report.
- Native pairing: `POST /<fleet id>/api/v1/pair` with `{code, name}`, on a second dialer, so the old pairing stays usable until the Board answers. The code, the device secret and the pending link never leave Rust: Kotlin passes the link and the name in, and gets IDs, names and sentences out. The answer is stored only if it has the contract's shape (`cookie_value` matches `^[1-9][0-9]*\.[0-9a-f]{64}$`). The store write is one sealed write that either happens whole or changes nothing, and the web view's jar is cleared only after it. The sentences for each error code are the contract's.
- Alert feed: `GET /<fleet id>/alerts/feed?after=<seq>&wait=25`, one long poll per paired fleet, each holding one of the 12 streams. The request is HTTP bytes only, with `Host: localhost`, only the cookie `hand_phone_<fleet id>` and `Connection: close`; the answer is read by its `Content-Length`, at most 64 KiB, never chunked. The core refuses an answer for another fleet, a wrong version, a replay on a first poll, a seq that does not grow, a cursor that is not the last seq, or more than 50 alerts, and treats it as a failed poll. A `link` is kept only when `parse_open` accepts it for the polled fleet; the alert is shown without it otherwise. The cursor in `<app data>/alerts/<fleet id>.cursor` moves only after the sink has posted every alert of an answer, because the next request is the Board's receipt. A 403 "no longer paired" stops that fleet, keeps its cursor, notifies once and is tried again after 5 minutes or when the cookie value changes; a second one in a row deletes the cursor. A missing cookie stops the fleet and deletes its cursor. Forget bumps a generation that the loop checks before each notification and each cursor write. The cookie is read from the core's sealed session store each poll and never logged; the feed client depends on neither Tauri nor an Activity, so a foreground service can host it. The store (`core/src/sessions.rs`) is one file sealed with the Keystore key that seals the iroh key, written by rename, and it imports the web view's `hand_phone_<fleet id>` cookies at each read until Tauri stops pairing into the jar, dropping an imported fleet the jar lost. Forget clears the jar before the store, so an import never brings a fleet back. An unreadable file is renamed to `sessions.sealed.bad`, replacing an older one so only the latest bad file is kept, and the app starts empty.
