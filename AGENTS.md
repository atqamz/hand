# Hand (next)

Personal supervisor layer for agents. Read `docs/spec.md` before changing anything.

- A new feature lands in `/api/v1` first, and no Board page gets a feature the API lacks.
- Terms follow `docs/vocabulary.md`; update it when a term, state, wake kind or ref changes.
- Standard library first. The dependencies are `modernc.org/sqlite`, `golang.org/x/sys` (already one of its own) for macOS process start times, and `github.com/egoist/mygo` v0.7.4 (pinned; Dependabot ignores it) for the desktop window, which is cgo-free. `iroh/` is a separate Rust crate that builds `hand-iroh`; it adds no Go dependency, and a change there runs `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings` and `cargo test --locked` in `iroh/` (`docs/companion-app.md`); `internal/board/peer.go` and `iroh/src/preface.rs` write the same preface grammar, so a change to either runs the `Iroh` workflow, which also runs the `internal/sidecar` and `internal/board` tests that need the real `hand-iroh` (`TestRealSidecar*` and `TestRealClient*`; `HAND_IROH_BIN`, absolute path; they skip without it). The sidecar's version is pinned once, in `internal/sidecar`, and a test keeps it equal to `iroh/Cargo.toml`: bump both together.
- `android/` is the Companion app: native Jetpack Compose screens over a Rust core through JNI, Android only. Read `android/AGENTS.md` before touching it. Its gate is `cargo fmt --all --check`, clippy for `aarch64-linux-android`, `cargo test --locked --workspace` with `HAND_IROH_BIN` built from `iroh/` in this checkout, the debug APK and Paparazzi, all in the `Android` workflow, which runs inside `android/` but for its sidecar step in `iroh/`, and which an `iroh/` change also runs. Its release tag is `android-v*`, and every app release is created with `--latest=false` because `hand update` resolves `/releases/latest` (`docs/update.md`). The vectors are `docs/companion-vectors.json`; `android/core` reads that file by path, so it builds only inside this repository.
- No code comments unless a hidden constraint needs one (≤3 lines).
- Every state change goes through `internal/state` in one transaction that also appends an event, except an `alert` row (the change it announces has its own event).
- Output is TOON via `internal/toon`; keep `hand orient` within its byte budget.
- Run `gofmt -l .`, `go vet ./...` and `go test -race ./...` before committing.
- A test in `internal/cli` calls `t.Parallel()` first unless it touches process-wide state: `t.Setenv`, `t.Chdir`, a `cli.*` hook or timing variable (assigned, or passed by pointer to a helper such as `setWait`), or a luvus binary that `luvus pin` or `hand init` copies and runs. Write a test executable with `fakebin.WriteExecutable`, which keeps a concurrent fork from holding it open ("text file busy").
- `.github/e2e` drives a release build as a user does, in CI on all three OSes (`docs/dogfood/README.md`); a change to the rows `hand doctor` prints, what `hand update` reports or a Board route changes its assertions too.
- `.github/render` renders the Board's fixture scenes (`TestRenderScenes` in `internal/board/scenes_test.go`) in CI on all three OSes and asserts the layout (`docs/dogfood/README.md`); a Board change that adds a page, region or fixture state adds a scene there too.
- `hand-desktop` is built by `.github/scripts/build-desktop.sh` for Linux amd64 and arm64, macOS arm64 and amd64 and Windows amd64 and published with the same release as `hand`. Its name, its version/commit stamp and its support (Linux and macOS, and Windows for `edge` builds, keyed by the channel `build-desktop.sh` stamps; the Windows asset on a stable build is built and checked by `.github/desktop/check-assets.sh`, not fetched) live in `internal/desktopasset`, `.github/desktop/check-stamp.sh` builds the Windows asset with a probe channel and checks the exe carries it, and `.github/desktop/smoke.sh` checks that `hand-desktop --version` prints what `hand version` does. `hand update` fetches it only where `desktopasset.Supported` says the window can run, and `hand doctor` has a `desktop` row, and on Windows a `desktop window` row and a `start menu shortcut` row (the shortcut is written by `internal/launcher` through one fixed PowerShell call, and a `Hand.lnk` that is not Hand's is not changed or removed, except in the narrow window between the check and the save), and on macOS a `desktop window` row that says `untested on a real Mac` and a `desktop app` row (`internal/launcher` writes `~/Applications/Hand.app` from the verified window binary, which `desktopasset.Path` places inside it, with `MacOS/hand` a symlink to the installed `hand`; an `Info.plist` without the `HandManaged` key marks a bundle that is not Hand's, and one that is not Hand's is not written into, changed or removed; `internal/launcher/bundle.go` builds on every system so its tests run on Linux too, and `TestRealWindowFromBundle` runs `hand update` from a fake release and opens the window from the bundle on the macOS runner). A change to the asset name, the stamp, the update step or the doctor row keeps those two in step and updates `docs/update.md`, `docs/platforms.md` and `docs/install.md`.
- `hand uninstall` (`internal/uninstall`) removes only what `hand update` and the install scripts placed, by fixed names beside `hand` and through `internal/launcher` (`Owned` lists, `Remove` deletes, both only for an entry marked Hand's, and `Mine` says whether the entry points at this install's window; an entry of another install, or companions beside a `hand` that has another name, are kept), never follows a symlink, keeps the fleets, `~/.secondhand` and the window's drafts, refuses while a Board or watcher of this install runs, and removes `hand` last. A change to what `hand update` or the installers place (a file name, a launcher entry, the `PATH` entry) changes `internal/uninstall` in the same PR, and its tests (`go test ./internal/uninstall`) prove each rule. A wizard install is left to Settings (`unins000.exe` beside `bin`).
- `packaging/windows/hand.iss` is the Windows setup wizard. `.github/workflows/setup.yaml` builds it (`ci.yaml` calls it for `edge`, and a PR run proves it; `release.yaml` does not, until the window runs on stable) with `.github/windows/build-setup.ps1`, which checks the archives and pins and verifies the Inno Setup compiler, and `.github/windows/check-setup.ps1` installs and uninstalls it silently. Its `hand.ico` equals what `internal/launcher` writes, and the shortcut's description, folder and icon are what `launcher` treats as Hand's; tests keep both in step, so a change on one side changes the other.
- `hand-iroh` is reached only through `internal/sidecar`: located next to `hand`, then on `PATH`, version-checked, and run with an empty environment and a stdin pipe it closes to stop it. Luvus is reached only through `internal/luvus`: UHP over its Unix socket (a named pipe on Windows), plus a read of `server.pid` in the session folder, and the four commands that package builds: `luvus server start`, `luvus --version` (to pin a copy), `luvus session list --json` (the Windows pipe address) and the interactive `luvus attach` (UHP has no terminal attach). Never call `luvus worktree`, `task`, `pane send`, or `server restart --all`.
- `www/` is the site built from `www/docs.txt`; a doc that should be published is added there.
- A fleet home is any folder holding `hand.db`. `~/.secondhand` (`$SECONDHAND_HOME`) holds `index/<id>` bookmarks, each the fleet home written temp+rename, and `worktrees/<id>/`; each fleet home records its known homes in `fleet.home`. Tests set `SECONDHAND_HOME` to a temp dir and never touch the real one.
- `skills/` holds the Hand-owned files `hand init` writes. `bootstrap.md` becomes a fleet's `AGENTS.md`. The `secondhand` skill is installed in every fleet. The binary's name replaces every `` `hand `` and `` `hand` `` in them, so write commands as `` `hand …` ``.
- `internal/desktop` and `cmd/hand-desktop` are a client of the running board, never a second owner: they read `board.addr`, the fleet bookmarks in `~/.secondhand/index` and `board.token`, verify the board's proof at `/<fleet id>/proof` before sending the token as the fleet's session cookie, write nothing except the API's actions (a message with its uploaded files, a decision's answer, a report's ack, the supervisor controls and the skills `sync`, `update` and `propose`) and three local stores, the per-fleet composer draft under `$XDG_STATE_HOME/hand-desktop/drafts/<fleet id>.txt` with its attached files in `<fleet id>.files` beside it (falling back to `~/.local/state/hand-desktop/drafts/`; `%LOCALAPPDATA%\hand-desktop\drafts` on Windows) and `prefs.json` beside the drafts folder, and `remote/` beside them (`internal/desktop/remote`: `hosts.json`, a key folder per paired host and `cookies.json`; the keys and cookies are secrets, written 0700 and 0600, and `cookies.json` is refused on Linux and macOS when group or others can read it), and import neither `internal/cli` nor `internal/board` nor `internal/state`; it pairs a remote host only after the user confirms "Add 4d92…6ed6?" (the one write besides the API's actions: `POST /<fleet id>/api/v1/pair` through the host's client), shows a remote fleet's host state as a word and a shape and never offers it `hand open`, Screen, Companion, Open in browser or Refresh models; `internal/desktop/remote` reaches `hand-iroh` only through `internal/sidecar`, never keeps, logs or prints a link, a code or a cookie, and holds a fleet ID once, whichever host or folder it comes from. `Router` in `internal/desktop` sends each fleet's calls to the host that holds it: the local Board with its token and proof, or a paired host's `hand-iroh` client with that fleet's `hand_phone_<fleet id>` cookie and no proof, never one host's credential to another; it reads a remote host's Needs every 15 s, a host that fails marks only its own fleets unavailable, and `403` with `X-Hand-Error` from a paired host is `revoked`, any other plain `403`, and a plain `401`, `not_recognised`. It tells the OS about a need only through `App.OnTitle`, `OnBadge` and `OnFlash`, which `main.go` sets to `Window.SetTitle`, `Application.SetBadgeCount` and `Window.FlashFrame` (`internal/desktop` imports no root `mygo` package): each fires when what it shows changes and never from `View`; the badge is the open fleet's own count and never a sum over fleets; the flash is an edge (a fleet's open needs rise in a fail or wait tone while the window is unfocused or minimized, never on a fleet's first read or its first after the Board failed), and focus, restore, every raising fleet falling to quiet, becoming unavailable or leaving the list, and `Close` end it (`Close` also clears the badge), while a failing Board leaves it on; a minimized window stops the open fleet's poll and reads `GET /api/v1/fleets` every 15 s instead, and `TestRealWindowAttention` (Linux, Xvfb) reads the title, the urgency hint and the launcher count of a real window. `internal/desktop/kit` holds the Board's colours, lengths and type roles in Go; its test reads `internal/board/static/board.css` by path (no import) and fails when a value differs, so a change to a token in `board.css` changes `kit` in the same PR. It holds a single-instance lock; a second launch hands its arguments to the running window, and `--open LINK` takes only the `handboard://open/` grammar of `docs/companion.md`, validated before the lock and again by the window that receives it. The window may launch `hand open` (the `hand` next to `hand-desktop`, else on `PATH`, run in the fleet's folder) to reach the Board in a browser, which is still no state of its own. One named exception to API first: the New fleet form (the zero-fleet card, or the rail item beside the fleets, whose Choose... button runs the folder dialog through the `App.PickFolder` hook) runs, wherever it shows, `hand init --name NAME FOLDER` and then `hand --home FOLDER board start`, argv without a shell, after its own checks of the form, because a fleet that does not exist yet has no Board route to ask; the exception covers only steps taken before a Board can serve them (`init`, `board start`), not any other `hand` verb: `runHand` refuses every argv but those two. Its UI tests use `ui.NewTester` per screen, and one screenshot per scene goes in `docs/images/desktop/` from `DESKTOP_SHOTS=<folder> go test ./internal/desktop -run TestScenes`; the package builds on Linux, macOS and Windows, and only Linux runs the window (`docs/platforms.md`).
- Board UI work (`internal/board` templates, CSS and `app.js`) reads `PRODUCT.md`, `.impeccable/surfaces/internal-board.md` and `DESIGN.md` first. It keeps the strict CSP (no inline script or style, no `style=` attribute), the five fleet-page region names (`status`, `console`, `timeline`, `queue`, `tasks`), and `#composer` outside every region; the board tests enforce these.
