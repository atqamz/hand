# Hand (next)

Personal supervisor layer for agents. Read `docs/spec.md` before changing anything.

- Terms follow `docs/vocabulary.md`; update it when a term, state, wake kind or ref changes.
- Standard library first. The dependencies are `modernc.org/sqlite`, `golang.org/x/sys` (already one of its own) for macOS process start times, and `github.com/egoist/mygo` v0.7.4 (pinned; Dependabot ignores it) for the desktop window, which is cgo-free. `iroh/` is a separate Rust crate that builds `hand-iroh`; it adds no Go dependency, and a change there runs `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings` and `cargo test --locked` in `iroh/` (`docs/phone.md`); `internal/board/peer.go` and `iroh/src/preface.rs` write the same preface grammar, so a change to either runs the `Iroh` workflow, which also runs the one `internal/sidecar` test that needs the real `hand-iroh` (`HAND_IROH_BIN`, absolute path; it skips without it). The sidecar's version is pinned once, in `internal/sidecar`, and a test keeps it equal to `iroh/Cargo.toml`: bump both together.
- No code comments unless a hidden constraint needs one (≤3 lines).
- Every state change goes through `internal/state` in one transaction that also appends an event.
- Output is TOON via `internal/toon`; keep `hand orient` within its byte budget.
- Run `gofmt -l .`, `go vet ./...` and `go test -race ./...` before committing.
- `.github/e2e` drives a release build as a user does, in CI on all three OSes (`docs/dogfood/README.md`); a change to the rows `hand doctor` prints, what `hand update` reports or a Board route changes its assertions too.
- `.github/render` renders the Board's fixture scenes (`TestRenderScenes` in `internal/board/scenes_test.go`) in CI on all three OSes and asserts the layout (`docs/dogfood/README.md`); a Board change that adds a page, region or fixture state adds a scene there too.
- `hand-iroh` is reached only through `internal/sidecar`: located next to `hand`, then on `PATH`, version-checked, and run with an empty environment and a stdin pipe it closes to stop it. Luvus is reached only through `internal/luvus`: UHP over its Unix socket (a named pipe on Windows), plus a read of `server.pid` in the session folder, and the four commands that package builds: `luvus server start`, `luvus --version` (to pin a copy), `luvus session list --json` (the Windows pipe address) and the interactive `luvus attach` (UHP has no terminal attach). Never call `luvus worktree`, `task`, `pane send`, or `server restart --all`.
- A fleet home is any folder holding `hand.db`. `~/.secondhand` (`$SECONDHAND_HOME`) holds `fleets/<id>` links and `worktrees/<id>/`. Tests set `SECONDHAND_HOME` to a temp dir and never touch the real one.
- `skills/` holds the Hand-owned files `hand init` writes. `bootstrap.md` becomes a fleet's `AGENTS.md`. The `secondhand` skill is installed in every fleet. The binary's name replaces every `` `hand `` and `` `hand` `` in them, so write commands as `` `hand …` ``.
- `internal/desktop` and `cmd/hand-desktop` are a client of the running board, never a second owner: they read `board.addr`, the fleets' links and `board.token`, verify the board's proof at `/<fleet id>/proof` before sending the token as the fleet's session cookie, write nothing except the API's three mutations (a message, a decision's answer and a report's ack) and the per-fleet composer draft under `$XDG_STATE_HOME/hand-desktop/drafts/<fleet id>.txt` (falling back to `~/.local/state/hand-desktop/drafts/`; `%LOCALAPPDATA%\hand-desktop\drafts` on Windows), and import neither `internal/cli` nor `internal/board` nor `internal/state`. Its UI tests use `ui.NewTester` per screen, and one screenshot per scene goes in `docs/images/desktop/` from `DESKTOP_SHOTS=<folder> go test ./internal/desktop -run TestScenes`; the package builds on Linux, macOS and Windows, and only Linux runs the window (`docs/platforms.md`).
- Board UI work (`internal/board` templates, CSS and `app.js`) reads `PRODUCT.md`, `.impeccable/surfaces/internal-board.md` and `DESIGN.md` first. It keeps the strict CSP (no inline script or style, no `style=` attribute), the five fleet-page region names (`status`, `console`, `timeline`, `queue`, `tasks`), and `#composer` outside every region; the board tests enforce these.
