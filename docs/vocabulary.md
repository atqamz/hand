# Hand vocabulary

This page defines the terms of Hand as its code implements them. The design and its reasons are in [`spec.md`](spec.md). What a command accepts and prints is owned by the command itself and its tests.

## People and agents

### Operator

The one person Hand is built for. The operator owns intent and every irreversible choice: they talk to the supervisor, answer decisions, and approve what the supervisor proposes. Their standing preferences live in the operator memory file.

### Supervisor

The single agent the operator talks to in a fleet. It captures each request as a task, writes plans and briefs, starts attempts, reads reports, and asks the operator through decisions. It does not write the code itself; workers do.

Normally Hand runs it: the managed supervisor lives in the background in the fleet's Luvus session, started from the fleet home in full-auto mode, and the operator reaches it from the board. Each launch gets a ref `sN`, and a new session's launch message begins `You are supervisor sN of the Hand fleet NAME`; a resumed one gets no launch message, so `hand orient` prints `you: sN` for the running supervisor's own pane (from `$LUVUS_PANE_ID`) and `you: not the supervisor` for any other pane. It prints no `you:` line when the variable is unset. A session that sees a running supervisor and no `you: sN` line is not the supervisor. At most one supervisor is live at a time. A long-lived process records the board generation it started under, and any close or signal of a supervisor pane re-reads `board.generation`; when the two differ, or the generation it holds is no longer alive, it records `supervisor.refused` with both and changes nothing. A process started with no board records no generation, so it guards nothing until a board writes one.

Resuming continues the same harness session under a new `sN`. `hand orient` names the current `sN` and adds the first one of that session, as in `s6 claude sonnet high running (resumes s1)`. `hand supervisor show` names the current one and adds a `resumes:` line with the first. After the relaunch settles, Hand types one message into the pane: `[hand v1 resume] you are now s6 (resumes s1)`. A session whose first Hand row predates the fleet move cannot be resumed from the new home, so resume starts a fresh one, records `supervisor.fresh` and prints `fresh:` (see [Move](#move)).

A supervisor has the same six states as an attempt. It is `stopped` after `hand supervisor stop` or a model switch, and `interrupted` after a reboot or a Luvus server restart.

An agent the operator opens by hand in the fleet folder is not the managed supervisor. It waits with `hand wait` instead of receiving wakes, and it stands down while a managed supervisor runs.

### Worker

The harness process that runs one attempt. It works in the attempt's worktree, never in the fleet home, and it sends its result back with `hand report add` from inside that worktree. Hand finds the attempt from the worktree's path.

### Harness

The agent CLI that Hand launches as a supervisor or a worker. There are six: `claude` (Claude Code), `codex` (Codex), `opencode` (opencode), `agy` (Antigravity), `copilot` (GitHub Copilot CLI) and `omp` (oh-my-pi). All but `copilot` can run the supervisor or a worker; `copilot` runs workers only, and `hand supervisor start` and `switch` refuse it. Each runs in full-auto mode:

### Agent state

Luvus's reading of the agent in a pane: `idle`, `working`, `done` or `blocked`. Hand's messages go through Luvus's fenced input, which refuses them while the agent is not ready for input, for example at a permission prompt. For a worker, the watcher notes `attempt.blocked` when the first observation (a status event or the start-up catch-up) and the next observation (the next status event, else the next reconcile tick) both read `blocked`, so a block that clears first records nothing and wakes nobody; the confirming observation records only when the screen shows one of the prompt shapes Hand reads (codex's `? N question` screen, a question with a choice row at the bottom of the screen or within the next line or two, an `Allow once`/`Deny` row, a trust screen or a Claude permission or dialog screen), not a box corner, a rule line or a status-bar fragment, and it records the block with Luvus's hint when it cannot read the screen; it turns `working` after a block into `attempt.working` (no wake, and it ends the blocked label; for opencode also when `hand attempt start` noted the block at launch, which the sweep checks, while another harness's launch note stays until the turn ends, and so does a block of another harness answered while the watcher was down), and `done`, or `idle` after the worker worked or blocked, into `attempt.quiet`. It records no turn end while a turn that starts at `attempt.running`, or at the first `attempt.sent` or `attempt.keys` after a turn end, is less than 30 seconds old, because a freshly launched harness can read `idle` while it starts; for a turn it watched start, the age is measured from the `working` it read. That first `idle` becomes the baseline, and a turn that ends after that window is recorded as before. A new `attempt.limited` is still recorded in that window. Before it records either for opencode, it asks opencode whether the attempt's session or a subagent session under it is still busy. Where a session has `time.busy` (opencode 2.2.2 and later), it is busy while `time.busy` is set and later than `time.idle`; without it (2.2.0 and 2.2.1), a subagent session is busy while its `time.idle` is missing or older than its `time.updated`, and the attempt's own session only while its `time.idle` is missing, because opencode also moves `time.updated` for a title, a model or an archive. A session not updated for 60 minutes is not busy. The question is the sweep's `opencode api --standalone GET /api/session?limit=1000` call, bounded at 5 seconds, that runs beside the watcher's event loop and answers for every opencode attempt waiting on it. While a session is busy, the turn has not ended and nothing is recorded (its 60-minute clock keeps running, so `attempt.long` still comes); each sweep asks again while any attempt waits, and the turn end is recorded from the agent state Luvus then reads once the session and its subagents are idle. A watcher that reconnects keeps the turns it holds. A watcher that starts finds an opencode worker already idle, asks once, and holds it with its clock rebuilt if a subagent runs. Otherwise it records nothing, unless opencode says the session went idle after the attempt's turn began, a turn that ended during the downtime: that turn end is recorded, as `attempt.idle` (which wakes nobody) after a `done` or `stuck` report, and as `attempt.quiet` after `attempt.running` or a `progress` report. One failed, slow or unreadable call keeps the hold for one more sweep; a second in a row records the turn as before. Luvus reads a wide opencode pane as `idle` while a background subagent runs after the turn that started it. When the attempt's newest event is already `attempt.quiet` or `attempt.idle`, or is a `done` or `stuck` report, the supervisor already knows, so the watcher records that turn as `attempt.idle` instead, which stays in the timeline, `hand orient` and the board and never reaches the supervisor. A turn that ends after a `progress` report stays `attempt.quiet`: it is the likely false done. Declining a permission prompt, or Claude Code's own two-minute auto-deny, ends the worker's turn this way. The watcher records no `attempt.blocked`, `attempt.working`, `attempt.quiet`, `attempt.idle`, `attempt.limited` or `attempt.long` for an attempt that has ended, also when `hand attempt stop` and a turn end race: the check is in the transaction that would record it.

A worker that hits its harness's usage limit does not exit: it goes idle at its prompt. When a turn ends with a limit line on the screen, the watcher records `attempt.limited` with that line instead of `attempt.quiet`, unless that line, without the time Hand adds, is the one the attempt's latest `attempt.limited` recorded. That line then belongs to an earlier turn. A turn end whose screen Hand cannot read is retried when the watcher reconnects, and is not recorded as quiet. `attempt.limited` always wakes the supervisor and is never recorded as `attempt.idle`, even right after a `done` report, because the limit is new. A turn that ends after it is `attempt.quiet`. The lines are claude's `You've hit your … limit · resets …`, codex's `You've hit your usage limit … try again at …`, and agy's `Individual quota reached … Resets in DURATION`, to which Hand adds the reset time in UTC. copilot's is `Session limit reached. Increase or unset the session limit to continue.`, shown only when a session limit is set (`--max-ai-credits` or `/limits`; Hand sets none). It has no reset time, so a second hit that follows the first with no other limit line between is recorded as `attempt.quiet`. A spent Copilot plan allowance or rate limit has no line yet: its text has not been captured. opencode and omp have none yet. Claude Code continues by itself at the reset; copilot waits until the session limit is raised or unset.

A turn that stays `working` for 60 minutes without a break records one `attempt.long`, with the detail `working for 60m`. The watcher checks on its reconcile tick, reads no screen, and records it once per turn: the next `working` to `idle` or `done` change or a `blocked` that holds to the next observation ends the turn, and a later turn can record it again. A restarted watcher rebuilds the turn's start from the attempt's events: the `attempt.running`, or the first `attempt.sent` or `attempt.keys` after the last `attempt.blocked`, `attempt.quiet`, `attempt.idle` or `attempt.limited`. It neither restarts the 60 minutes nor records a second `attempt.long` for that turn. A turn that began with no such event, because the worker resumed working on its own, counts from the restart. `attempt.long` always wakes the supervisor and is never recorded as `attempt.idle`.

## Fleets and files

### Hand

The CLI, one Go binary. It owns state, worktrees, the watcher and the board. It calls itself by its binary's name, so a build installed as `hand-next` writes `hand-next` into the fleet's `AGENTS.md`, its skill, its help lines and its errors.

### Channel

Where a `hand` binary comes from. `hand version` prints it next to the version and the commit:
- `source`: a local `go build`;
- `edge`: the rolling build of `main` that passed CI, published as the `edge` pre-release;
- `stable`: the binaries attached to a `vX.Y.Z` release.

`install.sh` installs stable by default, and edge with `HAND_INSTALL_VERSION=edge`. On Windows, `install.ps1` does the same, also with `-Edge` or `-Version`, from `hand-windows-amd64.zip` and its `.sha256`. `hand update` stays on the channel of the running binary, and `hand update --channel edge|stable` moves to the other one.

### Update

What `hand update` does, in order:
1. downloads and checks the newest build of the channel;
2. fetches the [hand-iroh](#hand-iroh) of that release, when the new `hand` names one and the release carries it, and checks it, before anything changes;
3. pins the Luvus version that build was tested with, when it is newer than the pin;
4. backs up each fleet's `hand.db` and the old binary to `$SECONDHAND_HOME/backups/`, keeping two of each;
5. replaces the sidecar, then the binary;
6. for each fleet:
   - stops its watcher by `watch.pid`;
   - switches its Luvus server to the pin when the fleet is stale, quiet and settled (see Luvus switch below), otherwise reports `pending: <reason>`;
   - starts that watcher again the way `hand supervisor start` does, when it stopped one;
7. stops the board by `board.pid` and starts it again the way `hand open` does, when it stopped one;
8. runs `hand init` in each fleet.

`hand update --check` walks steps 6 and 7 on the same path without changing anything: it fills the same `units` rows, each marked `would run`, and stops no process, no supervisor and no Luvus server and runs no `hand init`.

#### Luvus switch

On every OS a fleet's server is stale when its UHP `ping` version differs from the pin's. A server that does not answer is `not running` and a server that answers without a version is `unknown`; neither is switched, and `hand update --check` lists such a fleet under that name and plans no switch for it. A stale fleet is switched only when it is:
- quiet (issue #774): no live attempt, an idle supervisor, no queued input, and no live pane besides the supervisor's and the shell Luvus opens when it starts;
- settled: no event in the fleet newer than 15 minutes, and, for `hand update --auto`, no `luvus.failed` event for this pin version;
- not the fleet this update runs inside: a `hand update` whose environment has `LUVUS_SESSION` equal to the fleet's session stays `pending` for that fleet. The board's timer scrubs that variable, so it may switch the fleet later.

The steps, where any failed check leaves the fleet `pending: <reason>` and changes nothing more than the watcher's stop and start:
1. check quiet and settled;
2. stop the fleet's watcher by `watch.pid` and journal it;
3. read the supervisor pane's screen `content_revision`, wait 30 seconds, read it again, and check quiet again: typing or output keeps the fleet pending;
4. `hand supervisor stop` (journaled), then check quiet again; a queued input or a new pane resumes the supervisor and keeps the fleet pending;
5. stop the server: `server.stop`, then wait up to 10 seconds for the process in `server.pid` (in the session folder that `luvus session list --json` reports) to exit, and end it itself (on Windows its whole process tree) only when the stop was acknowledged or `ping` no longer answers; a recycled process ID, whose start marker differs from the one in `server.pid`, is never signalled, and a server that answers `ping` but refuses `server.stop` is never forced;
6. start the server from the pin (`luvus.Ensure`) and require that `ping` reports the pin's version;
7. resume the supervisor (a new `sN` on the same session), start the watcher, and append the event `luvus.switched` with the detail `OLD -> NEW`.

A failure at step 4 to 6 (the supervisor's stop, the server's stop or start, a wrong version) appends `luvus.failed` with the detail `PIN: reason` (a server that comes back with another version is one), resumes the supervisor and starts the watcher again as the journal's repair path does, and the update exits non-zero. The board's timer, which passes `--auto`, never tries the same pin again; a manual `hand update` does. Both events show in `hand orient`'s recent events, as one line in the board's chat (`Luvus 0.14.3 → 0.15.0 (switched while quiet)`), in the `fleets` row (`switched`, `pending: <reason>`, `failed: <reason>`) and in `update.log`.

Accepted losses: a `hand attach` viewer is disconnected, and text typed but not sent in the supervisor's pane is lost when the screen stayed still for 30 seconds. No worker loses work, since a switch needs no live attempt and no pane Hand did not start.

While `update.lock` is held, the board starts no watcher, so it cannot start one in the middle of a switch.

Stopping is the same on every OS: read the pid file (`PID START-MARKER BINARY`), skip it when the process no longer matches its start marker, skip it (reported as `skipped: runs BINARY`, and the fleet's Luvus switch stays pending) when it records another binary than the one being updated, then send SIGTERM and wait up to 10 seconds (Windows: `TerminateProcess`); a process that is still alive fails the step and is not started again. A pid file from a build that recorded no binary counts as the updated one. The process exits cleanly, so a systemd unit with `Restart=on-failure` does not bring it back. An installed `secondhand-board` unit is started again by the board's start; an installed watch unit stays inactive while the transient `secondhand-watch-<fleet id>` unit runs the watcher, and `hand update` disables and removes it when its `HAND_HOME` is relative or gone, no fleet is registered there, or a transient unit already runs that fleet's watcher (`--check` only plans that removal). It counts a loaded transient unit, which `systemd-run --collect` unloads when the watcher exits. `watch.lock` and the board's listen address keep a second watcher or board from running: the second exits (status 3 for the watcher, which systemd does not retry).

Before its first change it writes `$SECONDHAND_HOME/update.json`, a journal of the steps still to run, and removes it at the end. If an update dies part way, the next `hand update` finishes those steps first: it starts the watchers, resumes a supervisor it stopped (a supervisor whose resume failed after a Luvus switch stays in the journal until a resume succeeds), starts the board and runs `hand init`. That report reads `status: repaired`.

`hand update --keep-luvus` runs the same steps but never switches a Luvus server: every fleet whose server differs from the pin stays `pending: --keep-luvus`, and when the binary is already current and no newer Luvus needs pinning it returns `up to date` before it stops anything. Without `--keep-luvus`, a current binary and no newer Luvus still return `up to date` when no fleet is stale; otherwise `hand update` visits only the stale fleets: it stops no board, runs no `hand init` and leaves every other fleet's watcher alone, and its `fleets` rows show `skipped: current` under `init`. `hand update` holds a lock on `$SECONDHAND_HOME/update.lock` for the whole run (not `--check`): a second run exits at once with exit code 3. The journal is written to a temporary file, synced and renamed, and its folder is synced on Linux and macOS.

#### Update timer

`hand board --update-every DURATION` (0, the default, is off; 10 minutes at least) makes the board loop that keeps the watchers alive also start `hand update --channel CHANNEL --auto` as a detached child every DURATION, with its output in `$SECONDHAND_HOME/update.log` and `LUVUS_*` variables other than `LUVUS_HOME` scrubbed from its environment. It starts none while the previous child lives or `update.lock` is held, and none from a build whose channel is `source` (the board says why once). The board records DURATION in `board.update-every`, so the board an update restarts keeps it; a board started without the flag removes the file. With the timer off nothing switches a Luvus server by itself.

A backup restores with the units stopped: remove the stale `hand.db-wal` and `hand.db-shm`, then copy a backup over `hand.db`: the newest `hand.db.<stamp>` from `hand update`, or a daily `hand-YYYYMMDD.db` from the watcher, both under `$SECONDHAND_HOME/backups/<fleet id>/`.

### Secondhand

The family and storage name around Hand: the shared folder `~/.secondhand`, the `secondhand` skill, and the `secondhand-*` Luvus sessions and systemd units.

### Fleet

One supervisor's world: a fleet home with its projects, tasks, attempts, Luvus session and watcher. Several fleets can run side by side, and one board serves them all. `hand fleet list` shows the registered fleets and whether each home is `ok`, `missing`, `moved` or unreadable.

### Fleet ID and fleet name

The first `hand init` in a folder gives the fleet an ID that never changes: `f` followed by 12 hex digits. The ID names the fleet's link in the shared folder, its worktree folder, its Luvus session, its branches and its board path. The name is what people see. It defaults to the folder's name, and `hand init --name NEW` changes it. A move follows the folder while the name still equals the old folder's base name (on Windows, ignoring case); a custom name stays.

### Fleet home

Any folder that holds `hand.db`, which `hand init` creates. Commands find the fleet home in this order:

1. `--home DIR`, given before the command;
2. the working directory or the nearest folder above it that holds `hand.db`;
3. `$HAND_HOME`.

A `HAND_HOME` that differs from the fleet home found from the working directory is refused while you are inside a fleet. A fleet home cannot sit inside another fleet or inside the shared folder. To move a fleet, use [Move](#move); a plain `mv` leaves every recorded home path behind. A copy of a fleet home is refused while the fleet still sits at its registered home: delete the original or move it off that path, which can keep it on disk as an archive, and `hand init` in the copy then adopts it.

A fleet home holds:

- `hand.db`: the SQLite state;
- `AGENTS.md` and `CLAUDE.md`, which Hand owns and rewrites on every `hand init`;
- the `secondhand` and `secondhand-cleanup` skills under `.claude/`, `.agents/`, `.grok/` and `.pi/`;
- `memory/`: the operator memory;
- `routing.json`: the routing profiles;
- `inbox/`: the files attached on the board, and its trash (see Inbox folder and trash);
- `reports/` and `shots/`: the documents and screenshots workers leave for the operator (see Retention);
- `scratch/`: each attempt's scratch folder, `scratch/tN-aM` (see Scratch);
- `board.token`, made the first time the board serves the fleet;
- run-time files such as `luvus/`, `locks/`, `watch.lock` and `watch.log`.

### Move

Moving a fleet is `hand fleet move --yes PATH`: one transaction rewrites every text column's old home to the new home in its plain, `file://`, `\/` and JSON `\u002f` spellings (and on Windows its slash and ASCII case variants), records the new home in the `fleet` row, renames the fleet to the new folder's name when its name still equals the old folder's name (`fleet.renamed`, in the same transaction), verifies that no recognised spelling remains as a path in the database and refuses naming each cell it cannot reach, checks foreign keys and integrity, and writes a `fleet.moving` marker; then the folder moves, the link in `~/.secondhand/fleets` follows and a `fleet.moved` event records the move. The fleet ID, refs, branch names and worktree paths do not change; `fleet.moved` rows are history and are never rewritten by a later move. `~/<old folder>` becomes `~/<new folder>` only when both are direct children of `$HOME`; otherwise it becomes the absolute destination, and a `~/<old folder>` that is not the old home is left for you to edit, which the dry run lists and the move refuses. A path followed by `.`, `+`, a space or a non-ASCII byte is a longer name (`fleet-hand.bak`, `fleet-hand backup`), never the fleet, except that a `.` at the end of the cell or before whitespace ends the path; `/` and `\` separate it from what follows. `--dry-run` lists each cell with its absolute and `~` occurrence counts and the verification's hits; it writes nothing to `hand.db`, though it can create or change `hand.db-shm` and `hand.db-wal`. `--from OLD` rewrites a recorded home other than the folder the command runs in, and `--rewrite-only --yes` does that rewrite and verification without moving the folder, which is how a copy on another filesystem is adopted; a copy is adopted with `hand init` after the original is deleted or moved, and a folder whose database records another home, which `--from` alone cannot move: rewrite first with `--rewrite-only --yes --from OLD`. If the process stops after the rewrite and before the rename, `hand orient` reports the interrupted move and a rerun of `hand fleet move --yes PATH` finishes it without touching the `fleet.moved` history. After the rename, a `gitdir:` prefix in a worktree gitfile under `~/.secondhand/worktrees/<fleet id>/` that names the old home is rewritten to the new home, leaving the rest of the file alone; the move reports the rewritten, already correct and broken worktree counts, and refuses when one is left broken (a missing `.git` file or a missing target). A move refuses a live supervisor, attempt, watcher or board, pending supervisor input, an armed timer, a destination that exists and is not empty, the same or a nested path, another filesystem and a fleet missing from the registry; a folder whose database records another home is refused even with `--from`, so rewrite it first with `--rewrite-only --yes --from OLD`. The watcher and board checks trust their pid files, so a stale file or another `$SECONDHAND_HOME` is not seen. A supervisor's harness session is not in `hand.db`, so it cannot move with the fleet: for a session whose first Hand row predates the move, `hand supervisor resume` starts a fresh session instead of handing the harness a session that names the old folder, records `supervisor.fresh` with the move, and does not carry the earlier conversation over.

### Import

`hand fleet import SRC INTO DST`: the archive copy of one registered fleet into another. It adds the source projects and tasks (the tasks at `t + offset`, with only `tN` references in their title and goal shifted), copies its content folders, and exports its report bodies under `reports/archive-<source id>/`; it imports no attempt, report, decision, timer, event or supervisor input row. A project with the same repository is reused, and its lesson file follows the destination project name; a project with the same name and another repository is refused, and a file whose destination path already holds different content is left alone and reported. The source home keeps its files and gains an `imported-into` marker; the destination gains one `fleet.imported` event whose hash covers the inserted project and task rows only and is bound to the destination's task offset. A lock on both homes and a marker/event check inside the transaction make a concurrent import, into one destination or two, exit with a conflict instead of duplicating rows. `--dry-run` prints the manifest and writes no row, file or marker; SQLite may create `hand.db-shm`/`-wal` beside an opened database, and a dry run cannot detect a destination that refuses writes.

### Inbox folder and trash

`inbox/` in the fleet home holds the files the operator attaches on the board, named `YYYYMMDD-HHMMSS-N.ext` or `YYYYMMDD-HHMMSS-N-<name>`, with or without an extension (see Supervisor input). Hand deletes nothing there except through a prune:

- `hand inbox size` counts those files, sums their size and gives the ages of the oldest and the newest, by modification time, and the same count and size for the trash.
- `hand inbox prune --older-than Nd` (at least `1d`) moves each such file older than N days from `inbox/` into the trash, `inbox/.trash/` (mode 0700), by a rename on the same disk, and stamps it with the time of the move. It then deletes each such file in the trash older than 7 days by that stamp. `--dry-run` lists both and changes nothing.
- A prune touches only regular files with those names, directly inside `inbox/` or, for the expiry, `inbox/.trash/`. It never touches a symlink, a folder, an `.upload-*` file the board is still writing, or a file with another name, and it refuses an `inbox/` or `inbox/.trash` that is a symlink rather than a real folder. A file it cannot move or delete is reported, and the others still go. A prune that is not a dry run holds the fleet's `locks/inbox.lock`, so a second one at the same time exits 3.
- A prune that moves files records the event `inbox.pruned` with their count and size: `3 files, 12 MiB`. Deleting expired trash records no event, since each file's move was recorded.
- `"inbox": {"keep": "30d"}` in `routing.json` makes the watcher run that prune once a UTC day (see Watcher). `"off"`, the default, prunes nothing.

### Retention

Hand removes what it can prove safe, and only warns about the rest. The knobs are the `retention` object in `routing.json`, `{"worktrees": "7d", "warn_size": "20GB", "warn_days": "30d"}`; each value takes `"off"`, a missing one keeps its default, and `"retention": "off"` turns all three off. `worktrees` and `warn_days` are days from `1d` to `9999d`; `warn_size` is a size in `MB`, `GB` or `TB` (powers of 1024).

- **Worktrees.** Once a day (UTC) the watcher looks at every attempt that is not live, not cleaned and ended at least `worktrees` ago, and removes its worktree the way `hand attempt clean aN` does, only when all hold: no terminal is open in it, no process of your user has its working folder inside it, a process that started the watcher included (checked on Linux only; the reaper never signals a process, unlike `hand attempt clean`), its working tree is clean (untracked files count), every commit of `HEAD` is on a remote-tracking branch (pushed, or merged and pushed), and no ignored file looks like config or secrets (`.env*`, `*.local`, `*.pem`, `*.key`, `*credential*`, `*secret*`, `.npmrc`, `.netrc`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*`; the reason names them). Other ignored files, such as build caches, are removed with the worktree. The branch is kept. A removal records `attempt.cleaned` with the detail `aN: removed by retention after 7d`, plus `; N ignored file(s), SIZE removed` when ignored files went. Otherwise the worktree stays and Hand stores the reason in the attempt's `kept` column, records `attempt.kept` once per reason, and the Board shows a Needs item `Worktree kept: REASON` until the attempt is cleaned. The check runs git only for attempts past the window, once a day and once per watcher start, never on a watcher tick; a repository with no remote reads every commit as unpushed, so its worktrees are always kept and the Needs item counts the whole history; a repository where the branch was squash-merged and its remote branch deleted reads as unpushed after a fetch with prune, so clean it by hand (`--discard`) after checking the PR. A git failure, such as a changed project setting, is a reason too. `retention.worktrees` `off` removes nothing.
- **`reports/` and `shots/`.** Hand never deletes in them by itself. `hand orient` prints `artifacts: "reports/ and shots/ hold 31.2 GB, over the 20 GB limit; 5120 files are older than 30d (6.1 GB)"` once they hold more than `warn_size` or any file is older than `warn_days` by modification time, nothing below both limits, with a help line that names the `secondhand-cleanup` skill. The Board shows the same line as a Needs item (checked at most every 5 minutes). `orient` reads every file's size and age, which took about 0.45 s for 120 thousand files on one machine.
- **`hand gc --older-than Nd`** lists the files of those two folders not modified for N days, grouped by their first folder under `reports/` or `shots/`, with count, bytes and the oldest date, and the total; it deletes nothing. With `--yes` it deletes exactly those files, or only those under the scopes named after the flags, then removes the folders that became empty, records `gc.removed` with their count and size, and prints the deleted groups with their file count, bytes and oldest date under `deleted` (the dry run's `candidates`), and reports each file it could not delete in `failed` (exit 1). It scans again at `--yes`, so files that crossed the age since the dry run are deleted too: compare the dry run's totals just before it. It never follows a symlink, and lists only regular files. A second `hand gc --yes` at the same time exits 3.
- **Never touched:** `memory/`, `briefs/`, `inbox/` (see Inbox folder and trash) and anything unpushed.
- Workers are told not to store large machine files (`.obb`, `.pack`, `.apk`, `.aab`, bundles) under `reports/`, and to record the path and hash in the report instead. Such a file, and any path or file a worker wants to keep, must live outside its worktree: removing the worktree deletes ignored files too (see Worktrees below).

Backward compatibility is not kept for this: the `attempt.kept` column is schema 17, and a `hand` older than this refuses a database migrated to it and a `routing.json` that holds `retention`; going back needs a restored backup (see [Restore a backup](update.md#restore-a-backup)).

### Shared folder

`~/.secondhand`, or `$SECONDHAND_HOME`. It is not a fleet. `fleets/<fleet id>` is a file that holds the path of that fleet's home, `worktrees/<fleet id>/` holds every worker worktree outside every fleet, `luvus/` holds the **Luvus pin**, `board.addr` records where the running board listens, `board.generation` holds the running board's `PID MARKER` for the supervisor work it owns, `board.peer` holds the [peer preface](#peer-preface) secret, `board.iroh` holds the board's [`--iroh`](#phone-access-over-iroh) setting and the sidecar's last state, `iroh/` holds the sidecar's endpoint key, `board.log` holds the output of a board `hand open` started detached, `board.start.lock` makes two simultaneous `hand open` calls start one board, and `board.pid` holds the running board's `PID MARKER BINARY`. `update.lock` is the lock a `hand update` holds, `update.log` the last automatic update's output, and `board.update-every` the board's `--update-every` for the board `hand update` restarts. A fleet home also holds `watch.pid` for its running watcher. `hand update`, `hand board stop` and `hand watch stop` stop the processes these files name, only while the recorded start time and binary still match.

### Scratch

The folder Hand gives every attempt at `<fleet home>/scratch/tN-aM`, mode `0700`, created when the attempt's pane starts. The hidden `hand attempt _exec` wrapper makes it and exports it to the worker as `TMPDIR`, `TMP`, `TEMP`, `GOTMPDIR` and `CLAUDE_CODE_TMPDIR`; it sets no `HOME`, `XDG_CACHE_HOME` or `CARGO_TARGET_DIR`. It accepts only a `--dir` that resolves to exactly `<fleet home>/scratch/tN-aM` for a fleet home that holds a `hand.db`, is registered in the shared folder the launcher passes as `--root`, and has an attempt worktree at `<shared folder>/worktrees/<fleet id>/tN-aM`; it reads no database, resolves symlinks, and refuses anything else with the expected shape before it creates a folder or changes a mode, so a mistyped path cannot make another folder private. The folder is for temporary files, build output, downloads and logs, so a worker's default writes do not land in the operator's home folder. It lives inside the fleet home and moves with it; worktrees and the peer secret stay outside until the layout change. A Unix socket path holds at most 104 bytes on macOS and 108 on Linux, the socket's own file name included; when the scratch path leaves less than 8 bytes of that, `_exec` prints a warning in the pane, because a harness socket inside it may fail with `AF_UNIX path too long`. It is deliberately outside `reports/` and `shots/`, so the artifact counts `hand orient`, the Board and `hand gc` use never include it, and `hand update` and the watcher back up `hand.db`, not the scratch folder. It is not a sandbox: a worker that ignores the variables can still write anywhere its account can.

`hand attempt clean aN` removes it, unless `--keep-scratch` is given, and the watcher removes it with the worktree after `retention.worktrees` days. `hand attempt start --continue aN` gets a fresh scratch folder, because `aN` had to be cleaned first. `hand attempt gc` lists what is left, with its size, once the worktree is gone.

### Operator memory

Plain files under `memory/` that Hand never rewrites. `hand init` creates `memory/operator.md` once; it holds the operator's standing constraints, and `hand orient` prints up to 4000 bytes of it. `memory/projects/NAME.md`, when it exists, holds one project's lessons, and the supervisor reads it before writing a brief.

### Skill

The instructions `hand init` installs for the supervisor. The `secondhand` skill describes the supervision loop. The `secondhand-cleanup` skill guides freeing space in `reports/` and `shots/` with `hand gc` and the operator's approval (see Retention).

## Work

### Project

A short name (lowercase letters, digits and hyphens) for a git repository at an absolute path on this machine: `hand project add api /home/you/src/api`. Hand does not clone or copy the repository. It adds worker worktrees and branches to that repository with `git worktree add`. Every task belongs to one project.

A project's **grants** are the command prefixes the operator approved for always on an `ask` attempt's permission screen (see [Approval](#approval)). `hand project grants NAME` lists them as `id`, `harness`, `pattern` and `created_at`, and `--remove ID` drops one. A grant has no ref.

### Project git settings

Some settings in a project's git configuration name programs that git runs, such as `core.sshCommand`, a filter's `smudge`, a `credential.helper`, a config-defined hook (`hook.NAME.command`) or an `include.path`. The list in `internal/gitcfg` has every key that `git help config` (git 2.56.0) documents as naming a program, except those git ignores in a repository's own configuration, plus the contents of `.git/info/attributes`. `hand project add` records a digest of their values for the project in the `project.settings` column of `hand.db` (schema 13); it refuses a repository whose configuration git cannot read, and a folder that is no repository records nothing until Hand first runs git there. A project registered before schema 13 records them the first time Hand runs git in it, and `hand orient` shows the event `project.adopted`; a project that had already changed by then is accepted as it is.

Before every git command it runs for a project, Hand reads the same settings the way git does and compares them with the record. It reads the repository's own configuration with the files it includes, a worktree's own `config.worktree` and `.git/info/attributes`, and runs none of the programs. It does not look at the global or system configuration, a submodule's configuration or the environment. When a value differs, Hand runs nothing, exits 2 and names the changed settings, never their values. A setting kept only in an attempt worktree's own `config.worktree` is named with `(worktree)`, and `hand project trust` does not accept it: remove it from that worktree, or delete the worktree's folder and run the command again. Reading the settings and running the command are two steps, so a change made between them is caught by the next command. An alias is not listed, because git never resolves an alias over the built-in commands Hand runs, and neither are `remote.NAME.url` and `url.BASE.insteadOf`, whose `ext::` form needs `protocol.allow` or `protocol.ext.allow`, which are listed. The commands that run git in an attempt's worktree (`hand attempt clean`) also check that worktree.

`hand project trust NAME` is the way to accept the current values. It asks nothing, prints each setting and its value (control characters written as escapes), records them and the event `project.trusted`, and prints `status: unchanged` when nothing differs. `hand doctor` has a `project NAME` row. `hand init` skips the worktree repair of a project that is refused and says so. `hand report add` finds its worktree with `git rev-parse --show-toplevel`, which runs no configured program, and is not checked.

### Task

`tN`. The durable record of one operator request, with a project, a one-line title of 1–200 characters, and a goal that says what done looks like. The supervisor creates it with `hand task add` before any other work, so nothing lives only in chat.

| State | Meaning | Reached with |
|---|---|---|
| `inbox` | captured, not started | `hand task add` |
| `active` | work has begun; only now can attempts start | `hand task start` |
| `done` | finished; refused while an attempt is live or a report is unread | `hand task done` |
| `abandoned` | dropped; refused while an attempt is live | `hand task abandon` |

An `inbox` task can become `active` or `abandoned`, and an `active` task can become `done` or `abandoned`. `done` and `abandoned` are final, and reaching either withdraws the task's open decisions.

### Plan and plan revision

The supervisor's written plan for a task. `hand plan set --body-file PLAN.md tN` adds a new revision, numbered `p1`, `p2` and so on within that task. The newest revision is the current plan, and older ones are kept. Only an `inbox` or `active` task takes a new revision. `hand plan show tN` prints the current plan.

### Brief

The text the supervisor gives a worker with `hand attempt start --prompt-file BRIEF.md`: the goal, the constraints, the exact acceptance check, and what to commit. Hand appends the instructions for reporting back. Luvus takes at most 16 KiB per argument, so the brief and that footer must fit in 16 KiB; for a longer brief, point the worker at a file ([Long prompts](supervisor.md#long-prompts)). On Windows the footer asks the worker to write the report to a file outside the worktree and run `hand report add --status done --file PATH`, which works in PowerShell and Git Bash, instead of piping a here-document. The footer also asks the worker to wait for CI and reviews inside one blocking foreground command, never to end its turn to wait, and to report only when done or stuck.

### Attempt

`aN`. One worker's run on one task. `hand attempt start` needs an `active` task with no live attempt. Hand then:

1. makes a worktree at `worktrees/<fleet id>/tN-aM` in the shared folder, on the new branch `hand/<fleet id>/tN-aM`, from `--base` of the project's repository. Without `--base` Hand runs `git fetch origin` there (20 s at most) and starts from the branch `origin/HEAD` points to, else `origin/main`, else `origin/master`; a repository with no `origin`, or with none of those refs, starts from its current branch. When the start is a remote ref, unpushed local commits are not in the worktree unless `--base HEAD` is given. If the fetch fails, the worktree starts from the last fetched ref, or from the current branch when there is none, and `hand attempt start` prints a `warning:` line saying which and why. With `--continue aM` there is no new branch: the worktree checks out `aM`'s existing branch, and the new attempt records that it continues `aM`, which `hand attempt show` and the board's task page name. `aM` must belong to the same task and be ended and cleaned, and `--base` does not apply (the `worktrees/` folders are created with mode `0700`, and Hand's own git calls run no repository hooks and no `core.fsmonitor` command, so a hook a worker plants never runs inside Hand; the other settings that name a program, such as `diff.external`, a filter's `smudge`, `core.sshCommand` and config-defined hooks, are not switched off but [checked](#project-git-settings), and the real boundary is still the Safe use guidance in `docs/safe-use.md`);
2. starts the harness there in a Luvus terminal, with the brief as its prompt, through a hidden `hand attempt _exec` wrapper that makes the attempt's scratch folder and points its temporary-directory variables at it (see Scratch).

A task keeps all its attempts. At most one is live, that is `launching` or `running`.

| State | Meaning |
|---|---|
| `launching` | recorded; the worktree and terminal are being made |
| `running` | the worker's terminal is live in a pane |
| `exited` | the terminal or its process ended by itself |
| `interrupted` | the Luvus server restarted, or the terminal's root process changed |
| `stopped` | `hand attempt stop` ended it |
| `failed` | the launch failed, or did not finish within two minutes |

`launching` becomes `running` or `failed`, and `running` becomes `exited`, `interrupted` or `stopped`. The watcher and every `hand attempt`, `hand supervisor` and `hand attach` command first check the live attempts against Luvus.

When the watcher ends an attempt, it keeps the last screen it read from that attempt's pane, if it read one: about 2 KB from the end, with escape sequences and control characters removed. `hand attempt show aN` prints it as `last_screen`. The screen is stored only in the attempt row. It never appears in an event, a wake, `hand orient` or the board, because a worker can print anything. An attempt the watcher did not end, or whose pane it never read, has no `last_screen`. The screen is read when a turn ends, so it is that turn's last screen and not the pane's final state.

The board's attempt page, `/attempt/aN`, shows what Hand recorded about the attempt: the harness, model and effort, status and reason, times, branch and worktree, the brief and the launch line (both stored as the attempt's launch command, whose last word is the brief), its reports, and every event that names it, and for a `copilot` worker its [transcript](#transcript). It never shows `last_screen`.

`hand attempt clean aN` removes an ended attempt's worktree and keeps its branch. It also removes the attempt's own scratch folder, unless `--keep-scratch` is given, and the Claude Code directory described below. It refuses uncommitted changes, and commits on no branch, tag or remote, unless `--discard` is given. The watcher does the same by itself for a finished attempt after `retention.worktrees` days, under stricter conditions (see Retention).

Claude Code keeps a scratch directory per working folder, `<tmp>/claude-<uid>/<worktree path with every non-alphanumeric character replaced by "-">/`, where `<tmp>` is, on Linux, `CLAUDE_CODE_TMPDIR`, else `TMPDIR`, else `/tmp`. The `_exec` wrapper gives the worker `CLAUDE_CODE_TMPDIR=<fleet home>/scratch/tN-aM`, so a new worker's directory is inside the attempt's scratch folder and goes with it; `hand attempt clean` and `hand attempt gc` look for the older ones outside it from the environment of the `hand` command. On macOS Claude Code's root is not measured, so Hand looks under `CLAUDE_CODE_TMPDIR` else `/tmp`, and under `TMPDIR` too. It looks only in a `claude-<uid>` folder that is a real directory owned by the running user. On a RAM-backed `/tmp` a worker that writes captures or logs there fills memory, and Claude Code never removes it. After removing the worktree of a `claude` attempt, `hand attempt clean aN` removes the directories it finds, the attempt's scratch folder and each one outside it, printing them under `scratch_removed` with their size in bytes; a failure to remove one is a `warn` field, not an error, and it still removes every other directory it found. `--keep-scratch` leaves them and prints them under `scratch_kept`; `hand attempt gc` lists them once the worktree is gone. A worker must copy anything it needs from its scratchpad into its report or branch before the attempt is cleaned. Hand deletes only a directory directly under `<tmp>/claude-<uid>/` whose name ends in `worktrees-<fleet id>-tN-aM`, never by pattern, and never a symbolic link. The other harnesses have none. Linux and macOS only.

`hand attempt gc` lists the attempt scratch folders of worktrees that no longer exist (see Scratch) and the directories under `<tmp>/claude-<uid>/` named for a worktree of this Hand home (`worktrees/<fleet id>/tN-aM` under `~/.secondhand`) whose folder no longer exists: what earlier cleans, a crashed launch or a removed folder left. It is a dry run; `--apply` removes them, prints the ones it removed, and prints a `warn` for each it could not, and `--older-than DURATION` (for example `72h`) skips those with any file or folder modified more recently. A directory of an existing worktree, and of every attempt that is live in `hand.db`, is never listed. Neither command touches transcripts (`~/.claude/projects`, which `hand attempt transcript` and the board read) or any harness's shared database.

`hand attempt start` prints a `warn` field when 5 or more attempts are already live in the fleet, and starts anyway; see [Concurrent workers](supervisor.md#concurrent-workers).

Hand ends a worker in three places: `hand attempt stop aN`; a `hand` command or the watcher that settles an attempt whose terminal is gone, whose server restarted or whose launch failed; and `hand attempt clean aN`, just before it removes the worktree. What it reaches depends on the OS:
- Linux and macOS send SIGTERM to the worker's process group, SIGKILL after 5 seconds if the root is still alive, and then close the Luvus terminal. A command the worker started in its own session or process group (`setsid`, a daemonised server, a browser) is not in that group, and neither is anything once the root has already exited;
- Linux then also ends every process of your user whose working folder is the attempt's worktree or inside it: SIGTERM, and SIGKILL after 2 seconds. It runs also when the root is already gone. Hand reads `/proc` before SIGTERM and again before SIGKILL, so a process forked during the grace is ended too and one forked after the second read survives. It takes each process's start marker before it signals, checks it again first so that a recycled process ID is never signalled, and never signals itself or the processes that started it. It sweeps only a path of the form `worktrees/<fleet id>/tN-aM`, never the `worktrees` folder, a fleet's folder, your home folder or `/`. A shell of yours left inside the worktree ends too, so leave the folder first. A leftover that runs in another folder is not found;
- macOS has no `/proc`, so that second step does nothing there: a command outside the worker's process group survives and Hand does not report it;
- Windows ends the root and its descendants at once, found by parent process ID, with no graceful phase. The pane's root is `hand`, not the harness: `_exec` cannot replace the process there, so it spawns the harness as its child, while Linux and macOS replace it and the harness is the root. A process whose parent already exited is not reached, and Windows has no working-folder sweep.

### Report

`rN`. A worker's account of its attempt, added with `hand report add --status STATUS` from inside its worktree. Only a `running` attempt can report, and the body is 1 byte to 64 KiB.

| Status | Meaning |
|---|---|
| `progress` | a milestone; work goes on |
| `done` | the worker finished |
| `stuck` | the worker cannot continue |

A report stays unread until someone acknowledges it: the supervisor with `hand report ack rN`, or the operator with **Mark read** on the board. `hand task done` is refused while any report of the task is unread.

### Deliverable

Whatever a worker or the supervisor delivered: a PR or merge request on any forge, a document or page URL, or the path of a file or folder. The report footer asks the worker to end its report with one line `Delivered: <link or absolute path>` for each. A task the supervisor did itself has no report, so it passes each with `hand task done --deliverable PATH_OR_URL tN` (repeatable), which records one `task.delivered` event per value in the same transaction as `task.done`; the same rule applies, but a bad value is refused with an error that names it, and then nothing is recorded and the task is not finished. For a task that is already done (a backfill, or a result that comes late), or one still active, `hand task deliver tN PATH_OR_URL...` records the same events without changing the task; a value the task already has as an event is skipped. Hand reads report deliverables on demand, with no stored column: `Delivered:` lines first, and only for a report with none, the change-request URLs in its body (GitHub `/pull/N`, Gitea and Forgejo `/pulls/N`, GitLab `/-/merge_requests/N`, Bitbucket `/pull-requests/N`). A value that is neither an http(s) URL nor an absolute path (a POSIX or Windows path, judged by its text) is ignored. Every reader takes both sources together, newest first: `hand task show`, the board's task card (the newest) and task page, and `hand open tN --delivered`. The board labels each `PR`, `MR`, `link` or `file`; a `file` chip links to the [document viewer](#board) when the path is inside the fleet home and the viewer serves it, and stays text when the path is outside the fleet home, gone, or refused. `hand open tN --delivered` opens the newest, in the document viewer when its `file` chip would link there, and never a UNC path.

### Decision

`dN`. A question the supervisor asks the operator about one `inbox` or `active` task: `hand decision ask tN "QUESTION"`, or `hand decision ask --file - tN` with a longer question on stdin; a question holds at most 8000 characters. The question's first line is its headline, at most 120 characters; the lines after it are the body, shown with the board's markdown. A numbered line in the body that reads `N. Label — consequence (recommended)` is an option: the board lists the options as rows (the label in bold, the consequence under it, a Recommended badge) with an optional note and one Send, and answers with `N. Label`, then a blank line and the note. The note is optional, except that an option whose label starts with `Other` needs one. The consequence and the badge are optional, and a body without numbered lines gets a plain answer box. The `secondhand` skill makes it the only way the supervisor asks the operator anything.

| Status | Meaning |
|---|---|
| `open` | waiting for the operator |
| `answered` | the operator answered on the board or with `hand decision answer dN "ANSWER"` |
| `withdrawn` | the supervisor withdrew it with `hand decision withdraw dN`, or its task became `done` or `abandoned` |

## Runtime

### Luvus

The terminal runtime Hand runs every agent in ([RizRiyz/luvus](https://github.com/RizRiyz/luvus)). Hand speaks UHP 1.x to it over a Unix socket (on Windows a named pipe, whose address `luvus session list --json` reports and whose server must run as the same user) and uses only exact-argv terminals, agent status, fenced input and events. Hand keeps its own state and worktrees, and never uses Luvus's task ledger or worktree commands.

Each fleet has its own Luvus session, `secondhand-<fleet id>`. In a systemd user session, Hand starts that session's server in a transient scope (`systemd-run --user --scope`), so restarting the watcher or the board never stops an agent. Without a user session, or when `systemd-run` fails, Hand starts the server directly.

### Luvus pin

The copy of a Luvus binary that Hand runs, kept under `$SECONDHAND_HOME/luvus/<version>-<sha8>/luvus` (`luvus.exe` on Windows) and chosen by `$SECONDHAND_HOME/luvus/pin.json`. Every fleet under one `SECONDHAND_HOME` uses it, so a system upgrade never changes the Luvus a fleet runs.

- `hand init` pins the `luvus` on `PATH` when there is no pin, and downloads the tested version, checked against its SHA-256, when there is none on `PATH` either. `hand luvus pin` without `BIN` does the same when there is no pin. `hand luvus pin [BIN]` pins another binary, and old copies stay for rollback.
- The server start and `hand attach` check the copy's sha256 and refuse a copy that changed on disk.
- A new pin reaches a running server only when that server restarts. `hand luvus show` prints the server's version (from a UHP `ping`) and whether it is the pinned copy: `yes`, `no`, `not running` or `unknown`. Restarting it ends every live pane, so Hand does it only for a quiet, settled fleet (Luvus switch, under Update): `hand update` or the board's timer switches such a fleet, or you stop the server yourself, let the next `hand` command start the pinned copy, and resume the supervisor.

### Pane

The Luvus view of one terminal. The running supervisor and every running attempt each have a pane. Hand reads the screen and sends keys through it, and `hand attach supervisor` or `hand attach aN` opens it in your terminal.

Luvus refuses keys and messages (`agent_not_ready`) to a pane it does not know as an agent, and it names an agent from the program's file name, which never matches `codex.exe` or `claude.exe`. So Hand asks Luvus for a **process scan** of the pane (`terminal.backend.processes`) before the first key or message it sends to that pane in a run, and once more after an `agent_not_ready`, then, when that scan reports `observed`, sends the key up to 3 times, 200 ms apart, because Luvus can still refuse for a few milliseconds after it; a scan that observes nothing gets one more send. A scan that fails, or a Luvus without the method, never blocks a key that would have worked: the refusal then ends with a note that Luvus could not scan.

### Blocked screen and screen revision

A screen that waits for an answer, such as a trust or permission prompt, puts the agent in the `blocked` state. `hand attempt read aN` prints the screen as an indented multi-line block (`screen: |`, then the lines, with escape sequences and control characters other than newline and tab removed) and its revision. `hand attempt keys --revision N aN KEY...` sends keys only if the screen is still at that revision, so a stale answer is never typed. The supervisor's own screen works the same way, through `hand supervisor show` and `hand supervisor keys --revision N KEY...`, with the keys `enter`, `esc`, `up`, `down`, `1`, `2` and `3`. Claude Code's auto-deny countdown moves the revision every second, so the board also sends `--screen DIGEST`, a digest of the screen with the countdown taken out: when the revision moved but the digest still matches, the keys go out once at the new revision. The Board's Screen page sends an ordered sequence of allowed keys in one press, which its Ask card uses to move through a card without numbers. A key press on the supervisor's screen is recorded as a `supervisor.keys` event.

Hand answers the trust screens of agy, Claude Code, Codex and Copilot when they name the attempt's own worktree (the fleet home for the supervisor), and prints the result as `trust:` (`accepted`, `not asked` or `not pressed`). A Codex screen that also names a repository root is answered only when that root is the project's registered repository or its resolved path; a supervisor has no project, so it never is. Codex saves what it accepts, so `hand attempt start` and `hand supervisor start` also print `trusted:`, and an `attempt.trusted` or `supervisor.trusted` event records the screen, the folder and the repository root. Codex's `Working directory · Resume` screen is not answered, and shows as a blocked screen. A Codex screen that shows `? N question` (a question the worker asks the operator) puts `question: ` and the text above it in the `attempt.blocked` detail, so the Board's Needs item and `hand wait` show it; the wake only says the screen shows a question. Codex answers it with Shift+Left, and Luvus refused four spellings of that key as `unknown key` (0.12.0), so Hand cannot answer it: the question times out and the worker goes on with its own default. Copilot's screen (`Do you trust the files in this folder?`, with `1. Yes` selected) shows the folder in a box, wrapped at the pane width without spaces; Hand joins the lines and presses Enter only when the result is the attempt's own worktree. It never takes `2. Yes, and remember this folder`, which would write the operator's Copilot config; a trust given with `1. Yes` lasts for the session, so Hand prints no `trusted:`.

### Approval

A worker started from a profile with `"approve": "ask"` runs Claude Code without `--dangerously-skip-permissions`, so it asks before each command. The attempt records `approve: ask`: `hand attempt show aN` prints it, and the Board shows a small `ask` badge on that attempt only. An attempt of any other profile has `approve` `never`, which `show` leaves out, and launches as before.

When the worker blocks on a Claude permission screen, the Board's Needs item shows the command as the screen printed it and the buttons **Approve**, **Approve always: PREFIX** and **Deny**. They press the option numbers the screen prints (Deny is `4` when Claude also offers "switch to auto mode", `3` otherwise) through the same keys route as every worker screen, with the same revision and stale-screen refusal, so they work from a paired phone under the phone rules. For a Bash command the text shown is the one between the dialog's two dashed rules. For any other tool (`Edit file`, `Create file`, `Fetch` and so on) it is everything between the dialog's header and its question, without rules or the `Tip:` line, and the question line itself, which names the path or URL; a tool dialog with no such body gets no **Approve**. The Needs title is the tool and the first line, with `(+N lines)` when there are more. **Approve always** appears only for a Bash command whose second option reads `Yes, and don’t ask again for: PREFIX *` and whose PREFIX is `git status`. Claude's rule for a prefix matches every argument after it, so the list holds only prefixes that no flag turns into something else: on Claude Code 2.1.316 a rule `Bash(git log *)` ran `git log --output=FILE` and wrote outside the worktree without asking, and the same holds for `git diff`, `git stash`, `git branch`, `npm install`, `go test -exec`, `go build -toolexec` and the `cargo` build scripts. `git commit -F FILE` and `git add --pathspec-from-file=FILE` read any file into the commit message or the error output, where Claude's own file read of that path would have asked, so `git commit` and `git add` get none as well. `git -C` and `git -c` before the subcommand, `$(…)`, `;` and `&&` still prompted under the kept rule. Any other prefix (a runner such as `perl`, `ruby`, `go run`, `npm run`, `make` or `./run.sh`, a shell, an interpreter, `ssh`, `docker`, bare `git`, an environment assignment) gets none; the label names the prefix it stores. A screen Hand does not recognise, one whose dialog header or top rule is cut off by the 20-line read (a command of more than a handful of lines), one whose header is not `Bash command`, `Create file`, `Edit file`, `Edit notebook`, `Fetch` or `Read file`, one with a row that mimics the top rule (the real rule starts at the first column and spans the whole pane width), one where Claude prints that the proposed content cannot be shown in full or cannot be reviewed, and Claude's other dialogs (new MCP servers in the project, one or several, the CLAUDE.md import question, leaving plan mode) show as the raw screen with its keys and no **Approve**. An `ask` attempt's item joins Needs at once, without the 10-minute wait for a running supervisor.

The supervisor never answers an `ask` attempt's screen unless it is Claude's input prompt: `hand attempt keys` exits 2 naming the Board unless the screen shows the bare input box (a full-width rule, a row starting `❯`, a second rule of the same width and one more row, at the bottom). With a Claude `statusLine` configured the screen is not recognised as the input prompt, so the supervisor's `attempt keys` is refused with exit 2 and the operator answers from the Board; the Board's own route is unaffected. The one other screen it takes is the trust screen Hand's launcher already handles, and only with the keys `enter`, `down` or `up`. Every other screen is refused, whether Hand recognises it or not and whatever Luvus calls it. Three seconds after a key press, a screen that is not the input prompt is noted `attempt.blocked` with its own first row, so an unknown dialog gets a Needs item; the same note is made when Luvus reads such a screen as `idle` after the worker was `working` or `blocked`. A dialog Luvus reads as `idle` from the start of the attempt, such as a theme picker or a login prompt, gets no note and no timeout: the supervisor is still refused, and the operator finds it by reading the attempt. A recognised dialog with no answer for `approve_timeout` (`routing.json`, from `1m` to `24h`, default `10m`) is denied: the watcher presses the deny key once (`esc` when the dialog is a Claude permission dialog Hand cannot parse, a new-MCP-servers dialog, the CLAUDE.md import question or plan mode; `esc` there declines the servers, the imports or the plan, not a command), records `attempt.denied`, a wake, and nothing else. A screen of another kind waits for the operator: Hand presses nothing on it. An answer before the deadline records no denial. Starting an `ask` attempt starts the watcher when none holds `watch.lock`, so the timeout runs without a supervisor; a watcher that cannot read `routing.json` denies nothing until it can.

**Approve always** presses its key and stores a grant for the project: the harness and the command prefix, listed and removed with `hand project grants NAME` (`--remove ID`). Every later `ask` attempt of that project starts with each grant as `--allowedTools=Bash(PREFIX *)`, the form Claude prints and writes itself; other projects, and attempts that do not ask, get none. Removing a grant does not touch an attempt that is already running with it, and option 2 also makes Claude write the same rule into the worktree's `.claude/settings.local.json`. If the grant cannot be stored, the press still happened: `hand attempt keys` exits 0 and prints a `warning:` line on stderr, and the next screen asks again. Asking is friction, not a boundary: see [Safe use](safe-use.md#ask-before-each-command).

### Access

A worker started from a profile with `"access": "readonly"` is a read-only worker, for a review, research or audit task. Claude Code starts with `--permission-mode dontAsk`, so any tool or command no rule allows is denied without a prompt. `--tools=Bash,Read,Grep,Glob` leaves it only those tools: `Edit`, `Write`, `NotebookEdit`, `EnterWorktree`, `CronCreate`, the `Agent` tool and tool search are not offered to the model, so no rule can allow them. `--setting-sources=user` makes it ignore the repository's own `.claude/settings.json` and `.claude/settings.local.json`, with their allow rules and hooks, and its `.mcp.json`; a pull request cannot widen what the worker may do by adding them. `--strict-mcp-config` also drops every MCP server, the operator's own included. Two allow rules are added: `Bash(gh pr view *)` and the report command exactly as the brief's footer prints it (`Bash('/path/to/hand' report add *)`). Claude's own read-only commands, such as `git log`, `git diff`, `git show`, `git status`, `cat`, `ls` and `grep`, run without a rule, and its file reading tools work. A command that writes (`touch`, `sed -i`, `tee`, a redirect, `git commit`, `git tag`, `git push`), a compound command that holds one, and `git diff --output=FILE` are denied. The brief's footer for such a worker shows only the report command, since it cannot wait on CI. The attempt records `access: readonly`: `hand attempt show aN` prints it, and the Board shows a small `readonly` badge on that attempt only. An attempt of any other profile has `access` `open`, which `show` leaves out, and launches as before.

Measured on Claude Code 2.1.316 with a mock model: `git diff --output=FILE` is denied, but the same command under an explicit rule `Bash(git diff *)` wrote the file, so Hand passes no rule for git. It is a permission mode, not a sandbox. The operator's own user-level Claude settings (`~/.claude/settings.json`) still apply, because they hold the login and environment, so a `Bash(touch *)` allow rule there lets a read-only worker run `touch`, and a user-level hook still runs; the file tools stay absent. The repository's own settings do not apply: this was measured by committing a `.claude/settings.json` with `Bash(touch *)` and `Bash(git *)` allow rules and a `SessionStart` hook, and a `.mcp.json`, which no longer write anything. A read-only Claude worker has no folder it may write: its scratch folder arrives with the sandbox launcher. `report add --file PATH` still reads any file the account can read, as for every worker, so a read-only worker can put one into a report. Only `claude` supports it, and not on Windows: the report command and its quoting are not measured there, so `routing.json` with `access: readonly` on Windows is refused with an `invalid` error naming the profile. A `hand` older than this key refuses the whole `routing.json` that holds it (`unknown field "access"`), so no profile works there until the key is removed, and the database, once migrated to schema 16, is refused by that older `hand` as one it does not know: going back needs a restored backup, as [`hand update`](update.md#restore-a-backup) describes. Codex's `--sandbox read-only` blocks the write to `hand.db` that `hand report add` makes, so a Codex worker could not report; opencode, agy and Copilot have no mode Hand can rely on. They reject the value until the launcher enforces it. Read-only does not stop a worker from leaking what it can read.


### MCP

A Claude worker starts with `--strict-mcp-config`, so it loads no MCP server: not the ones in the operator's own Claude config, not the repository's `.mcp.json`, not a plugin's. A profile in `routing.json` may add `"mcp": "FILE"`, a path inside the fleet home (a relative path, never `..`, never absolute) to an MCP config the operator maintains, for example `"mcp": "mcp.json"`. That worker starts with `--strict-mcp-config --mcp-config=FILE` and no other source. `hand attempt show aN` prints `mcp: PATH` when the launch holds one, `hand route list` has an `mcp` column, `hand doctor` fails the profile when the file is missing, and `hand attempt start` refuses to launch without it. Hand never reads the user's own Claude config (`~/.claude.json`) and never reads the MCP file either: Claude does. Why a worker needs a profile with `mcp`: a server in the operator's config can drive a logged-in browser, so every worker, including one that follows text from an untrusted issue, would have a path to it; and each server is a process per worker.

Measured on Claude Code 2.1.316 with a mock model and a scratch `HOME` whose Claude config holds two `@playwright/mcp` 0.0.84 servers (idle, no page opened), summing `VmRSS` over the worker's process tree ten seconds after its first request: before, 3 processes and about 540 MB (the Claude process 267 to 269 MB and two servers of 135 to 138 MB each; two runs); after, 1 process and about 253 MB. With a real run (`TestClaudeMCP`), a server in the user config and one in the repository's `.mcp.json` did not start for a default worker, and only the profile's file started for a worker with `mcp`. This is a break: a worker used to inherit every server of the user's config. An operator who relies on a browser or another MCP server in workers adds `"mcp": "mcp.json"` to those profiles and puts the servers in `mcp.json` in the fleet home. A `hand` older than this key refuses a `routing.json` that holds `mcp` (`unknown field "mcp"`).

Only `claude` supports it. `hand route list` and `hand attempt start` refuse `mcp` on any other harness, on a path outside the fleet home and together with `"access": "readonly"` (a read-only worker starts without MCP servers), and `hand supervisor start` and `switch` refuse a profile that names a file: the supervisor starts as before. Codex, opencode, agy and Copilot keep loading the MCP servers of their own configuration, as before. Their installed binaries were checked for a way to start with only a named MCP file: Codex 0.166.0 (`--ignore-user-config` skips the whole `config.toml`, which is more than MCP, and was not measured), opencode 2.2.5 and agy 1.4.12 have none in `--help`, and Copilot was not installed where this was checked. Hand claims no isolation for them.

### Watcher

`hand watch`, one per fleet. It:

- follows Luvus's events and checks the live attempts at least every 30 seconds (`--every`);
- presses the deny key on an `ask` attempt's permission screen that stayed unanswered for `approve_timeout`, and records `attempt.denied` (see Approval);
- records the `attempt.blocked` (once a second observation still reads `blocked`), `attempt.quiet`, `attempt.idle`, `attempt.limited` and `attempt.long` events from Luvus's agent status (an opencode turn end only once its session and subagents are idle, see Agent state), an `attempt.working` event when a worker whose newest event is `attempt.blocked` works (it ends the blocked label in `hand orient`, and wakes nobody; for opencode also for a block that `hand attempt start` noted at launch: each sweep costs one query per running opencode attempt, and a status read only for one whose newest event is `attempt.blocked`), records another `attempt.blocked` for an `ask` attempt whose newest event is `attempt.keys` (the launcher's trust keys, or an answer) and whose screen still shows a permission, MCP-server or plan-mode dialog 3 seconds later, because Luvus stays `blocked` between the trust screen and the dialog that follows it and reports no change, and on every start catches up on a blocked screen or an ended turn it missed while it was down;
- delivers queued messages and wakes to the managed supervisor, and alerts once each time a supervisor reaches a usage limit, counting a limit as over once a screen read shows no limit line or another supervisor takes over;
- wakes the managed supervisor with `supervisor.stalled` while it idles with unwatched work (see Unwatched and stalled), and with `timer.fired` when a timer comes due (see Timer: it needs a managed supervisor);
- snapshots the fleet's `hand.db` once a day (UTC) with `integrity_check` to `$SECONDHAND_HOME/backups/<fleet id>/hand-YYYYMMDD.db`, and keeps the newest 7, retrying a failed snapshot only after the next UTC day starts or the watcher restarts; `hand update` keeps its own `hand.db.<stamp>` files in that folder, and neither removes the other's;
- removes the worktrees of finished attempts once a UTC day, in the background, as Retention describes, and records `attempt.cleaned` or `attempt.kept`; while `routing.json` is invalid it says so once and removes nothing;
- prunes the inbox folder once a UTC day when `routing.json` sets `inbox.keep`, as `hand inbox prune --older-than KEEP` does, and writes the day to `inbox/.trash/.pruned` so a restart that day does not prune again; it logs only the files that failed, which wait for the next day's run; while `routing.json` is invalid it says so once and does not prune;
- resumes an interrupted or exited supervisor when it starts, if `routing.json` turns on `supervisor.autoresume`;
- alerts when an attempt ends, blocks, hits a usage limit or goes quiet (not for `attempt.idle`, which wakes nobody), when a decision is asked while it runs, and once per stall episode, on the first stall wake at or after 60 minutes idle;
- sends each alert through the `notify` command in `routing.json` (an argv; `HAND_NOTIFY_KIND`, `HAND_NOTIFY_REF`, `HAND_NOTIFY_TEXT` and `HAND_NOTIFY_URL` in its environment), else through `notify-send` (on macOS, `osascript`; on Windows, none), unless `--notify=false`. On Linux the `notify-send` notification offers **Open**, which opens the item's address with the OS opener; Hand waits up to 10 minutes for the click, keeps at most 8 waiting at once, and sends a plain notification when `notify-send` lacks `--action` and `--wait` (checked once with `notify-send --help`), when the click command fails without printing the action, or when `board.addr` is not a board address (a loopback host with an explicit port; no login, query or fragment).

The running board keeps it alive. `hand unit board` prints the board's systemd user unit on Linux, and exits 2 on macOS and Windows.

`hand supervisor start`, `resume` and `switch` start it when its `watch.lock` is free: as the transient user unit `secondhand-watch-<fleet id>` (`Restart=on-failure`, `RestartSec=5`, `RestartPreventExitStatus=3`) in a systemd user session, otherwise detached with its output in `watch.log`. `hand orient` reports `watch: running` or `watch: missing` from the same lock, without creating it. The running board starts it the same way, at startup and every 30 seconds, for each fleet that has a live supervisor or that has `autoresume` in `routing.json` and an ended supervisor to resume (the last one that started is `interrupted` or `exited`), so a crashed or killed watcher comes back on macOS and Windows too and after a reboot once the board is up. A fleet with neither gets none, a fleet whose home is gone or whose `hand.db` will not open is skipped, and a failed start is written to the board's log once per change of error. That probe holds the lock for an instant, so a starting watcher tries it five times, 20 ms apart, before it gives up.

### Event and cursor

Every state change is one transaction that also appends an event with a sequence number, a kind such as `task.active` or `attempt.reported`, a task and a detail. A cursor is the sequence number of the last event seen. `hand orient` prints the current one.

### Wake

A message that tells the supervisor something changed, that a timer it armed came due, or that it idles with unwatched work, so it never polls and spends no tokens while idle.

- **Managed supervisor:** Hand sends its pane a message whose first line is `[hand v1 wake]`, followed by one `KIND DETAIL` line for each event since the supervisor's wake cursor. A line about a task ends with that task, e.g. `(t1 "Fix the login redirect")`. Hand sends a wake only while the supervisor is idle or done, and only after every queued operator message has gone out. While the supervisor's screen shows its harness's usage-limit line, Hand holds wakes and leaves the cursor where it is, because the harness would answer them with the limit error. It holds them too when it cannot read that screen. The hold lifts once the line leaves the screen. Operator messages still go out. Luvus types the message and then presses Enter 45 ms later. Codex swallows an Enter that comes within 120 ms of a paste when its terminal has no bracketed paste, as on Windows, so when a Codex supervisor has not left idle 1.5 seconds after the message, Hand presses Enter itself once. When Luvus refuses the message with `agent_not_ready` although Claude Code is idle or done and its screen shows an empty prompt (Luvus judges the input box from the cursor and its rails, which a Windows console can place elsewhere), Hand types the message key by key, as `hand supervisor force` does, and records the delivery as typed.
- **Supervisor opened by hand:** it runs `hand wait --after CURSOR`, which returns the wake events and the next cursor. It has no timers: `hand wake` is refused without a managed supervisor, so it waits with `hand wait --timeout`.

The wake kinds are:

| Kind | Meaning |
|---|---|
| `attempt.reported` | a worker added a report |
| `attempt.quiet` | the worker's turn ended; the detail says whether it reported since its last quiet turn, or `api error: <line>` when claude's screen has a line starting `API Error:` |
| `attempt.limited` | the worker's turn ended at its harness's usage limit; the detail is the limit line |
| `attempt.long` | the worker's turn has run 60 minutes without a break; the detail is `working for 60m` |
| `attempt.blocked` | the worker waits at a screen that needs an answer, recorded once a second observation still reads `blocked`, or Hand noted a launch problem: a trust screen it did not answer, a prompt it could not submit, a copilot that fell back to Auto or is not signed in, or, for an `ask` attempt, a screen that is not Claude's input prompt after the keys Hand or the operator sent, or when Luvus reads such a screen as idle after the worker was working or blocked |
| `attempt.denied` | an `ask` attempt's permission screen stayed unanswered for `approve_timeout`, and the watcher pressed deny; the detail names the wait and the key |
| `attempt.exited` | the attempt ended by itself; the reason reads `terminal exited (code N)` or `terminal exited (signal NAME)` when the watcher saw Luvus's `terminal.exited` event within 1 second of noticing the terminal gone, else `terminal exited`; a `hand` command that notices the exit first records the bare reason |
| `attempt.interrupted` | the attempt was cut off by a Luvus restart or a changed process |
| `attempt.failed` | the attempt's launch failed |
| `decision.answered` | the operator answered a decision |
| `supervisor.stalled` | the supervisor idles with unwatched work; the detail names the tasks and the idle time |
| `timer.fired` | a timer came due; the detail is `wN`, how late it fired when that is a minute or more, and its note |

A `progress` report never wakes the supervisor on its own; `attempt.limited` and `attempt.long` wake it unless the wake leaves them out, as described below. A `progress` report rides in the next wake with an event that does, or goes out once 50 such reports wait. `attempt.idle` is not a wake kind: it never reaches the supervisor and sends no desktop or notify-command alert.

A wake leaves out what the supervisor already handled: an `attempt.blocked`, `attempt.quiet` or `attempt.long` of an attempt that is no longer running when the wake goes out, an `attempt.limited`, or an `attempt.quiet` with `api error`, of an attempt that is stopped or cleaned (an exit or an interruption not yet cleaned keeps the limit line and its reset time in the wake), and an `attempt.exited`, `attempt.interrupted` or `attempt.failed` of an attempt already cleaned. The events stay in the timeline. `hand wait` leaves them out the same way.

Wakes reach the managed supervisor through the watcher, so `hand watch` must run for the fleet.

### Unwatched and stalled

A fleet's work is **unwatched** when at least one task is `active`, no attempt is live, no decision is open and no timer is armed that is due within 6 hours while a managed supervisor runs: no event will ever wake the supervisor for it. While a managed supervisor runs, a task with an armed `waits` timer (see Timer) is left out, and its timer does not count for the other tasks. Its **idle time** counts from the fleet's last event other than `supervisor.stalled`, `supervisor.delivered` and `model.changed`, which only record that something already recorded reached the supervisor or that the model a harness reports changed. `hand orient` lists such tasks as `unwatched[N]` (at most 15, then `unwatched_more`) with `unwatched_idle`, and prints neither otherwise.

The watcher records `supervisor.stalled`, a wake, when the work is unwatched and the supervisor is running and idle: Luvus reads it as `idle` or `done`, its screen revision has not changed for 30 seconds (the test the Luvus switch uses), no message waits for it, its screen shows no usage-limit line, and no model switch is pending. A stopped, blocked, limited or switching supervisor gets none. An episode's first stall comes when the idle time reaches `after`; each later one waits twice as long as the one before, up to `every`: by default 20 minutes, then 40, then every 60. Any other event ends the episode, so the idle time and the delays start again. A turn holds the next stall until `after` has passed since the watcher last saw the supervisor working. The detail names the tasks and the idle time: ``s3: t139 and t142 are active, no attempt is running, idle 23m. Start a worker, arm a timer with `hand wake`, or finish the task.`` The first stall wake of an episode at or after 60 minutes idle also alerts the operator, once.

`routing.json` sets the delays with `"stall": {"after": "20m", "every": "60m"}`, each from `1m` to `24h` (one left out keeps its default), and `"stall": "off"` turns the stall wake off. Without `stall` the defaults apply. A bad value makes `routing.json` invalid with an error that names it; the watcher says so once in its output and keeps the defaults.

### Timer

`wN`. A wake the supervisor arms for later with `hand wake`, for something outside Hand such as a PR review: once after a delay (`--after 30m`), once at a time (`--at <UTC time, RFC 3339>`), or repeatedly (`--every 30m`). `--while tN` ties it to a task: finishing or abandoning the task cancels it. `--note` says what to check, in one line of at most 200 characters. `--after` and `--every` take Go durations or whole days (`3d`). `--waits` (with `--while tN`, one-shot, due at most 30 days away, one armed per task) makes the timer a **wait**: tN is waiting on an outside party until it fires, and the note is the reason. Timers belong to the managed supervisor: `hand wake` is refused while no managed supervisor runs (a supervisor on the current Luvus server, started by `hand supervisor start` or `resume`), and a supervisor opened by hand waits with `hand wait --timeout` instead. `hand wake list` and `hand wake cancel` work without one. A timer is due at least 1 minute ahead and repeats at most once a minute, and a fleet holds at most 20 armed timers. It is stored in `hand.db` as `armed`, `fired` or `cancelled`, so it survives a watcher restart, a supervisor switch and a resume. `hand wake list` shows the armed ones, `hand wake cancel wN` cancels one, and `hand orient` lists them as `timers` (id, due time, note).

The watcher fires a due timer while the managed supervisor runs, on its start and on every reconcile tick, by recording `timer.fired`, a wake, whose detail is `w3: check PR 909`. A timer that came due while the watcher or the supervisor was down fires once when both are back, marked with how late it is: `w3, 2h10m late: check PR 909`. A repeating timer then moves to its next due time, or to `every` after now when that has passed, so it never fires twice for one gap. `hand wake`, a fire and a cancel record `timer.armed`, `timer.fired` and `timer.cancelled` with the timer's task. An armed timer keeps the work from being unwatched only while a managed supervisor runs and it is due within 6 hours (the watch horizon); with no managed supervisor, or one from an earlier Luvus server, no armed timer counts, the work shows as `unwatched`, and `hand orient` marks each timer `(no managed supervisor: not fired)`. A timer armed further out, such as `--at` a month away, does not stop the stall wake, and `hand orient` marks it `(beyond the horizon)` while the stall wake names the nearest one (`t1 is active, no attempt is running, idle 20m; w2 is armed but due in 31d`). A repeating timer counts while its next due time is within the horizon, and a timer that comes within it starts counting then. The watcher logs a fire as `timer.fired w3: check PR 909`, the form of the event. While a wait is armed and a managed supervisor runs, its task is not `unwatched`, and it leaves the Board's STALLED, FAILED and INTERRUPTED items and the stall wake's task list; the wait fires once like any one-shot timer, then the task is plain `active` again and all of that returns. Finishing or abandoning the task, `hand wake cancel wN` and `hand attempt start` on the task end a wait early (`timer.cancelled`). `hand orient` marks a wait's timer `(waits tN)` in place of `(beyond the horizon)`, `hand task show tN` lists it as `waits`, and the Board shows `Waits until Nov 3: reason` on the task's page and its Tasks row. Hand never asks a forge or CI anything for a timer: it only wakes the supervisor.

### Supervisor input

`iN`. A message queued for the supervisor, from the board's message box or `hand supervisor send --text TEXT`. It is at most 16 KiB of UTF-8 with no control characters other than newline and tab, and it may not start with `[hand v1`, which Hand keeps for its own messages. Inputs are delivered in order as soon as the supervisor can take them.

An input can carry files. Each one the operator pastes, drops or picks on the board, of any type and up to 10 MiB, is copied into the fleet's `inbox/` folder as `YYYYMMDD-HHMMSS-N-<safe name>`: the original base name with every run of characters outside `[A-Za-z0-9._-]` turned into `_`, leading dots and dashes stripped, and at most 80 bytes with the extension kept. An image (png, jpeg, webp or gif, by its bytes, not its name) takes the extension of its type, and any other file named like an image gets `.bin` appended. The board holds them as chips beside the message box and, on send, appends a line `[image: PATH]` for an image and `[file: PATH]` for any other file after the operator's text, one per file; older images are named `YYYYMMDD-HHMMSS-N.ext`. The supervisor reads that path with its own tools, as data. Chat shows each such line from this fleet's `inbox/` as a thumbnail for an image and a file card for anything else, and a dashed card once the file is gone. A prune may later move the file to the trash, and it matches only these names Hand gives, never another file in `inbox/` (see Inbox folder and trash).

### Model list

What Hand knows about the models each harness can use: one list per harness, a machine-wide cache in `$SECONDHAND_HOME/models/<harness>.json` (folder mode 0700, files 0600, written to a temporary file and renamed). It holds names only. Each model has a name, a label, the efforts it supports and a **source**: `built-in` for what a harness carries itself (Claude Code's aliases and ids, Codex's bundled catalog), `discovered` for what it read or fetched (the lists of opencode, agy and Copilot, Codex's own `models_cache.json`), and `custom` for a name Claude Code lists that is neither an alias nor a Claude id (a gateway name, a pin, a `modelPicker` entry). Claude Code claims every effort for such a name, which Hand cannot confirm, so `hand models` marks them `unverified`. A Codex model whose visibility is not `list` is hidden: valid, but not offered. The file also holds a format number, the harness's version, a key (the binary's size and modification time, and those of the config files whose change should invalidate the list, hashed; Hand only stats them), the time it was read, the names that were listed once and are gone, and the reason of the last refresh that failed.

Hand reads a list with one command per harness, no prompt and no tokens: Claude Code's `initialize` control request over `claude -p` with stream-json in and out (only the `models` array of the answer is decoded), `codex debug models --bundled` (else Codex's own cache file), `opencode models --standalone` (names) and `opencode api --standalone GET /api/model` (the variant ids of each model, kept as its efforts; when that call fails the names stay without variants), `agy models`, `copilot help config` (the quoted names under `model`, which it prints offline; `auto` is added, and every other model gets the flag's own effort levels, marked `unverified` because the page names no effort per model; a changed format gives no list and a note) and `omp models --json` (each `selector` with its `thinking` levels; an empty answer is a failure, not a list with no models). Each run has a timeout, an output limit, no terminal and a minimal environment, and is killed with its process group; a harness that is missing, signed out, too old or garbled gives no list and a short reason, and nothing is blocked ([what Hand runs](safe-use.md#what-hand-runs-to-list-models)). Claude Code's list reflects the environment and the folder it ran in, so it is the list for the process that refreshed it.

A list is stale after 1 hour for Claude Code, whose answer follows environment pins and settings that the key cannot see and costs about 0.4 seconds and no network, and after 6 hours for the others, or as soon as its key changes. A stale list is still used. A failed refresh keeps the previous list, records its reason and is tried again after 15 minutes. Two refreshers at once run one command, under a lock file beside the cache.

Only four things run a listing command: the watcher, for every stale or missing list of a harness a `routing.json` profile names, while it runs (it logs a new failure once); `hand models --refresh [HARNESS]`; `hand route list`, for a harness a profile names that has no cache yet; and the board's **Refresh models** action, which runs the same refresh in the background (one per harness at a time, at most one every 30 seconds, laptop sessions only). Everything else, the board's pages included, reads the cache and never runs a harness. With no cache, Claude Code shows its four aliases, Codex its own cache file, and opencode, agy, Copilot and omp no list. `hand models` prints the lists, and `hand doctor` one `models NAME` row per harness.

A model that was in a list and is not in the fresh one has **left the list**. For Codex, agy, Copilot and omp, whose lists name every model they accept, `hand route list` shows a profile naming it as `valid: no`, with `model X is no longer listed by H` in its `warn` column, while the list is fresh; for Claude Code, whose custom names no list can vouch for, and for a stale list, it stays `valid: yes` with that warning. A model that was never listed is only unverified. A list read from Codex's own cache file can be narrower than its bundled catalog, so it never marks a model as left, and a model it lists is not left.

### Model switch

A pending change of the supervisor's model or effort that keeps its harness and its conversation: `hand supervisor switch --model M --effort E`, `--profile NAME`, or the model menu on the board. Hand applies it when the current turn ends, by stopping the supervisor and resuming the same session with the new model under a new `sN`. `--cancel` drops a pending switch. For opencode the model is `provider/id` and the effort is its variant, which a switch may leave empty: a switch to another model sends no variant unless `--effort` gives one, and `--effort default` is sent but not stored. Hand refuses an opencode model that is not in `opencode models` (after refreshing the list once). Before the resume Hand runs `opencode api --standalone session.switchModel` on the supervisor's session, and after any opencode resume it checks that opencode took the one-line resume note, and holds the messages until a switch or a new supervisor that answers when it did not; a failure leaves the supervisor stopped, `hand supervisor resume` runs it again, and `--cancel` also drops the switch of the newest stopped supervisor.

`hand supervisor switch --harness H` (or a profile on another harness) changes harness instead. It is refused while the supervisor is working; between turns it stops the supervisor and starts the next one on the new harness, with a launch message that names the one it replaces. The new supervisor starts a new session and orients from `hand orient`; the board keeps the earlier session in Chat under a divider. `hand route list` and the board's model menu list each harness's models and efforts from its [model list](#model-list): the variants of each opencode model as its efforts (none when `opencode api` could not be read), and no efforts for agy. The board's Start and switch forms group the model select by source, narrow the effort select to the chosen model, and add an "Other model" box next to the select; a name typed there wins over the select (the form posts it as `other` beside `model`), and a name outside the list starts with the warning.

A worker's model switch is `hand attempt switch aN --model provider/id [--effort VARIANT]`, for an opencode attempt only. It never waits: the attempt must be `running`, its pane idle or done at the prompt (checked again just before the stop), and opencode's session list must not show its session busy, else the command refuses and changes nothing, as it does for a model that is not in `opencode models` or one the session already runs. The route is the supervisor's restart without its resume note, because the worker's identity does not change: stop the pane's process (not the worktree sweep of `attempt stop`), `session.switchModel` on the attempt's session, then the same `--session` launch with no brief. One transaction points the attempt at the new terminal, writes the new model and effort into the attempt (with a `model.changed` event when they differ), and appends `attempt.switched`, whose detail reads `aN: switched to MODEL EFFORT, pane P`; the argv stored on the attempt, brief included, is unchanged, and the watcher's next sweep reads the model back from the session and corrects the column when it differs. If `switchModel` fails, the old pane is started again, and `attempt.switched` reads `back on OLD` when the session reads back on its old model, `back on its pane, on X` when it reads back on another model, else `back on its pane, model unverified`; the stored model is the one read back, else it stays. If the new pane cannot start, the session is put back on the old model (when it is known, else the error says where the session stays), and the attempt ends `interrupted` with the reason `switch to MODEL failed: …`; its worktree and session stay, and `hand attempt clean aN`, then `hand attempt start tN --continue aN`, starts it again on the same branch. A switch killed after the stop and before the new pane leaves the attempt `running` with no pane; the next command ends it `exited` (`terminal exited`), and the same two commands continue it, on whichever model the session ended on. A switch takes about 4 seconds, plus up to 30 seconds while the new pane settles; a send before then can be refused as not at a prompt.

### Routing profile

A named harness, model and effort in `routing.json` in the fleet home (for opencode the model is `provider/id` and the effort is its variant name, which may not be an effort level (`fast`, `thinking`, `none`), such as `{"harness": "opencode", "model": "local/m2", "effort": "deep"}`; a profile with no model starts opencode on its own configuration). `hand init` writes a starter of five `claude` `sonnet` profiles that differ only in effort (`quick` low, `default` medium, `high` high, `deep` xhigh, `max` max) when the file is missing, and never overwrites it. The supervisor's routing rules pick a profile; the profiles of a fleet may differ in model, so a step up can be a model change, and a missing profile falls back to the next one down. Only the worker's own result failing (wrong, incomplete, lost or looping) is a capability failure that steps up; a missing tool, credential, device, lock, permission or usage limit is not, and the attempt restarts at the same profile. `hand route list` shows the profiles and whether each is valid on this machine: its model and effort are well formed and its harness is found on `PATH`, by the same lookup a start uses. A profile whose model Hand cannot verify stays `valid: yes` and carries the reason in its `warn` column; one whose model has [left the list](#model-list) of Codex or agy is `valid: no`. A start from the board searches the board's `PATH`, which it keeps from when it started, and its error says so. The board's Start picker makes the same lookup on every render and marks a profile whose harness is missing as unavailable. `--profile NAME` picks one for `hand attempt start`, `hand supervisor start` and `hand supervisor switch`. A `claude` profile may add `"approve": "ask"` (the default `"never"` is today's launch, with prompts skipped; see [Approval](#approval)); `hand route list` and `hand attempt start` refuse `ask` on any other harness, and `hand supervisor start` and `switch` refuse a profile that asks. A `claude` profile may add `"access": "readonly"` (the default `"open"` is today's launch; see [Access](#access)); `hand route list` shows each profile's `access` and, last, its `mcp`, and a profile that is `readonly` on another harness, or together with `"approve": "ask"`, is refused as an invalid value, as is `hand supervisor start` and `switch` with a `readonly` profile. A `claude` profile may add `"mcp": "FILE"` to give its worker one MCP config; every Claude worker otherwise starts with no MCP server (see [MCP](#mcp)). The same file holds `supervisor.autoresume`, the watcher's `notify` command, its `stall` delays and `approve_timeout`. `hand route list` also prints a track record per harness, model and effort over ended attempts: how many, and the rates of first-try finish, re-attempt, stuck reports, interventions and wakes per attempt, and the median minutes to the first `done` report.

## Surfaces

### Orient

`hand orient`: a bounded summary of the fleet, rendered from state plus one scan of `reports/` and `shots/` (the `artifacts` line). It shows the home, the fleet, the supervisor (`supervisor: s21 opencode anthropic/claude-sonnet-5-5 running`: its ref, harness, model and effort when it has them, and status; the line is quoted when a value needs it, as for a model with a `:`), the task counts, the cursor, the unwatched tasks and their idle time when there are any, the armed timers when there are any (one due beyond 6 hours is marked `(beyond the horizon)`, a wait `(waits tN)`, and every one `(no managed supervisor: not fired)` while none runs), `inbox_folder` with the count and size of the inbox folder's files when there are more than 500 or they pass 100 MiB (with a help line pointing to `hand inbox size`), `artifacts` when `reports/` and `shots/` are over the `retention` limits (with a help line naming the `secondhand-cleanup` skill), the active tasks with their plan, attempt (with `quiet`, or `blocked:` and the screen's hint, when that is its newest signal, and `(waits until 2026-11-03)` while the task has a wait), report and open decisions, then the open decisions, the unread reports, the inbox, recent events and the operator memory. A title, question, hint or report summary that is too long is cut at a word boundary, so a URL is never cut in half. It stays under 6000 bytes: when it would not fit, it drops rows and says which command lists the rest. The supervisor runs it at the start of every turn and after every wake.

### Doctor

`hand doctor`: a check of this machine and the fleet it runs in, for when something does not work. It prints the binary's version, channel and path, git's version, the pinned Luvus and its server's version, then a `checks` table of `check,state,fix` rows, where the state is `ok`, `warn`, `fail` or `info` and every row that is not `ok` names its fix. The checks: `hand` (this binary is the one on `PATH`; a source build), `git` (found; `core.longpaths` on Windows), `harness NAME` for each harness found on `PATH` (a harness found only as a `.cmd` or `.bat` is a `warn` that names the file, because Hand never starts a batch file), `models NAME` for each of them (always `info`: how many models its [model list](#model-list) holds and from which sources, how old the cache is, or why there is no list), `systemd` on Linux (a user session, information only), `luvus pin` (pinned, unchanged and runnable), `iroh` (the [hand-iroh](#hand-iroh) sidecar: `info` when it is not installed, installed and off, or the board is not running; `warn` for a version other than the one this `hand` pins, a failed sidecar, one that reached no relay, or a recorded `--iroh` with no sidecar installed; `ok` while it is ready; the `iroh` field then holds its version and path and `iroh_id` the endpoint ID), and inside a fleet `schema`, `fleet` (registered under `~/.secondhand`), `project NAME` for each project (`ok`; `info` before its [git settings](#project-git-settings) are recorded; `warn` when its repository cannot be read; `fail` naming the settings that changed since), `routing.json`, `profile NAME` (the check `hand route list` makes; a `warn` naming the profile when its model cannot be verified, and also when its harness is missing while no harness at all is on `PATH`, the profile is still the one `hand init` wrote and no supervisor runs: a machine used for the Board only; a `fail` when its harness is missing in any other case), `luvus server` (its version against the pin), `board` (a board for this fleet answers at `board.addr`), `phone` (the [phone address](#phone-address): `ok` when serve proxies the board's root, `warn` for a mount under a path, `info` when serve is not set up, no `tailscale` answers or no board runs, `fail` when Funnel is on; it runs only the two read-only `tailscale` status commands) and `watcher`. Outside a fleet it skips the fleet checks and says so. It exits 1 when a check fails, else 0. It repairs nothing, starts no server, agent or board, reads the model lists without refreshing them, and spends no tokens. It opens `hand.db` as every command does, so a database of an older schema is migrated then. It reads no credential, so it cannot tell whether a harness is logged in, and it checks the shell's `PATH`, not the board's.

### Board

`hand board`: a local web page from the same binary, and the operator's interface. One board process serves every registered fleet. `/<fleet id>/` is one fleet's page, and `/` lists the fleets while the board listens on a loopback address; on a network address, and for a request that a proxy forwarded (`X-Forwarded-For`, `Forwarded` or `Tailscale-User-Login`), `/` shows no list, so open a fleet by its link, unless the request holds a valid [paired phone](#paired-phone) session: then it lists the fleets that phone is paired with, and no others. The default address is `127.0.0.1:7777` (`--addr`); `--peer-addr` opens a [peer listener](#peer-listener) beside it. `hand open` starts a board when none answers its `/<fleet id>/proof` check: `systemctl --user start` of an installed `secondhand-board` unit, else a transient unit of that name, else a detached process (macOS, Windows, no user manager) logging to `board.log`; it waits up to 10 seconds for the proof. `/<fleet id>/connect` is the Phone page, where the laptop shows a [pairing code](#pairing-code) and lists and revokes [paired phones](#paired-phone), and `/<fleet id>/pair` is the page a phone pairs on.

A fleet's page has two parts. At 900px and wider, the work pane (Needs, then Tasks) sits beside the supervisor pane, with a separator between them that the operator drags to size the chat (the board remembers one width); below that Needs, Tasks and Chat are three tabs, which merge into the masthead on short screens. `/<fleet id>/supervisor` is the supervisor's Screen page: it reads the pane unconditionally (40 lines, whatever the agent state), shows the text with its revision and digest, the fixed key toolbar and, when the screen is a dialog, an Ask card. A dialog is a supervisor whose reported state is `blocked`, or a screen whose question line sits directly above its option block and the prompt's own footer (`select`, `↑/↓` or `esc`) in the last rows; a bullet or a numbered transcript line alone is not a dialog. A numbered card presses `1`, `2`, `3`; a card whose options are marked `◯` and `◉` moves from the cursor to the option it names (`up` or `down` once per row, then `enter`), so the focused option sends `enter` only. Each press carries the screen's revision, digest and last press, and a stale screen is refused. On a network address the page shows the screen and no forms. The page carries the same live status strip as the fleet page, so its tab title, favicon and Needs count follow the fleet, and a dropped stream shows the connection band with Reload. The [rail](#rail) lists the pages and the fleets:

- **Needs:** what waits on the operator, most severe first: the supervisor's blocked screens; a worker's blocked screen or its turn that ended without a report, once no supervisor is running or the supervisor has left it for 10 minutes; a worker stopped at a usage limit, at once and until it works again, and the supervisor while its screen shows a limit line; failed, exited or interrupted attempts (not those of a task that waits, while its wait is armed); "Work is waiting for a supervisor" while work waits on one; the idle supervisor once a stall wake went out (`Supervisor idle for 1h12m with 3 active tasks and no running attempt`), until the work is watched, another event arrives or the supervisor works; a supervisor that stopped unexpectedly; open decisions; unread reports; an attempt whose turn has run 60 minutes (`attempt.long`); a finished attempt whose worktree Hand keeps and why (Kept); `reports/` and `shots/` over the retention limits (Old files). The items sit in bands, one head per kind (Blocked, Failed, Decision, Report and so on); the top item is open and the rest are one-line rows. Below them sits the task list, grouped under Active and Inbox, with each attempt's agent state. With nothing waiting it reads "All clear";
- **Chat:** the supervisor pane: the conversation, read from the harness's own session record without tool calls or thinking (the supervisor's replies on the pane, the operator's messages as bubbles on the right, Hand's own events as one-line notes), plus the message box and the supervisor controls. The rail's Conversation page shows the same conversation on a page of its own.

When a fleet has more than one registered project, every task row, every decision and every report in Needs, and every row of the Tasks page carry a neutral badge with the task's project name (cut with an ellipsis, the full name in its tooltip); the badge links nowhere. Each task and each decision also has its own page; from the fleet page, tasks, attempts, decisions and reports open in the viewer dialog, outside links open in a new tab, and the rail, the crumbs and the pager navigate in place. The Tasks list under Needs keeps active and inbox tasks and the five most recent finished ones; **Browse finished tasks (N)** opens `/<fleet id>/tasks`, the Tasks page: a search over title, goal and ref (every word must match, in any case) that covers every task; filters for status (default (every status once there is a query, finished without one), or one chosen status), project (when the fleet has several) and a UTC date range, and results newest first, grouped by day with a count, 50 to a page. `hand task list --q` searches every status the same way. A task's finish date is the time of its `task.done` or `task.abandoned` event; a task still open dates by its last update. `?all=1` on a fleet page still lists every task. Every action answers with a short receipt, and Chat shows key presses and the supervisor's starts, stops and switches as Hand lines. The board is a projection of state, so restarting it loses nothing. The supervisor controls work only while the board listens on a loopback address. On a network address, only answering decisions and marking reports read still work.

### JSON API

The board's read-only views as JSON under `/<fleet id>/api/v1`, for a local client such as the planned desktop app. It serves the fleet status and Needs, the timeline, the tasks list, and task, attempt, decision and report detail, each in one envelope with the fleet, a [change cursor](#change-cursor) and `generated_at`. It needs the same session cookie as the pages, answers only on a loopback board, is read-only in v1, and never returns `last_screen` or any terminal screen. [`api.md`](api.md) has the endpoints and the error contract.

### Change cursor

The opaque `cursor` in a [JSON API](#json-api) envelope, and the `X-Hand-Cursor` header: it holds the fleet and the event sequence the board had read, not a time. A client sends it back as `?since=`: the same value answers `304 Not Modified` with no body, an earlier one answers the new data, and one this board did not issue answers `400 bad_cursor`.

`/<fleet id>/doc/<path>` is the document viewer: a read-only page for a file or folder inside the fleet home, on a loopback or a network address. It renders Markdown up to 1 MiB in document mode (relative links, relative images and task lists, still without raw HTML), shows other text of any size as numbered lines (a file up to 8 MiB whole, in chunks of 500 lines; a larger one as a window of about 4 MiB that opens at its end, moved by `?at=BYTE` or `?line=N`, with `?find=TEXT` listing up to 200 matching lines over the whole file, and `?from=BYTE&line=N` returning the complete lines appended since BYTE as the Follow feed, or the header `X-Hand-Reset` when the file shrank or was replaced), serves an image inline when both its bytes and its name say image, previews JSON (pretty up to 16 MiB), CSV and TSV (a header and a table of the first 2,000 rows), diffs, HTML (a sandboxed frame without scripts), SVG (an `<img>`), PDF (a same-origin frame), and video and audio (only when the sniffed type and the extension agree, with HTTP Range), each with a Source, Text or As written toggle where the file has text (Markdown up to 1 MiB has Rendered and Source, remembered in the browser as `hand.doc.source`), through `?raw` headers set per type (`sandbox` CSP, `nosniff`, no `allow-scripts` or `allow-same-origin`), lists a folder (folders first, then names in any case order with the exact name as the tie-break, dot entries hidden, every entry in pages of 500 by `?page=N`, a last page for a number past the end, and a refused symlink as a row with its reason and no link), gives an image its own page with `?view` (Fit) and `?view=actual`, steps a file's page to the neighbouring files of its folder (`Previous` and `Next`, with ← and →, skipping folders and refused entries), and offers every file as a download; a Markdown or text file has a **Wide** toggle (the dialog opens wide, the page in a reading width), and a Markdown table wider than its box has a **Pin first column** toggle, both remembered in the browser; a file whose first 8 KiB holds a NUL or invalid UTF-8 shows a notice instead of text. A text response never reads an unbounded file into memory and never writes unbounded HTML, and the line writer escapes every byte: ANSI colour (SGR 30 to 37 and 90 to 97, bold) becomes `x-` classes, other CSI and OSC sequences are dropped, C0 and C1 controls and bidirectional controls show as visible marks (boxed for the first 20,000 in a response, plain symbols after that, so the HTML stays within a few times the file's size), and a line is cut at 256 KiB. It refuses dot paths, the files at the top of the fleet home (`hand.db`, `board.token`, `AGENTS.md` and the rest), `luvus/`, `locks/`, `projects/`, anything that is not a regular file or a folder, and any path whose real path, after symlinks, leaves the fleet home; the same rules decide whether a `file` deliverable links to it, whether `hand open tN --delivered` opens it there, and whether an absolute path in a reply, decision, report, plan or document becomes a link (at most 50 paths in one message; a path that is missing or refused stays text). A path relative to the fleet home (`reports/t1/design.md`, `./shots/t2/`) links only inside backticks, and only when it exists inside the fleet home and passes the same rules; bare text links absolute paths only. To show the operator a file, put it under `reports/` and name it there: the Board cannot open a path outside the fleet home.

### Transcript

What a harness wrote down about a session, which the board reads in place, line by line, never loading a whole file, and skips a line it cannot read. The Chat reads the supervisor's; for `omp` it reads the session file under the agent folder's `sessions/`, lists its user and assistant messages, reads the served model from the latest assistant message and the context gauge from that message's usage, and keeps the launch's effort because omp does not record a resume's change. The attempt page reads a `copilot` worker's: `$COPILOT_HOME/session-state/UUID/events.jsonl` (`COPILOT_HOME` defaults to `~/.copilot`), where UUID is the word after `--session-id` in the attempt's launch line. It lists the latest 50 entries oldest first: the worker's messages (`worker`), each tool call as the tool's name and the first line of its command or path (`tool`, never its output), and a message sent to the worker after the brief. The details column adds **Answered by**, the model of the worker's latest message. A worker message keeps its first 4000 bytes. When the session's `selectedModel` is set, is not `auto` and differs from that model as typed (a dated alias of the same model would warn too), a warning line reads `Asked for X, answered by Y.`: Copilot started on Auto in place of a model it does not offer. The transcript has no turn or usage rows. A launch line without `--session-id` says so, and an attempt on another harness has no transcript on its page.

### Viewer dialog

A thing's page opened in place: a `<dialog>` in every Board page, outside the live regions (the fleet page's five and the supervisor page's `sup`) and the composer, that shows the page the Board fetched (a document, a task, an attempt, a decision, or a report as its task's page at the report's card), so it can never differ from the page. A click on a link to one opens it with `showModal()` and pushes the page's address (`pushState`) tagged with a depth of 1; a link followed inside the dialog pushes another entry one deeper, up to 20, so Back and the strip's Back step through the dialog's pages, Back at depth 1 closes it, Forward opens it again and a reload shows the normal page. Close, Escape and the backdrop go back the whole depth. Ctrl, Cmd, Shift and middle clicks, the dialog's **Open as a page** link (which always carries the page shown now) and a page without the script use the link's own `href` in a new tab. A task or attempt page in the dialog refreshes itself every 10 seconds while the page is visible, with one timer that stops when the dialog changes page or closes. The forms of those pages work in it (a decision's answer and a report's Mark read post with `fetch`, and on success the dialog's page and the page behind refresh); the answer box keeps its own draft key, `dialog:<decision id>`, beside the Needs box's. A form outside that table would be disabled under a line that sends the reader to the page. The live refresh and the event stream of the page behind keep using the address the Board page was opened on, not the dialog's.

### Rail

The Board's navigation: a 56px column of icons at the left edge from 900px, and below that a sheet opened from the masthead's menu button. It holds Board (with the live Needs count), Tasks, Conversation, Screen, Phone and the fleets. A name shows on hover, on focus, or for every item at once from the label button. It lists the current fleet and only the other fleets whose token the browser holds, or whose pairing the phone holds, and that fleet still accepts; it shows no other fleet's Needs count. On a network address it lists only its own fleet.

### Board token

`board.token` in each fleet home. It guards that fleet's page, and the browser exchanges it for a cookie named for that one fleet, which only that fleet accepts. The cookie is kept for 400 days, or until `board.token` changes, only when the login link carries `keep=1` (plain `hand open` adds it), the board is on a loopback address and the request has no proxy header (`X-Forwarded-For`, `Forwarded` or `Tailscale-User-Login`). Any other login, such as a `hand open --print` link, a proxy, a header-less forwarder or `ssh -L`, or a network address, lasts until the browser quits. The cookie goes to every page of the board, which is how the rail knows the other fleets the browser can open. `hand open` logs the browser in with it without printing it, and only that login is kept; `hand open --print` prints a login link that holds it, for another device or browser. A [paired phone](#paired-phone) never holds it, and changing it signs every paired phone out.

### Phone address

The HTTPS address a phone opens the Board at, which Hand finds without changing anything: it runs `tailscale serve status --json` and `tailscale status --json` (the `tailscale` on `PATH`, or the Tailscale app's folder on macOS and Windows; each for at most 2 seconds, the answer kept for 30 seconds) and reads the serve configuration. It is known only when serve proxies the Board's root (`/`) over HTTP to the Board's own address and Funnel is off: then it is the serve name, such as `https://laptop.tailnet.ts.net`, with the port when it is not 443. A mount under a path, a TCP forward, another port, Funnel, a missing `tailscale`, an error, a timeout or output that is not a serve configuration leave it unknown. The Phone page's Network card names the state (ready, not yet, public, this computer), `hand doctor` reports it in its `phone` row, `HAND_NOTIFY_URL` uses it for alerts, and `hand open --print` prints the login link at it. An address typed on the Phone page overrides it.

### Paired phone

A phone the operator signed in from the Board's Phone page, which the state keeps as a device: a number, a name the operator typed on the phone (40 characters at most), the Tailscale login `tailscale serve` sent when it paired (or `iroh:PEERID` for a phone that paired through a [peer preface](#peer-preface); none when it paired through a forward with no login), the pairing time, a [phone label](#phone-label) and a hash of its secret in the `device` table of `hand.db`. Its cookie is `__Host-hand_phone_<fleet id>` over HTTPS, else `hand_phone_<fleet id>`, and holds the device's number and secret, good for 90 days from pairing: the board refuses it after that, and the Phone page marks the row `signed out after 90 days` until it is revoked. It has its own form token, and no page it loads holds `board.token`. Revoking deletes the device. Pairing records `board.paired` and revoking records `board.revoked`, each with the detail `NUMBER NAME` and no task, in the same transaction as the change; neither is a wake kind. A phone cannot show codes or revoke another phone, and `hand orient` shows the events like any other. Rotating `board.token` makes every secret fail, since each hash is keyed with the token. A phone paired with several fleets holds one such cookie per fleet, each valid only for its own fleet, with that fleet's own record, hash, number, form token, `board.paired` event and revoke; the host checks only the fleets a request's cookies name, each once, to list them in the [rail](#rail) and at `/`. A record made before the label existed has an empty label, keeps working and reads `this fleet only` on the Phone page. **Revoke** deletes one fleet's record; **Revoke everywhere** deletes the records of one label in every fleet the laptop's browser holds a valid `board.token` login for, one fleet at a time, each with its own `board.revoked` event, and says which fleets it could not reach. A page served without a session names no fleet: its title and header read "this Board".

### Phone label

A random 16-character lowercase hex string, written into every [paired phone](#paired-phone) record that one pairing creates, in each fleet's `device` table (`device.phone`; empty for a record made before the label existed). It only says that those records are one phone's; it is no credential, opens nothing, and appears in no event, cookie or page a phone can load. The laptop's Phone page carries it in the hidden field of the forms that revoke that phone, and lists the records that share it as one phone. Two pairings of one phone get two labels, and no two phones share one. **Revoke everywhere** deletes every record with the label, in each fleet this browser is signed in to.

### Pairing code

A one-time code of 10 characters from the Crockford alphabet (`0-9` and `A-Z` without `I`, `L`, `O` and `U`; typing `I`, `L` or `O` is read as `1` or `0`), shown on the Phone page as `K7QM3-XRD2P`: 50 bits, from the system's random source. It works once and for 5 minutes, a new code cancels the one before it, ten wrong tries from any phone cancel every code, and a phone address that tries 5 wrong codes within a minute waits up to a minute. Only the laptop's login can show one, and it names the fleets it pairs: the fleet whose page shows it, plus any of up to 7 others that the laptop's browser held a valid token for and the operator ticked, kept in the board's memory next to the expiry and the used flag. One code pairs the phone with each of them, at most once. Codes live in the board's memory only, so a restart or a changed `board.token` cancels them. The pairing link a browser opens is `ADDRESS/<fleet id>/pair#CODE` (the [Companion app](#companion-contract) reads a different one, the [companion link](#companion-link)): the code sits in the `#` part, which the browser never sends, and opening the link only shows a form, so a preview cannot spend the code. The Phone page also draws the link as a QR code, black on white in both themes: the board encodes it itself (byte mode, error-correction level M, versions 1 to 10, so at most 213 bytes) and sends no request for it. A longer link shows as text only.

### Peer listener

A second loopback listener of `hand board`, off unless `--peer-addr ADDR` names a loopback address, and refused beside a `--addr` that is not loopback. It serves the same fleets as the board's own address, for a local tunnel (an `ssh -R` or `-L`, a forward) or the planned sidecar to point at, and counts every request on it as remote:

- The request counts as forwarded. `/` lists no fleet without a [paired phone](#paired-phone) session, errors are scrubbed, `keep=1` does not keep the login, and no page installs.
- Every client-sent `X-Forwarded-*`, `Forwarded` and `Tailscale-*` header is dropped before the board reads it. `Tailscale-Funnel-Request` is the exception: it still makes the board refuse the request.
- The pairing tries key on the connection's [peer preface](#peer-preface) ID, or on the one key `anonymous` for a connection with no preface, never on the socket address. The board's own address keys its tries on text of a different form, so a client there cannot spend a peer's tries by sending an `X-Forwarded-For` that looks like its ID.
- Only `/static/…` and `/<fleet id>/pair` answer without a paired phone's cookie, and a paired phone's cookie counts only while the connection's login matches the device's: `iroh:<peer ID>` for a connection with a preface, none for one without; a device with no login counts from any connection. `board.token` and a `hand_board_<fleet id>` cookie open nothing here, nor does one add a fleet to the [rail](#rail) or the Phone page, even beside a paired phone's cookie for another fleet. `/<fleet id>/proof` is refused here, paired or not.
- A connection that has shown no paired phone's cookie, on any path, is closed after 32 requests (Funnel refusals count) or 64 KiB read, and a request head is at most 16 KiB. Each of its requests must finish reading its body within 10 seconds, refused or not. A connection that has shown one has no cap and no body limit; every request is still checked, and a request that carries a phone cookie that no longer proves (the phone was revoked, or signed out after 90 days) puts the cap back, counting what the connection has read so far. A request with no phone cookie changes nothing. Every connection, paired or not, is closed after 30 seconds with no request.
- The supervisor's controls follow the board's own address, so they are on, as behind `tailscale serve`.

### Peer preface

The first line a connection to the [peer listener](#peer-listener) may send, before any HTTP byte, to give itself an identity: `HAND-PEER 1 PEERID SECRET` and a line feed, in single spaces, at most 256 bytes. PEERID is 16 to 64 characters of `0-9a-z`. SECRET is the contents of `board.peer` in `~/.secondhand`: 48 hex characters from the system's random source, made by the first `hand board --peer-addr`, kept with mode 0600, never printed, and read by a sidecar from that file (a path in its arguments, never the secret). A connection with the right SECRET gets the identity `iroh:PEERID`; one peer per connection, fixed for its life. The board never reads an `iroh:` login from the `Tailscale-User-Login` header. A connection whose first bytes are not `HAND-PEER ` carries no preface and is served as anonymous remote. A connection that starts `HAND-PEER ` and then has a wrong SECRET or version, a malformed PEERID, extra fields, a carriage return, or no line feed within 256 bytes, is closed without an answer. Changing `board.peer` takes a board restart, and the sidecar must read it again. The preface travels over loopback in the clear, which is why the listener is loopback only; the secret grants an identity, not access: a peer still needs a pairing code and then its cookie.

### hand-iroh

A separate program, built from the Rust crate in `iroh/` and released as `hand-iroh-<os>-<arch>.tar.gz` (`.zip` on Windows) with a `.sha256` file, never part of the `hand` binary. It opens an iroh endpoint on a key it keeps in a folder it is given. For each stream a dialer opens, it connects to the [peer listener](#peer-listener), sends the [peer preface](#peer-preface) with the dialer's endpoint ID and the secret from `board.peer`, and copies bytes both ways. It never decides who is paired: iroh admits every dialer, and the board applies its unpaired limits and its pairing check. It prints one `ready id=ENDPOINTID relay=URL` line (`relay=none` with no relay) and exits when its stdin closes. `hand` pins the one version it works with (`hand version` prints it as `iroh:`), looks for it next to `hand` and then on `PATH`, fetches it with `hand` (`install.sh`, `install.ps1` and `hand update`; `edge` carries none), and runs it as the board's child when the board starts with [`--iroh`](#phone-access-over-iroh): see [The hand-iroh sidecar](phone.md#the-hand-iroh-sidecar).

### Phone access over iroh

The opt-in of `hand board --iroh`, off by default and refused beside a `--addr` that is not loopback. The board opens the [peer listener](#peer-listener) on a free loopback port (or the one `--peer-addr` names) and starts [hand-iroh](#hand-iroh) as its child, with the listener's address, the path of `board.peer` and the key folder `iroh/` in `~/.secondhand`, an empty environment (except `SystemRoot` on Windows, which Go adds for DLL loading), and a pipe as its standard input that it closes when it stops. The sidecar is `starting`, `ready` with the endpoint ID and relay, `failed` with a reason, or `stopped`; `hand doctor` and `board.iroh` show it, and the Phone page shows it while the board serves, so `stopped` has no page. A sidecar that exits is started again after 1 second, then 2, 4 and 8 seconds; five exits in a row that each came within a minute make it `failed`, and so does a missing sidecar or one of another version, which are not retried. A failed sidecar never stops the board. The board records the setting in `board.iroh`, which `hand open` and `hand update` use to start the board again with the flag. Pairing a phone over it is not built yet.

### Hand's Android Companion

The phone app that dials the laptop's [hand-iroh](#hand-iroh) endpoint ID and shows the Board in a web view. It is for Android only; the Android app is built outside this repository against the same [contract](#companion-contract). Hand's iOS Companion is deferred, and nothing targets iOS.

### Companion contract

The page [`companion.md`](companion.md) and the test vectors beside it, which fix what a phone app may rely on when it reaches the [peer listener](#peer-listener) through the [hand-iroh](#hand-iroh) sidecar: the protocol name `hand-board`, one bidirectional stream per TCP connection, the close and reset codes 1 to 5, the caps, the [companion link](#companion-link), what the app opens, and the version rule. It has one whole-number version, 1 today. The app is a separate program built against it; the Board's side, the Phone page's choice and the effect of revoking on an open connection, is built, and the page marks what remains of step 3. iOS is deferred.

### Companion link

What the Phone page shows, as a QR code and as text, to pair the Companion app: `handboard://c#v=1&e=ENDPOINTID&f=FLEETID&c=CODE`, and `&r=RELAY` (a percent-encoded relay URL) when the laptop does not use the public relays. It is at most 213 bytes, and everything in it is in the fragment, so a query, a server or a log never holds the [pairing code](#pairing-code). The app checks it against 15 reject rules in a fixed order and, once the user confirms, opens `http://localhost:PORT/<fleet id>/pair#CODE` in its web view, with the name `localhost` and never an IP address.

### Board app

The Board installed on a phone's home screen. One per board: its manifest's `id`, `start_url` and `scope` are `/`, so it opens the fleet list of that phone, not one fleet. It exists only for pages that reached the board through a proxy over HTTPS (`X-Forwarded-Proto: https` with a proxy header, never Funnel), where `app.js` registers `/sw.js`. The installed app on iPhone has storage of its own and starts signed out.

### Offline page

`/offline`: the static page the Board app's worker shows in place of a navigation that failed, timed out after 8 seconds or got a `502`, `503` or `504`. It reads "Laptop unreachable" with the time, has **Retry**, names no fleet and holds no session, and it is the only page the worker stores, with the three static files it links.

### TOON

The compact text format of every command's output: `key: value` fields, `name[N]{fields}:` tables, and `help[N]:` hints that name the next command.

## Changed since 0.7

Hand 0.7 ([`0.7`](https://github.com/atqamz/hand/blob/0.7/docs/vocabulary.md)) used some terms that the redesign dropped or changed:

- **Supervisor** was the operator's own interactive session. It is now the managed background agent `sN`. A session opened by hand still works, but stands down while a managed supervisor runs.
- **Supervisor harness and worker harness** were separate registries. There is now one list of harnesses, `claude`, `codex`, `opencode`, `agy`, `copilot` and `omp`, used for both roles, except that `copilot` is a worker only. Grok and Pi are no longer launched, although `hand init` still installs the skill for them.
- **Fleet identity** in `state/hand.db` is now the fleet ID in `hand.db` at the root of the fleet home, and fleets also have a name.
- **Fleet registry** (`~/.secondhand/registry.db`) is replaced by the pointer files in `~/.secondhand/fleets/`.
- **Current invocation context** has no term of its own. The fleet home is still found from the working directory or `HAND_HOME`, but the working directory now wins: a `HAND_HOME` naming another fleet is refused while you are inside one. `--home DIR` is new.
- **Duplicate fleet** remains a refusal: a copied fleet home is refused until one copy is deleted.
- **Supervisor orientation** is still `hand orient`. Monitor targets and currentness tokens are gone, and it prints an event cursor instead.
- **Monitor target, currentness token and wake hint** are replaced by events, the cursor and the `[hand v1 wake]` message.
- **Legacy Herdr namespace** is gone: Herdr and Treehouse are replaced by Luvus and plain `git worktree`.
- **Task kind** (`scout`, `ship`) and **execution class** (`mechanical`, `standard`, `deep`) are dropped. A task has only a goal. Whether it ships code is up to the brief.
- **Brief** front matter (`execution_class`, `planned_against`, `model`, `effort`) is dropped. A brief is plain text, and the harness, model and effort come from the attempt's flags or profile.
- **Profile** is now a routing profile in `routing.json`. **Route**, the mapping from task kind and execution class to a profile, is dropped. `hand route list` lists the profiles, and the supervisor names one per attempt.
- **Project** was cloned, adopted or created under the fleet home. It is now a name for an existing repository, which Hand uses in place.
- **Delivery mode and gate** (`direct-pr`, `local-only`, `no-mistakes`) are dropped, and Hand has no merge, deliver or teardown step.
- **Worker** is recognised by its worktree's path. `HAND_ROLE=worker` is gone.
- **Report** was a scout's file, `data/<id>/report.md`. It is now a record of any attempt, with a status, and it is read and acknowledged through Hand.
- **Plan**, **decision** and **supervisor input** are new records with their own refs.
