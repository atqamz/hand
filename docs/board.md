# The board

The board listens on `127.0.0.1:7777`. Each fleet has its own page at `http://127.0.0.1:7777/<fleet id>/`, and `/` lists the fleets. Each fleet keeps its own token in `board.token` in its folder, so logging in to one fleet never logs you out of another. A fleet you add or move shows up without a restart. The board also keeps each fleet's watcher alive (see [Keep the watcher and the board running](autostart.md#keep-the-watcher-and-the-board-running)). To reach the board from a phone, use a tunnel such as `ssh -L` or `tailscale serve`, then pair the phone on the Phone page (see [Pair a phone](#pair-a-phone)). Without Tailscale, [Reach the board from a phone without Tailscale](phone.md) covers an SSH tunnel, Cloudflare Tunnel with Access, WireGuard and a LAN address.

A fleet's page has a slim rail of icons at the left edge (Board, Tasks, Conversation, Phone and the fleets this browser or phone can open) and, from 900px wide, two panes. The work pane lists what waits on you (**Needs**), grouped by severity with the most severe first, then the tasks with a search field (**Tasks**). When the fleet has more than one registered project, each task row, the Tasks page, and each decision and report in Needs show the task's project as a small badge; with one project nothing shows. A decision shows its options as a choice list: pick one, add a note (required when the option starts with "Other"), and send. The supervisor pane on the right shows the supervisor controls, the conversation without tool calls or thinking, and the message box. Drag the line between the panes, or focus it and use the arrow keys, to resize the chat; the board remembers the width, and a double-click resets it. Below 900px the page has three tabs, **Needs**, **Tasks** and **Chat**, and the rail opens from a menu button as a sheet. Tasks, attempts, decisions and reports open in a dialog over the page, so the chat, Needs, the message draft and the scroll positions stay as they were; the rail and the page's own links stay in place. The **Tasks** page searches every task. Each task and each decision also has its own page. The board is a projection of Hand's state, so restarting it loses nothing, and it updates itself as things change. While the page is open, the board sends a small beat every 15 seconds when nothing else changed. If the page hears neither an update nor a beat for 35 seconds (the laptop slept, or a proxy or tunnel dropped the connection without closing it), a band under the header reads "Connection lost since 12:41", with the time of the last update, the status word reads "unknown" and the status line dims. The page reconnects by itself, and the band goes as soon as the board answers. The same band reads "Reconnecting…" in the first moments of a dropped connection, and "Log in again: hand open --print" when the board refuses the session ("Signed out: pair again on your laptop" on a paired phone, which the board refuses after Revoke or after 90 days).

A file deliverable inside the fleet folder opens in the Board's document viewer, `/<fleet id>/doc/<path inside the fleet folder>`; a path outside the folder, one that is gone, or one the viewer refuses stays text. The same holds for an absolute path written in a supervisor reply, a decision, a report, a plan or a document, and for a code span that holds only a path: it links to the viewer when the viewer would show it, and otherwise stays text. A click on a link to the viewer anywhere on the Board (a file chip, a path in a reply, decision or report, a deliverable, a sent file card or image in the chat, and a folder entry, Previous, Next, pager step or relative link inside the viewer) opens it in place, in a dialog over the page you are on: the chat, Needs, the tasks, the message draft and the scroll positions stay as they were. The dialog shows the same page, with the same header, Copy path, Find, Follow and toggles; Esc, the close button or Back closes it, and Forward opens it again. The address bar shows the file's address while it is open, so a reload on it shows the normal page and the address opens in a new tab. **Open as a page** in the dialog's top strip, and a Ctrl, Cmd, Shift or middle click on any such link, open it in a new tab; with no script, every link is the same new-tab link. Text past 8 MiB opens at its end in the dialog too, as it does in the page. The dialog loads the file the same way a tab does, and a path the viewer refuses or cannot find shows its reason in the dialog with a Close button.

The same dialog opens a task, an attempt, a decision and a report, from any link to one on the Board: a task row, a Needs link, a ref in a reply, a Hand line, a report or an event, the Tasks page, the conversation, the attempt page's links, a deliverable. A report opens as its task's page at the report's card. The strip at the top of the dialog has **Back**, the page's title and **Open as a page**, which opens the page the dialog shows now in a new tab. A link followed inside the dialog goes one page deeper: Back, the browser's Back button and Alt-Left return one page, Back is disabled on the first page, and the browser's Back button on the first page closes the dialog; Esc, the close button and a click outside the dialog close all of it. The dialog keeps at most 20 pages deep. A task or attempt page in the dialog updates itself every 10 seconds, without moving what you are reading, and stops when the dialog closes or opens another page. What the page does, the dialog does: answering a decision and Mark read work in it, post without leaving the page, show a refusal or a decision answered elsewhere in the form with your text left in place, and on success update the dialog's page and the Needs list and counts behind it at once. The answer box in the dialog keeps its own draft, apart from the one in Needs for the same decision. Places (the rail, the crumbs, the Tasks page, the conversation) navigate in place, and a PR or any outside link opens in a new tab. A Ctrl, Cmd, Shift or middle click, and a page without the script, open the link in a new tab as before.

The viewer only reads:

- **Markdown** up to 1 MiB renders with tables, code blocks, task lists, and relative links and images that resolve inside the fleet folder; raw HTML stays text, and a remote image stays a link. A **Rendered** and **Source** toggle in the header switches a `.md` or `.markdown` file between that view and its raw text (numbered lines, `#L12` anchors, Find, Wrap, Follow and Copy contents of the file, as for any text); the Source view is `?as=text`, so Previous, Next, the pager, Find and the dialog keep it, and the choice is remembered in this browser (Rendered stays the default; with Source remembered, a Rendered page loads and then switches to Source, keeping a `#L12` anchor, and a Ctrl, Cmd, Shift or middle click on the toggle leaves the choice alone). A file over 1 MiB, or one that is not text, has no toggle and shows as it did before. A table's first column scrolls with the rest; a table wider than its box shows a **Pin first column** toggle that keeps the first column in view, and the choice is remembered in this browser. A Markdown or text page has a **Wide** toggle that lifts the 80ch reading width to the whole page, and the viewer dialog opens wide by default; the choice is remembered in this browser.
- **Other text** of any size shows as numbered lines, never refused for its size. A file up to 8 MiB shows whole; a larger one opens at its end, 4 MiB at a time, with **Start**, **Earlier**, **Later**, **End** and a **Line** field to jump. Lines show as text only: ANSI colours become a fixed set of classes, other escape sequences are dropped, control characters and bidirectional marks show as visible symbols, a carriage return keeps the last part of the line, and a line past 256 KiB is cut with a note. **Find** (`/` focuses its field; on a whole file, the browser highlights matches and steps through them with Enter and Shift+Enter; on a larger one, or where the browser lacks the highlight API, it lists up to 200 matching lines of the whole file, matched against the raw bytes of each line up to its first 256 KiB, so it can differ from the highlights on text that holds escape sequences or carriage returns), **Wrap** (which hides the line numbers), **Follow** (the end of the file, as it grows; it stops with a notice when the file is replaced or shortened) and `#L12` links to a line (these work with the script on) sit above the text. Markdown over 1 MiB shows as text too.
- **JSON** up to 16 MiB shows pretty-printed (two-space indent, the same numbered lines, windowed like any large text when the result passes 8 MiB), with an **As written** toggle for the bytes in the file; a file that is not one valid JSON value, whose pretty form would pass 64 MiB, or that is larger than 16 MiB, shows as written, with a note for the first two. **CSV** and **TSV** show as a table of the first 2,000 rows (the first row is the header and does not count; a cell is cut at 300 characters; a column of numbers is right-aligned; the first 8 MiB is read), with a **Text** toggle for the whole file. A **diff** or **patch** (`.diff`, `.patch`) colours added, removed, hunk and file-header lines. Every Source, Text and As written view goes through the same line writer as other text.
- **HTML** (`.html`, `.htm`) shows as a preview "without scripts": a sandboxed frame with no scripts, no forms and no access to the Board, so its scripts, links and relative images do nothing; **Source** shows the markup as text. **SVG** shows as a picture, never as a document, with a **Source** toggle. A **PDF** shows in the browser's own viewer, in a frame of the same origin, and keeps its Download.
- **Video and audio** (MP4, WebM, MP3, WAV, Ogg and Opus) play in the page, with seeking, only when the type the Board finds in the file's first bytes and its extension agree. A file whose bytes and name disagree is text if it is text and a download if it is not.
- **An image** shows inline only when both its bytes and its name say PNG, JPEG, WebP or GIF. A link to it from a folder or a neighbouring file opens its own page (`?view`), with **Fit** and **Actual size** (`?view=actual`), a Download, and Previous and Next to the neighbouring images; the bare path still returns the image itself.
- **A folder** lists its folders first, then its files (names in any case order, a tie broken by the exact name, so the order is the same on every request), with a thumbnail for each image; dot entries are hidden. Every entry is listed, 500 to a page: `?page=N` (an out-of-range number shows the last page, a bad one the first), with the count ("1,200 entries, page 3 of 3"), First, Previous, Next and Last above and below the list, and a **Page** field to jump when there are more than three pages. A link that leads outside the fleet folder, to a file the Board never shows, to nothing, to a loop or to something that is not a file or folder stays in the list as a row that is not a link and says so in plain words ("leads outside the fleet folder", "points at a file the Board never shows", "points at nothing", "cannot be read"), never naming the target. The server reads only the names of a folder, which for 100,000 entries cost about 20 MiB of heap and 0.3 s, and the page holds the 500 it shows.
- **Stepping through a folder:** a file's page shows **Previous** and **Next** to the neighbouring files of its folder, in the listing's order, skipping folders and refused entries (a folder with one file shows neither), and ← and → do the same unless the focus is in a field, a media control, the text or a scrolled picture, or text is selected. The folder link in the crumbs returns to the listing page that holds the file.
- **A file that is not text**, one with a NUL or invalid UTF-8 in its first 8 KiB, and not a PDF, picture or media file described above (an archive, an APK, an Office file, any binary), says so and offers a Download, which the browser saves (`Content-Disposition: attachment`, `nosniff`, a sandbox CSP) and never runs. Every file has a Download link.
- **Copy path** in the header copies the absolute path shown there, for a file or a folder. **Copy contents** on a Markdown or text page copies the file as written (up to 8 MiB); on a windowed large file it reads **Copy window** and copies the lines the page shows. Each says "copied" in the status line, or asks the reader to select the text when the browser refuses the clipboard.

The previews load the file from `?raw`, which sets the headers by type, always with `nosniff` and a `sandbox` CSP that has no `allow-scripts` and no `allow-same-origin`: HTML (`text/html`, with `frame-ancestors 'self'` and `X-Frame-Options: SAMEORIGIN`, inline styles only, no images), SVG (`image/svg+xml`), PDF (`application/pdf`, `SAMEORIGIN`), media and images (their sniffed type), any other text as `text/plain` (so `.js`, `.md` and a `.png` that is not a PNG show as text) and anything else as an attachment. The page itself allows `media-src 'self'` and `frame-src 'self'` and nothing else new. PDF was checked in Chromium only.

It never shows dot files and dot folders, the files at the top of the fleet folder (`hand.db`, `board.token`, `AGENTS.md` and the rest of Hand's own), `luvus/`, `locks/`, `projects/`, a FIFO or device, or a path whose real path, after symlinks, leaves the fleet folder, and it says which rule refused the path. It works on a network address too, so the fleet's token also reads the fleet folder's files: keep the board on loopback and reach it through a tunnel.

`hand open` opens a page in your browser, from inside a fleet:

| Command | Opens |
|---|---|
| `hand open`, `hand open supervisor` | the fleet page |
| `hand open tN` | the task |
| `hand open dN` | the decision |
| `hand open rN`, `hand open aN` | the report or attempt, on its task's page |
| `hand open tN --delivered` | the task's newest deliverable: a PR, a document, or a file or folder, in the document viewer when it is inside the fleet folder |

`--delivered` opens a file or folder inside the fleet folder in the document viewer when the viewer serves it, through the same login link as the other pages, and `--print` prints that link.

`--delivered` never opens any other file itself, because the path is text from a worker's report or `hand task done --deliverable` and the OS opener runs programs: for a path outside the fleet folder, gone or refused, it opens the folder that holds the file, or the folder itself, and it opens a URL only when its scheme is `http` or `https`; `--print` prints that path or URL as it is. It never opens a UNC path (`\\host\share\...`), because Windows would connect to the host it names and could leak credentials: it exits with an error that prints the path, and when the newest deliverable is a UNC path it does not fall back to an older one.

`hand open` logs the browser in with the fleet's token through `xdg-open` (on macOS, `open`) and never prints the token; `hand open --print` prints the login link instead, for a phone or another browser, so keep that output private. When `tailscale serve` proxies the board's root over HTTPS, the printed link uses that address instead of `http://127.0.0.1:7777`, and holds the same token; plain `hand open` always uses the local address. It finds the board through `~/.secondhand/board.addr`, which the running board writes, and starts a board first when none answers.

The board is where you start, chat with and resume the supervisor. Those controls work only while the board listens on a loopback address, which a tunnel keeps true. On a network address such as `0.0.0.0` the supervisor controls are off; answering decisions and marking reports read still work.

The Start picker lists every routing profile and marks the ones whose harness is not on the board's `PATH` (the one it started with): the option is disabled and reads "claude not found on the board's PATH" (on Windows, "codex found only as a batch file" when the only `codex` on `PATH` is a `.cmd` or `.bat`, which Hand never starts), and the preselected profile is `default`, or the first available one when `default` is not. When none can start, the Start button is off and a line names the missing harnesses and the fix: install the harness or add its folder to `PATH` (for a batch file, install the standalone harness or add the folder of its `.exe`), then restart the board: `hand board stop`, then `hand board`, or restart its unit. The check is the lookup a start makes, runs no harness and is redone on every refresh, so an install shows after the next one. A profile whose model has left a fresh Codex or agy [model list](vocabulary.md#model-list) is disabled the same way, with "model X is no longer listed by agy" after the middle dot, and the preselection skips it; a profile whose model Hand cannot verify stays selectable and carries its warning after the middle dot. The "Other harness, model or effort" rows are not marked.

Each of those rows, and the model menu, picks a model from the harness's model list: one select with the models grouped by source (built-in, discovered, custom; the custom group reads "custom, efforts unverified" when Claude Code claims efforts Hand cannot confirm), each option showing the label and the name. The effort select follows the model: it offers only the efforts the list gives for it and is hidden for a model that supports none; an unverified model offers the standard efforts with "efforts unverified" under the row. "Other model" stays beside the select and wins when it is filled (the effort then offers every effort, marked unverified); choosing from the select clears it. A harness with no list keeps its two text boxes, and opencode shows no model control until its model can be applied. Under a row, a muted line "listed 3 h ago" appears only when the list is older than its limit, and "refresh failed: …" with the reason when the last refresh failed; a stale list is still used. A live update keeps the choice and the text typed in a row.

**Refresh models** is the last row of the overflow menu (laptop sessions only; a paired phone does not see it and is refused). It posts to `/models/refresh` (optionally `harness=claude|codex|agy`), starts the refresh of each list in the background (at most a minute), answers at once with "Refreshing models…" and never waits for a harness. Without `harness` it starts every harness that is not busy or cooling down and answers 204 when at least one started (a refusal of all of them is a 429 with the reason). It runs one refresh per harness at a time and at most one every 30 seconds ("claude models are already refreshing", "claude models were refreshed 12 s ago; try again in a moment"); the page shows the new list at its next live update, and a failure shows as the note under the row. The Board reads the cache and runs a harness only for this action.

## The attempt page

Every `aN` on the Board, in a reply, a report, a decision, an event or a Needs item, opens the attempt's page, `/<fleet id>/attempt/aN` (`hand open aN` opens it too; a bare number works as well). The task page's attempt rows and "from aN" lines link to it. It shows only what `hand.db` holds, the same facts as `hand attempt show aN`:

- the header: harness, model and effort, the status with its reason, when it started and stopped and for how long, the branch, the worktree path with a **Copy path** button, the pane while it runs, the attempt it continues, and the PR, MR, link or file chips of its reports;
- its reports, as on the task page, each with **Mark read** while unread;
- the **brief**, the briefing the supervisor gave the worker, which Hand stores as the last word of the launch command, and the **launch line**, the rest of that command;
- a **timeline** of every event that names the attempt, oldest first: its state changes, the turns the watcher saw end or block, the keys pressed on its screen (key names, never text), what was typed into it (a byte count), the folder Codex saved as trusted, its reports and its cleaning.

A worktree that `hand attempt clean` removed is marked as removed, and its branch is kept. The page does not show the worker's screen, the last screen Hand stored, or any transcript; see [Attempt](vocabulary.md#attempt). A running attempt's page refreshes itself like the task page, every 10 seconds, so the timeline and the report fill in without a reload.

The page holds nothing the task page does not already hold, apart from the brief and the launch line, so a paired phone opens it, the network-address board serves it read-only, and Funnel and unauthenticated requests are refused as for every other page.

## Pair a phone

The rail's **Phone** page, `/<fleet id>/connect`, signs a phone in without giving it the fleet's token. Only a browser logged in with the token, the laptop's, can open the page's controls. The board still listens on loopback, and the phone reaches it through a tunnel you set up: `tailscale serve --bg 7777`, an SSH tunnel or any other. The page sets up no network; its **Network** card reports what it finds, and Hand never changes a Tailscale setting.

The card runs `tailscale serve status --json` and `tailscale status --json` (the `tailscale` on `PATH`, or the Tailscale app's own folder on macOS and Windows), each for at most 2 seconds, and keeps the answer for 30 seconds. They need no root and change nothing. A missing `tailscale`, an error, a timeout or output that is not a serve configuration all read as no Tailscale. The card then says one of:

- **ready**: `tailscale serve` proxies this board's root (`/`) to the board's own address. It names the HTTPS address, such as `https://laptop.tailnet.ts.net`, and counts the user-owned Android and iOS devices on your tailnet that are online. The address field below is filled with it.
- **not yet**: Tailscale answers but serve does not proxy this board, or proxies it under a path such as `/board` (the board's links need the root). The card lists the steps: turn on HTTPS certificates for the tailnet once (Tailscale admin console, DNS, HTTPS Certificates; the certificate puts this computer's name in public certificate transparency logs, so rename a revealing name first), run `tailscale serve --bg 7777` (on Linux, once before it: `sudo tailscale set --operator=$USER`), and install Tailscale on the phone. Hand runs none of them. Serve must proxy `http://127.0.0.1:PORT` (or `localhost`) to this board's port, over HTTP, with no path after it; a TCP forward does not count.
- **public**: Tailscale Funnel is on for this board. The board refuses Funnel requests, and the card says to turn it off (`tailscale funnel reset`). `hand doctor` reports it as a failure.
- **this computer**: no Tailscale answered. Use another tunnel, such as one of the paths in [Reach the board from a phone without Tailscale](phone.md), and type its address.

A typed address always wins: the field takes any address the phone opens, the browser remembers one that differs from the detected one for the fleet, and it is the one the pairing link and the QR code use.

1. **Check the address the phone opens.** With `tailscale serve` set up, the field already holds it. Otherwise type it, for example `https://laptop.tailnet.example` (no path); the browser remembers it for the fleet. When this browser holds the token of other fleets, **Fleets this phone may open** lists them with a checkbox each: only the fleet you are on is ticked, and the phone gets only the fleets you tick (see [Several fleets on one phone](#several-fleets-on-one-phone)). Choose **Show pairing code**.
2. The page shows a **pairing code** of 10 characters, such as `K7QM3-XRD2P`, and the pairing link `ADDRESS/<fleet id>/pair#CODE` as text you can copy and as a **QR code** beside it, for the phone's camera. The QR holds that one link, so it is as private as the link: valid once and for 5 minutes, and anyone who photographs it within that time can pair first. It stays black on white in the dark theme, because scanners need it, and the board draws it on its own, with no request to any other service. A link too long for a QR code (over 213 bytes) shows no picture, only the text link and the code. The code works once and only for 5 minutes. **New code** shows another and cancels the one before it. Ten wrong tries from any phone cancel every code, and a phone address that tries 5 wrong codes within a minute waits up to a minute. The address is the last `X-Forwarded-For` entry, which `tailscale serve` sets; behind a proxy that passes a client's own header through, a client picks its own address, and only the ten-wrong-tries rule limits its guessing. Codes live in the board's memory only, so restarting the board or changing `board.token` cancels them.
3. **On the phone**, open the link. Its page is a plain form: opening it, or a messenger previewing it, spends nothing and signs nothing in. The script moves the code from the address bar into the code field (the code is in the link's `#` part, which the phone never sends to the board) and puts the cursor in the name field. Or open `ADDRESS/<fleet id>/pair` and type the code; `I` and `L` read as `1`, `O` as `0`. Choose **Pair**. A code that expired, was used, is wrong or follows too many wrong tries says so, and the form stays.
4. **The phone's session** is its own. For each fleet it was paired with it holds a cookie `__Host-hand_phone_<fleet id>` (`hand_phone_<fleet id>` over plain HTTP), HttpOnly, SameSite Strict, good for 90 days from pairing (the board refuses it after that, whatever the cookie says), and its own form token, so no page it loads holds the fleet's token. It can do what the board allows on that address: chat, answer decisions, control the supervisor, attach files. It cannot show a pairing code or sign out another phone. On a read-only board (a network address), it is read-only like every session there. Its Phone page reads "This phone" with **Sign out this phone**.
5. **Paired phones** lists the phones paired with this fleet and, when this browser is signed in to other fleets, the phones paired with those (see [Revoke a phone everywhere](#revoke-a-phone-everywhere)): each one's name, its Tailscale login when `tailscale serve` sent one, the time it paired and the last time it asked for a page (the last time is kept in memory and is empty after a restart). A phone paired before one code could pair several fleets reads `this fleet only`: pair it again with more fleets ticked, then revoke the old row. **Revoke** signs that phone out of this fleet at once, including a page that is open, and the phone then reads "This phone is no longer paired"; its other fleets stay paired until you revoke it there too, or press **Revoke everywhere**. A phone paired through `tailscale serve` is bound to the login serve sent: a request with another login, or none, is refused. The header only narrows access, never grants it. Changing `board.token` signs out every phone and every browser, and the list keeps the phones' names until you revoke them.

The board records `board.paired` and `board.revoked` events (the detail is the phone's number and name, never a code or a secret), and keeps only a hash of each phone's secret in `hand.db`.

Through the phone's address the board also:

- refuses every request that arrives through Tailscale Funnel (`Tailscale-Funnel-Request`) with a page that says so, serving only its stylesheet and script. Never publish the board with Funnel or any other public proxy;
- shows no fleet list at `/` to a request that carries `X-Forwarded-For`, `Forwarded` or `Tailscale-User-Login`, which a proxy adds, unless the request also carries a valid phone session: `/` and the rail's **All fleets** then list exactly the fleets that phone is paired with (see [Several fleets on one phone](#several-fleets-on-one-phone));
- names no fleet on a page served without a session (the pairing page, the refusals for a missing, revoked or lapsed login, the Funnel refusal): its title, header and text read "this Board";
- answers a request that carries one of those headers for a fleet whose store cannot be opened exactly as it answers an unknown fleet id (404, "fleet not found"), so it shows neither the error nor whether the fleet exists but is broken. The board writes the full error to its stderr; a direct loopback request still shows it on the page;
- sends `Referrer-Policy: no-referrer` on every page, so a link out of the board never tells the other site the board's address.

`hand open --print` still prints a login link that holds the fleet's token, which a browser keeps as the laptop's session: pair a phone from the Phone page instead.

### Several fleets on one phone

One code can pair a phone with several fleets. On a fleet's Phone page, **Fleets this phone may open** lists the fleets this browser holds a valid `board.token` login for, with a checkbox each: the fleet you are on is always included and cannot be unticked, because the phone redeems the code at its address, and the others start unticked. The list is the rail's: at most 7 other fleets, so one code names at most 8. A phone's own pairing never counts here, so a phone cannot add a fleet, and a fleet this browser holds no valid token for is not listed. The code page then says "It pairs the phone with A and B."

The board checks the choice again when it makes the code: every posted fleet id must be on that list and still registered, and any other id is refused with "not signed in to every fleet you chose", names nothing and makes no code. The code keeps its fleets in the board's memory next to its expiry and its used flag; the phone's form carries only the code and a name, so a phone cannot change them. A code still works once and for 5 minutes, ten wrong tries cancel it, and a phone address that tries 5 wrong codes waits: a code that grants up to 8 fleets has the limits of a code that grants one.

**Pair** on the phone spends the code once and makes one secret. For each fleet in the code, that fleet's own board stores an ordinary phone record (the name, the login, a hash of the secret keyed with that fleet's own `board.token`, and a 16-character hex label that is the same in every record of one pairing and is no credential) and records its own `board.paired` event. No fleet gives another a hash or a token, and a fleet's board refuses a request to pair a phone unless the code that was spent names it. The response sets one cookie per fleet, `hand_phone_<fleet id>`, each holding that fleet's number for the phone and the secret (about 100 bytes each, so 8 add under 1 KB to every request); the names differ, so they never overwrite each other (`Path=/`, so all go to every page of the board), and each fleet accepts only its own, with its own form token: a fleet's form token posted to another fleet is refused. A phone's secret for one fleet proves nothing for another.

The records are written first, one fleet after another, and a cookie is set only for a record that was written; every cookie goes out in the one response, after the last record. A fleet that cannot be opened (down, removed) or whose store fails gets no record and no cookie, and the others still pair; the result page then reads "Paired with A and B. 1 fleet was not reachable. Pair it from its own Phone page on your laptop." It does not name the fleet that failed, because the phone is not paired with it. A reply that never reaches the phone leaves records with no cookie: they show on the laptop's list and you revoke them. A code for one fleet redirects to that fleet's page as before; a code for several shows the result page with an **Open** button for each fleet paired.

Each fleet keeps its own revoke, its own 90 days and its own `board.token`: revoking in one fleet, or changing its token, signs the phone out of that fleet only. **Revoke everywhere** cuts a phone off from all the fleets this browser is signed in to (see [Revoke a phone everywhere](#revoke-a-phone-everywhere)).

On a phone, the rail's **All fleets** and `/` list exactly the fleets whose cookie in that request is still valid for that fleet, with the same checks as a page of its own: the secret, the 90 days, the revoke, and the Tailscale login it was paired for. The board looks only at fleets named by a cookie in the request, and checks each fleet once per request. It never names a fleet the phone is not paired with, and never says how many others exist. A request with no valid phone session at `/` still reads "pair it on the fleet's Phone page on your laptop". Choosing a listed fleet needs no new login. If its pairing is revoked or lapses between the list and the tap, its page says "This phone is no longer paired with this fleet", with no fleet name, and the next list leaves it out. A board on a network address stays read-only and lists only its own fleet.

### Revoke a phone everywhere

The Paired phones card shows a phone paired with several fleets once. A row holds the phone's name, the names of the fleets it is paired with, its Tailscale login, the earliest time it paired and the latest time any of those fleets saw it, then one line per fleet with its own **Revoke**, and **Revoke everywhere** beside the name when the phone is in two or more of them. Records that carry the same phone label are one phone; two pairings of one phone, or two phones with one name, carry two labels and stay two rows. A phone listed for the fleet you are on and no other fleet reads as before, with one **Revoke**. A record from before the label reads `this fleet only` and lists only on its own fleet's page.

The card lists only the fleets this browser holds a valid `board.token` login for, the rail's fleets: at most this one and 7 others. A fleet it holds no valid login for is never read, so a phone's record there is never listed, and the page names no such fleet and counts none: it never says that a phone is "also paired with" others. A fleet that cannot be opened, or whose store fails, is named in a notice, "beta could not be reached, so its phones are not listed here."

The board reads another fleet's records through a method the host gives each fleet's board, `PhoneRecords`: a number, a name, a login, the label and two times, with no hash and no secret. The host calls it only for a fleet whose `hand_board_<fleet id>` cookie in the request matches that fleet's `board.token`, and checks it again at every call; the fleet you are on is read directly. A board with no host around it, a host that cannot check a login, a handler without the method, or a fleet that is down lists nothing from that fleet.

**Revoke** in a fleet's line, and **Revoke everywhere**, post to this fleet's page like any laptop form: this fleet's form token (its `board.token`), as every laptop form needs. That token alone grants nothing in another fleet. For each other fleet the board asks the host to revoke through a second method, `RevokePhone`, and the host opens that fleet's board only after it has read that fleet's own `board.token` and compared it with the laptop's cookie for that fleet, for this call. The fleet id and the label the browser posts are never trusted: the fleet must be one of the fleets this request proves, and the label must be 16 lowercase hex characters; a label that no proven fleet holds changes nothing and is answered like any other repeat, so no response tells whether a label exists in a fleet this browser is not signed in to. A fleet's own board refuses the call unless it carries a grant that names that fleet, which only the host makes after the proof and which a nil, empty or other fleet's grant cannot replace. A phone's own session, even one that also carries a laptop's login for another fleet, is refused before any of this runs: a phone can sign only itself out of its own fleet, and it never learns that its label exists elsewhere.

**Revoke everywhere** goes through the fleets one at a time, this fleet first. In each, one transaction deletes every record with the label and writes one `board.revoked` event for each (the number and the name, never the label or a secret). The phone's next request to any of those fleets gets "This phone is no longer paired with this fleet", and its open event streams close, as with a single Revoke. When every fleet answers, the page returns to the list. When some do not (down, a store that fails, a board that cannot do it), the others are still revoked and the page says plainly: "Revoked in A and B. C could not be reached: its record of this phone, if it has one, is still active. Press Revoke everywhere again when it is back, and also remove the phone from your tailnet if it is lost." with a **Revoke everywhere** button that posts the same label. Pressing it again asks every fleet again: those already done have nothing left to delete and write no second event, so only what remains is revoked, and a repeat of a finished revoke does nothing. A phone's records in a fleet that the host cannot read stay on that fleet's Phone page once it is back.

**Revoke everywhere covers the fleets this browser is signed in to.** A record in any other fleet is left alone and not mentioned: open that fleet and its Phone page, or sign in to it, and revoke there. A phone's own **Sign out this phone** stays per fleet; there is no "sign out of all my fleets" on a phone, because it would act in other fleets from a phone's cookie. On a board on a network address the host gives no fleet reach: the card lists, and **Revoke everywhere** revokes, this fleet only.

### Install the Board as an app

A phone can install the Board to its home screen and see an offline page when the laptop does not answer. It happens only on a page that reached the board through a proxy over HTTPS: the request carries `X-Forwarded-Proto: https` and one of `X-Forwarded-For`, `Forwarded` or `Tailscale-User-Login`, and no `Tailscale-Funnel-Request`. Then the page links the manifest, the home-screen icon and the theme colours, and `app.js` registers the worker, but only in a secure context. A board opened on a loopback address, over plain HTTP, through an SSH tunnel or through Funnel (which is refused) gets none of it, and nothing on those pages changes. There is no setting to turn it on; `tailscale serve` and a Cloudflare Tunnel send those headers, a proxy that sends none gets no app.

**One app per board, not one per fleet.** The manifest's `id`, `start_url` and `scope` are all `/`, so a phone paired with several fleets installs one icon, and it opens `/`, which lists the fleets that phone is paired with. `/` is the one page that answers without a session: a phone that is signed out, or was revoked everywhere, opens it and reads that it must be paired on the laptop, where `/<fleet id>/` would answer 403 and a refusal. The manifest holds no fleet name, so the same file serves every visitor and holds nothing private. It names the app "Hand Board" ("Hand" under the icon) and sets `display: standalone`; a manifest allows one theme colour and one background, so both are the light ground `#ffffff`, and the pages' own `theme-color` tags give the dark ground `#111317` to a phone in dark mode. The icons are the favicon's mark at 192 and 512 px and a maskable 512 px, on the dark ground.

**The worker** is `/sw.js`, served from the board's root with scope `/`, `Cache-Control: no-cache` and no cookie. It handles `GET` navigations only: it asks the network, waits at most 8 seconds, and on a network error, the timeout or a `502`, `503` or `504` from the proxy it answers with the offline page. Anything else it receives passes through untouched: a `POST`, `/events`, a fetch from the page, a document, an image. The one exception is a file under `/static/` that the offline page links: when the worker's cache holds that exact URL it answers from it, so the offline page has its stylesheet with no network, and otherwise it asks the network. It never stores a page, a response of the board's API, an event stream or a document. Its only cache writes are in its install step: `/offline` and the three files that page links (`board.css`, `favicon.svg`, `offline.js`), fetched without credentials. It uses no push and no background sync. `TestTheWorkerCachesOnlyTheOfflinePage` pins this.

**Updates.** `/sw.js` starts with a build stamp, a hash of the worker's source and the offline page it serves (and so of the hashed file names the page links). A new release that changes any of them changes the file, and the browser installs the new worker. The worker calls `skipWaiting` after its cache is filled and `clients.claim` when it activates: it keeps no state for a page and answers with nothing but the offline page and its files, so replacing it under an open page breaks nothing, and the first visit's page is under its control without a reload. A worker that cannot fetch its files at install, because the laptop is unreachable at that moment, installs nothing, and the next page load tries again. Activation deletes every `hand-offline-` cache except its own.

**The offline page**, `/offline`, answers without a session and names no fleet. It reads "Laptop unreachable", says since when and when it last tried, and has **Retry**, which reloads the page the phone was opening. It asks `/offline` again every 10 seconds and when the browser reports it is online, and reloads when `/offline` answers `200`, so a phone that was waiting on a sleeping laptop opens the Board by itself. The browser never shows the offline page for a board that answers, only for one that does not.

**On the Phone page**, the **Install** card appears on pages that qualify, for the laptop's and the phone's session alike. In a Chromium browser the **Install the Board app** button appears when the browser offers installation, and the card is hidden inside the installed app. For iPhone and iPad it says to choose Share, then Add to Home Screen, and that the installed app has its own storage, separate from Safari, so it starts signed out and must be paired again inside it.

No phone was used to check this: Chromium reports no installability error for the manifest on the fixture, and the offline page appeared 8 seconds after the proxy froze. Whether Safari copies its cookies into the installed app was not checked.
