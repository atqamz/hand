# Alerts on your phone

The watcher alerts you when an attempt ends, blocks, hits a usage limit or goes quiet (a repeated turn end, `attempt.idle`, does not alert; a block counts only once a second observation still reads `blocked`, the next status event or reconcile tick, so a one-poll flicker does not alert, and a failed `agent.explain` keeps the block pending for the next tick; it alerts on the first observation instead when Hand noted a launch problem (a trust screen it did not answer, a prompt it could not submit, a copilot that fell back to Auto or is not signed in), when an `ask` attempt's screen is not Claude's input prompt after the keys Hand or the operator sent, or when Luvus reads such a screen as idle after the attempt was working or blocked), when the supervisor asks a decision (`t3 decision: Keep the old cookie name?`), and once when the supervisor has idled 60 minutes with unwatched work ([When the supervisor idles](supervisor.md#when-the-supervisor-idles)). By default that is a desktop notification. On Linux it offers **Open**: a click opens the item's board page in the browser, signed in when that browser holds the 400-day login. Hand keeps up to 8 of those notifications waiting for a click, each for at most 10 minutes; when 8 already wait, when `notify-send` has no `--action` and `--wait` (checked once with `notify-send --help`), when the click command fails without printing the action, or when `board.addr` is not a board address (a loopback host with an explicit port; no login, query or fragment), it sends the plain notification without **Open**. To send every alert to your own command instead, put its argv in `routing.json`. This `sh` example is for Linux and macOS:

```json
"notify": ["sh", "-c", "exec curl -s -H \"Title: $HAND_NOTIFY_REF\" -H \"Click: $HAND_NOTIFY_URL\" --data-raw \"$HAND_NOTIFY_TEXT\" https://ntfy.sh/CHOOSE-A-LONG-RANDOM-TOPIC"]
```

Install the ntfy app on your phone and subscribe to that topic. Hand runs the command without a shell, with `HAND_NOTIFY_KIND` (`decision.asked`, `attempt.blocked`, `attempt.quiet`, `attempt.limited`, `attempt.exited`, `attempt.failed`, `attempt.interrupted`, `attempt.long`, `supervisor.limited`, `supervisor.stalled`), `HAND_NOTIFY_REF` (`d3`, `a7`, `supervisor`), `HAND_NOTIFY_TEXT` and `HAND_NOTIFY_URL` set. The URL is the item's board page. It is empty when no board runs or neither `board.addr` is a loopback board address nor `tailscale serve` is ready. It is the tailnet address when serve proxies the board's root over HTTPS (see [Pair a phone](board.md#pair-a-phone)), `https://laptop.tailnet.ts.net/<fleet id>/decision/d3`, which the phone opens through the Tailscale app, signed in as a paired phone; otherwise it is the loopback address the board listens on, for example `http://127.0.0.1:7777/<fleet id>/decision/d3`, which a phone cannot open. Hand reads the address from `tailscale serve status --json` and `tailscale status --json` and keeps it for 30 seconds; with no `tailscale`, no serve, serve under a path, or Funnel on, a loopback board gives the local address and a board on a network address gives none; [Reach the board from a phone without Tailscale](phone.md#alerts-that-open-on-the-phone) shows how to rewrite it in the command. The command gets 10 seconds, and a failure is ignored. When the timeout expires Hand kills the command; on Linux and macOS it kills the whole process group, but on Windows only the command itself, so a child of `sh -c` can outlive the kill. Prefer an argv that runs the program directly, or `exec` inside `sh -c`. A `routing.json` that cannot be read leaves the desktop notifier in use (on Windows there is none, so no alert is sent), and the watcher writes one line about it to its own output, `watch.log` when it runs detached, which no one is shown. `--notify=false` turns all alerts off.

The notify command sends that URL, the title and the text to wherever you point it. With the `ntfy.sh` recipe above, ntfy.sh receives them in the clear, so it sees your machine and tailnet name (which the HTTPS certificate already publishes in certificate transparency logs), the fleet id, the item's ref and the alert text. Nobody can open the link without the tailnet and a paired phone, but the text is yours to keep short: use a long random topic, or a ntfy server of your own on the tailnet.

On Windows, this toast recipe uses `powershell.exe` (unverified: it has not been run on a Windows machine). It borrows Windows PowerShell's app ID, because Windows may show no toast for an app ID that nothing registered. Hand starts it without a console window:

```json
"notify": ["powershell.exe", "-NoProfile", "-Command", "[void][Windows.UI.Notifications.ToastNotificationManager, Windows.UI.Notifications, ContentType = WindowsRuntime]; $x = [Windows.UI.Notifications.ToastNotificationManager]::GetTemplateContent('ToastText02'); $t = $x.GetElementsByTagName('text'); [void]$t.Item(0).AppendChild($x.CreateTextNode($env:HAND_NOTIFY_REF)); [void]$t.Item(1).AppendChild($x.CreateTextNode($env:HAND_NOTIFY_TEXT)); [Windows.UI.Notifications.ToastNotificationManager]::CreateToastNotifier('{1AC14E77-02E7-4E5D-B744-2EB1AE5198B7}\\WindowsPowerShell\\v1.0\\powershell.exe').Show([Windows.UI.Notifications.ToastNotification]::new($x))"]
```
