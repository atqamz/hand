# Commands

Run `hand` with no command to list the commands, and a command with no subcommand, such as `hand attempt`, to list its subcommands. Put flags before the positional arguments; only `hand open` also takes `--delivered` after the ref, `hand task done` its `--deliverable`, and `hand task parent` its `--parent` and `--root`; `hand task deliver` takes its values after the ref. `--home DIR`, given before the command, picks the fleet. `-h` or `--help` after a command that takes flags prints them and exits 0.

| Command | Purpose |
|---|---|
| `hand init [--name NAME] [DIR]` | Make a fleet, or refresh, rename or adopt a moved one. Refuses to make a fleet in a folder holding Hand 0.7 data. |
| `hand fleet adopt [--from OLD]... [--check]` | Rewrite every recorded old home of this fleet to the folder it runs in, in one transaction that appends a `fleet.adopted` event; any other `hand` command in a copied or moved fleet does this by itself first. `--from` adds an old home (repeatable); `--check` counts cells and occurrences per column, rehearses the rewrite on a scratch copy of the database and lists what would block it, writing nothing to `hand.db`. It refuses while an old home still holds a `hand.db` of this fleet, while the watcher, the supervisor or a board that serves this fleet runs, while the new home is inside an old home and while a move is pending; `hand supervisor stop` and `hand supervisor interrupt` never adopt, so they work in a moved fleet; see [Fleets](fleets.md#a-fleet-on-a-removable-disk). |
| `hand fleet unlock` | Clear `fleet.host`, the marker of the host that has this fleet open, and append a `fleet.unlocked` event; the attempts that ran there stay as they were. Use it when that host is gone. It refuses while this machine's watcher holds `watch.lock`. See [Fleets](fleets.md#which-host-has-the-fleet-open). |
| `hand fleet list` | List the registered fleets and whether each home is found: it reads the bookmarks in `~/.secondhand/index` and each fleet's `fleet.home` record. |
| `hand fleet move (--dry-run\|--yes) [--from OLD] [--rewrite-only] [PATH]` | Rewrite the fleet's recorded home paths and move its folder. The fleet's name follows the folder while it still equals the old folder's base name (on Windows, ignoring case): the move or `--rewrite-only` renames it to the new folder's name in the same transaction and records `fleet.renamed`, so a name that differs from that base, including one set with `hand init --name`, stays. Exactly one of `--dry-run` and `--yes` is required, and so is `PATH` unless `--rewrite-only` is given. `--from OLD` names the home to rewrite (default: the fleet home the command selects, and required when the database records no home); `--rewrite-only` rewrites to the selected fleet home, the folder it runs in or `--home DIR`, and leaves the folder there, which is how a copy on another filesystem is adopted after the original is deleted or moved and `hand init` adopts the copy. `--dry-run` lists every cell that would change, the absolute and `~/` occurrence counts and the result of the verification; it writes nothing to `hand.db`, though it can create or change `hand.db-shm` and `hand.db-wal`, and needs a writable folder. `--yes` rewrites every text column in one transaction in the plain, `file://`, `\/` and JSON `\u002f` spellings (and on Windows slash and ASCII case variants), except the `fleet.moving` and `fleet.moved` event rows, which are history and can keep an older home in them, scans the database independently of the rewrite, reports every hit in those columns and refuses while one remains, naming each cell and the manual fix, runs `foreign_key_check` and `integrity_check`, records the new home, writes a `fleet.moving` marker, closes and moves the folder, points the bookmark in `~/.secondhand/index/<id>` at it and appends `fleet.moved`. `~/<old folder>` becomes `~/<new folder>` only when both folders are direct children of `$HOME`; otherwise it becomes the absolute destination, and a `~/<old folder>` that is not the old home is left for you to edit, which the dry run lists and the move refuses. Letters, digits, `_`, `-`, `.`, `+`, a space and a non-ASCII byte are name bytes, so a path followed by one is a longer name (`fleet-hand.bak`, `fleet-hand backup`), never the fleet, except that a `.` at the end of the cell or before whitespace ends the path; `/` and `\` separate it from what follows. A `hand.db.pre-move-<time>` copy is written before the rewrite. It refuses a live supervisor, attempt, watcher or board, pending supervisor input, an armed timer, a destination that is not empty, the same or a nested path, another filesystem, a fleet missing from the registry, and a folder whose database records another home: `--from` alone does not allow that move, so run `hand fleet move --rewrite-only --yes --from OLD` there first. A move (without `--rewrite-only`) also rewrites its `gitdir:` prefix of every worktree gitfile under `~/.secondhand/worktrees/<fleet id>/` that names the old home, reports the rewritten, already correct and broken worktree counts, and fails when one is left broken; `--dry-run` reports the same counts and writes no gitfile. |
| `hand fleet import [--dry-run] SRC INTO DST` | Copy another fleet's projects and tasks, its `memory/`, `deliverables/`, `plans/`, `inbox/`, `reports/` and `briefs/` files, and its report bodies as archive files, without rewriting history; `--dry-run` prints the manifest and writes no row, file or marker, though SQLite may create `hand.db-shm`/`-wal` beside a database it opens, and it cannot detect an unwritable destination (see [Fleets](fleets.md#import-another-fleet)). |
| `hand project add NAME PATH`, `hand project list` | Register a repository by its absolute path, and list projects. |
| `hand project note NAME TEXT`, `hand project notes NAME` | Append a dated entry to the project's `notes/NAME.md` in the fleet home, created with a `# NAME — notes` title when missing, or print the file as a `notes` block; multi-line text is kept, empty text is a usage error, and an unknown project is refused with the names Hand knows. `notes` shows `no notes` for a registered project without a file. |
| `hand project trust NAME` | Accept the project's current git settings that name a program, after Hand refused to run git because they changed; prints each value. |
| `hand task add [--goal TEXT] [--parent tN] PROJECT TITLE` | Capture a request as an `inbox` task, under another task with `--parent`. |
| `hand task parent tN (--parent tM \| --root)` | Move a task under another one, or make it a root. A task cannot sit under itself or one of its own descendants. |
| `hand task start tN`, `hand task done [--deliverable PATH_OR_URL] tN`, `hand task abandon tN` | Move a task to `active`, `done` or `abandoned`. `--deliverable`, repeatable, records a file or link the supervisor produced itself: an http(s) URL or an absolute path; any other value is refused, and then nothing is recorded and the task stays as it was. `done` and `abandon` on a task with open sub-tasks finish it and print a `warn`. |
| `hand task deliver tN PATH_OR_URL...` | Record a deliverable on an `active` or `done` task, for a late or missing one: one `task.delivered` event per value, the same value rule as `--deliverable`, and the task's status, finish date, plan and reports stay as they were. A task in the inbox or abandoned is refused, and so is a bad value (exit 2), and then nothing is recorded, not even the good values of the same call. A value the task already has as a `task.delivered` event is skipped and listed under `already recorded`, so a backfill can run again; a value that only appears in a report's `Delivered:` line is recorded anyway, and the readers show it once. |
| `hand task list [--status LIST] [--q TEXT] [--since DATE] [--until DATE] [--limit N] [--flat]`, `hand task show [--full] tN` | List tasks newest first (default `inbox,active`; `--status` takes the board's words: `inbox`, `active`, `done`, `abandoned`, `finished` for done and abandoned, and `all` alone for every status), or show one with its parent, children, plan, attempt, wait, report, deliverables (newest first) and decisions. The list places each child after its parent, oldest root first, and adds a `parent` column only when a row has a parent; `--flat` prints the plain table, newest first. `--q` searches every status unless `--status` is given, and keeps tasks where every word, in any case, is in the title or goal or is the whole ref (`t12`). `--since` and `--until` take a UTC `YYYY-MM-DD` and filter on the day a task finished (`done` or `abandoned`; its last update otherwise). Rows of finished tasks carry that day in a `finished` column. `task show` cuts the goal at 4 KB the way `report show` does (head, omitted-bytes line, last 512 B); `--full` prints all. |
| `hand plan set --body-file PATH tN`, `hand plan show [--full] tN` | Add a plan revision (or `--body TEXT`), and show the current one. `show` cuts the plan at 8 KB the way `report show` does; `--full` prints all. |
| `hand attempt start [--harness H] [--model M] [--effort E] [--mcp FILE] [--continue aN] --prompt-file PATH tN` | Start a worker in a new worktree from the repository's fetched default branch (`origin/HEAD`, else `origin/main`, else `origin/master`, else its current branch; from a remote ref, unpushed local commits are left out, so pass `--base HEAD` to keep them); `--harness` is `claude`, `codex`, `opencode`, `agy`, `copilot` or `omp`, and a start without `--continue` and no `--harness` is a usage error (see `hand models`; opencode takes no model or effort, and agy no effort) (a model Hand cannot verify starts anyway and the output carries a `warn` field; `copilot` takes `--model auto` and an optional `--effort`, and runs a model its plan lacks on Auto without failing, which Hand notes as `attempt.blocked` when it sees the line at launch, as it does a signed-out Copilot), `--mcp FILE` gives a `claude` worker one MCP config, a path inside the fleet home (see [MCP](vocabulary.md#mcp); other harnesses are refused with exit 2, a link is followed only to a file inside the home and never into `scratch/`, and `--continue` does not inherit it), `--base REF` picks another start point, and `--continue aN` checks out the branch of `aN`, an ended and cleaned attempt of the same task, so pushes reach its PR, and an omitted `--harness`, `--model` or `--effort` comes from `aN` (a flag wins, then the attempt, then the harness default). Starting a worker ends the task's wait, if it has one (`hand wake --waits`). The pane starts through a hidden `hand attempt _exec` wrapper that makes the attempt's scratch folder and points `TMPDIR`, `TMP`, `TEMP`, `GOTMPDIR` and `CLAUDE_CODE_TMPDIR` at it, and, for a claude worker when `worker.compact_percent` in `routing.json` is a valid nonzero value, also sets `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` (see [Worker](vocabulary.md#worker)); `--continue` starts a fresh scratch folder because the one of the attempt it continues is removed by `clean`. |
| `hand attempt track` | Print the track record: a `track` table, below. |
| `hand attempt list [--task tN] [--limit N]`, `hand attempt show aN` | List attempts, or show one with its live agent state, or the last screen the watcher read from one that ended. |
| `hand attempt read [--lines N] aN` | Print a running worker's screen (40 lines by default, at most 500), as an indented multi-line block, and its revision. |
| `hand attempt keys --revision N aN KEY...` | Answer a worker's screen, only if it is still at that revision. Luvus names the keys: `enter`, `esc`, `up`, `down`, `ctrl+c`, a single character; it refuses any other as `unknown key`, so a modified key such as Shift+Left cannot be sent. |
| `hand attempt send --text TEXT aN` | Send a worker a message (or `--file PATH`, or `--file -` for stdin), only while it is at its prompt. |
| `hand attempt stop aN`, `hand attempt clean [--discard] [--keep-scratch] aN` | Stop a worker, and remove an ended attempt's worktree while keeping its branch. Clean also removes the attempt's scratch folder (`<fleet home>/scratch/tN-aM`), which holds a new `claude` worker's Claude Code directory, and any Claude Code directory it finds outside it from the operator's environment (a pane started before this change); each is a `scratch_removed` row with its size. `--keep-scratch` leaves them and prints them as `scratch_kept`; `attempt gc` lists them once the worktree is gone. |
| `hand attempt switch aN --model provider/id [--effort VARIANT]` | Switch an opencode worker's model, only while it is idle or done at its prompt and opencode runs no turn of its session (otherwise it refuses and changes nothing; it checks the prompt again just before it stops the pane, so a message that started a turn in between also refuses). It stops the pane, runs `session.switchModel`, and starts `opencode --standalone --auto --session ID` again in the same worktree with no brief, and waits up to 30 seconds for the new pane to settle; a `hand attempt send` before that can be refused as not at a prompt. The attempt's model and effort are recorded in the same transaction. The worktree is not swept, so the worker's background shells and dev servers in the pane's process tree end with it, as does its unsent text (`warn`), and a terminal that will not close is a `warn` too. A model not in `opencode models` is refused. A switch that fails puts the old pane back; when no pane can start, the attempt is `interrupted`, and the error names `hand attempt clean aN` and `hand attempt start tN --continue aN`. A switch killed between the stop and the new pane leaves the attempt `running` with no pane, and the next command ends it `exited`: recover it the same way. |
| `hand attempt gc [--apply] [--older-than DURATION]` | List the attempt scratch folders (`<fleet home>/scratch/tN-aM`) and the Claude Code scratch directories of worktrees that no longer exist (a dry run); `--apply` removes them, and `--older-than 72h` keeps those with anything modified more recently. Both print a `warn` for each directory they cannot remove and still remove the rest. |
| `hand gc --older-than DURATION [--yes] [SCOPE...]` | Without `--yes`, list the files in the fleet's `reports/` and `shots/` not modified for DURATION (days, like `30d`), grouped by task folder with their size, and the total; nothing is deleted. With `--yes`, scan again and delete the files that qualify then (run the dry run just before, and compare), or only those under the SCOPEs (`reports`, `shots` or a path inside one, after the flags). `memory/`, `briefs/` and worktrees are never listed. |
| `hand report add --status STATUS --file -` | Report from inside a worker's worktree: `progress`, `done` or `stuck`, from stdin, a file, or `--text`. |
| `hand report list [--task tN] [--attempt aN] [--unacked]`, `hand report show [--full] rN` | List and read reports. `show` prints a body of up to 8 KB whole. A longer one prints its first 7 KB, one line with the bytes omitted (the kept `Delivered:` lines count as shown) and the command with `--full`, the `Delivered:` lines of the omitted part (in order, 1 KB in all; a line that no longer fits is dropped), then its last 1 KB. Head and tail are cut at a line, or at a rune boundary when the nearest line break would drop more than half of that share. The sizes are bytes of the stored body, so quoting in the TOON output (quotes, backslashes, control characters) can print more; the stored body is unchanged. A report is cut only when the omitted part is larger than the note, and the supervisor reads it whole (`--full`) before acting on a cut one that matters. |
| `hand report ack [--by NAME] rN` | Acknowledge a report. |
| `hand history search QUERY [--limit N] [--since 7d\|36h\|DATE] [--who operator\|supervisor\|report] [--task tN] [--context N]`, `hand history search --full REF` | Search what was said in this fleet: the operator's messages (`iN`), the supervisor's prose replies (`yN`) and the reports (`rN`); no worker conversation or tool output, and no other fleet. QUERY is SQLite FTS5 syntax (`amber kiln` needs both words, `a OR b`, `"a phrase"`, `pre*`; case and Latin accents are ignored; a ref like `t12` is one word); words after the command are joined, and flags may follow them. A QUERY FTS5 cannot parse is searched as its words, each quoted and all required. Rows are `ref,at,who,task,supervisor,text` ordered by relevance then newest first, `text` a one-line snippet of at most 300 bytes with the match in `«»`; `total` counts every match. `--limit` is 1 to 50 (default 5, which stays under 4 KB). `--since` takes `Nd`, `Nh` or a UTC date. `--task tN` keeps a task's reports and the messages and replies that name it. `--context N` (0 to 5) adds a `context` table: the N entries before and after each message or reply hit, with `hit` naming the row they belong to. The output stops at 16 KiB with a line `N more; narrow with --since, --who or --task`. No hit is exit 0 with `hits[0]` and a help line; an empty QUERY, a limit, context, `who` or `since` out of range is exit 2. `--full REF` (`iN`, `rN` or `yN`, no QUERY) prints that entry whole; a body that would print past 16 KiB (the stored text is cut at 16 KiB, then more to fit the metadata and the two-space indent of each line) ends with a line saying how many bytes were omitted; an unknown ref is exit 3. Every printed text passes through `internal/redact`, since operator messages and reports are stored as written. Search matches the stored text, not the redacted output, so a query can confirm that a string occurs in an operator message or report even where the output shows `[redacted:…]` (see History in the [vocabulary](vocabulary.md#history)). Any process that can run `hand` in the fleet can run it, as with `hand report show`. |
| `hand history import [--dry-run] [--session ID]...` | Store the supervisor replies of sessions that ended before the watcher kept them (see History in the [vocabulary](vocabulary.md#history)). For every distinct harness session recorded in a supervisor row (or only each `--session ID`; an ID no supervisor recorded is exit 3 and nothing is written) it reads the whole transcript with the Board's Chat rules, keeps the supervisor's replies, numbers them as the watcher does, attributes each to the supervisor row of that session that was live at its time (the session's first row when none was) and stores them through `internal/redact` in chunks of 500, one `supervisor.replied` event per chunk. The key is the watcher's `(session, at, n)`, so a second run inserts 0 and writes no event, and a run beside the watcher is safe. Rows are `ref,harness,session,entries,inserted,status` (`ref` is the first row of the session), `status` is `ok`, `no session recorded` (the launch never recorded one), `no transcript` (the harness has deleted it, or no file matches; nothing can bring it back), `unreadable` (a format or an opencode export Hand cannot parse) or `harness missing` (an opencode session needs the `opencode` binary on `PATH` for its export), and `total` counts sessions, entries and inserted; the rows stop at 16 KiB with a line saying how many are not shown. `--dry-run` reads and reports, writes no row and no event, and `inserted` is what a run would insert. A manual command: the watcher never runs it. |
| `hand decision ask [--file PATH\|-] tN [QUESTION]` | Ask the operator about a task; the first line is the headline (at most 120 characters). |
| `hand decision answer [--by NAME] dN ANSWER`, `hand decision withdraw dN` | Answer or withdraw a decision. |
| `hand decision list [--all]`, `hand decision show dN` | List open decisions (or all), and read one with its answer. |
| `hand skills list [SCOPE]`, `hand skills add [SCOPE] [--ref REF] NAME\|PATH\|URL`, `hand skills update [SCOPE] [NAME]`, `hand skills remove [SCOPE] [NAME]`, `hand skills outdated [SCOPE\|--all]`, `hand skills sync [SCOPE] [--yes NAME@COMMIT] [NAME]` | List and manage skills that are not the two `hand init` ships, on the [Agent Skills](https://agentskills.io/specification) format; [Skills in the spec](spec.md#skills) has the model. `SCOPE` is `--project NAME`, `--fleet` or `--user`. With none, inside a git checkout the scope is that project: `.agents/skills/<name>` and `skills-lock.json` in the checkout, one root; in the fleet home it is refused with exit 2, listing the fleet's projects. `--project NAME` acts on the checkout the fleet registered for NAME. `--fleet` is the fleet home's `.claude/`, `.agents/`, `.grok/` and `.pi/` under `skills/`, with `skills-lock.json` in the fleet home; `--user` is the same four folders under `$HOME`, with `~/.agents/skills-lock.json`, and needs no fleet. A project skill whose folder is dirty in git (uncommitted or untracked) is refused by `add`, `update` and `remove` with exit 3. `list` prints `name,source,commit,scope,managed` for the skills in the scope's `.agents/skills`; in the fleet scope the two `hand init` ships show as `hand init`, `managed: no`. `add` subscribes the scope to the skill: it copies (never links) a skill folder, writes the entry `source` and `ref` into the scope's `skills.json` (`<checkout>/.agents/skills/skills.json` in a project, `<fleet home>/skills.json` in the fleet, `~/.agents/skills.json` for the user; commit the project's with its lock), `--ref REF` names the branch to track or the tag or commit to pin (an own source, the own skills repository, tracks `main`; any other git source is pinned to the commit `add` read; a `PATH` has no ref; a `refs/...`, `pull/...` or `merge-requests/...` ref is refused), and `remove` deletes the entry. Hand reads `ref` from `skills.json`, so moving a pin is editing that file and running `sync`. `add` copies, writes `managed-by: hand` into its `SKILL.md` frontmatter, and records `source`, `commit`, `skillPath` and a `computedHash` of the copy in the scope's `skills-lock.json`, the vercel-labs/skills version 2 lock, which keeps other tools' entries as they are and refuses another version; a project lock records a local `PATH` source relative to the lock (`./` inside it, `../` outside, `/` separators), as `npx skills` does, and Hand resolves it against the checkout that holds the lock, so a committed project lock holds no machine path (an entry another tool wrote relative in a fleet or user lock resolves against the fleet home or `$HOME`). A `PATH` is a folder holding `SKILL.md`; a `URL` (`https://`, `file://`, `git@`) is a git repository whose root is the skill, named after the repository; a bare `NAME` is `skills/NAME` in `https://github.com/atqamz/skills.git` (recorded as `atqamz/skills`). `add` and `update` refuse, with exit 2 and the field named, a skill that breaks the specification (`SKILL.md` frontmatter, `name` equal to the folder and lowercase with single hyphens, `description` 1-1024 characters, `compatibility` at most 500, `metadata` a block map rather than a flow map such as `{...}`, `SKILL.md` under 500 lines) and never rewrite its body. Git runs through the same helper as Hand's other git calls: a shallow clone into the temp folder, deleted after, with `GIT_TERMINAL_PROMPT=0` and, when neither `GIT_SSH_COMMAND` nor `GIT_SSH` is set, your `core.sshCommand` (default `ssh`) with `-o BatchMode=yes`, so a private `https://` or `git@` URL fails instead of asking for a password, a passphrase or a host-key answer. A skill folder over 32 MiB (the sum of its files, `.git` aside) is refused; the cap applies to the copy, after the clone, and does not bound the clone. A name must match `[A-Za-z0-9][A-Za-z0-9._-]*` in the arguments. Hand locks the scope's state while it reads, changes and writes it, and writes each root's copy next to the target and swaps it in, so a failed `update` leaves every root old; an interrupted one is finished by running `update` again. `update` copies again when the source's content differs from the locked hash (a path source: when its content changed) and says `current` otherwise, taking a backup of the previous copy first; with no `NAME` it takes every skill Hand manages in the scope. `update` and `remove` refuse, with exit 3 and no force, a skill whose `SKILL.md` frontmatter lacks the marker (so `secondhand` and `secondhand-cleanup`, which `hand init` owns, and your own skills), one that changed locally since the copy (its hash is not the locked one), and, for `remove`, a marked folder with no lock entry; the detail column says which. Remove or add it by hand after moving your edits away. `outdated` fetches each subscribed source's `ref` into a temp folder (nothing is written to the scope, except that reading a pre-version-2 state file moves it into the lock first) and prints `name,state,scope,source,ref,commit,latest,detail` with the state `current` (source and copy both match the lock), `behind` (the source moved; the copy is untouched), `edited` (the copy's hash is not the locked one; the source did not move) or `conflict` (both), or `error` with the reason in `detail`; `--all` covers the fleet and every project of the fleet. `sync` fetches the same way and acts per skill: an own source that is `behind` is applied with a backup of the previous copy (`<fleet home>/.agents/skills-backups/NAME/` or `~/.agents/skills-backups/NAME/` or, in a project, `<git dir>/hand-skills/backups/NAME/`, one timestamped folder per apply, never pruned) and prints `updated OLD -> NEW`; a third-party source that is `behind` is not applied: `sync` prints its diff (`diff-NAME`, `git diff --no-index` of the copy against the new version) and the commit it resolved, and `hand skills sync --yes NAME@COMMIT` applies exactly that commit (the whole id: 40 hex characters, 64 in a SHA-256 repository, never a prefix; a path source with no commit names the whole hash of its content), because a skill steers workers that run with permissions skipped; if the ref moved since the diff, `--yes` refuses with exit 3 and prints the new diff, and `--yes` with no `@COMMIT`, or with a prefix of the commit, refuses too, exit 3; the guard is on `sync` only, `hand skills update NAME` still applies a third-party source you name with no diff; an `edited` or `conflict` copy is never overwritten by `sync`, whatever its source; `current` stays. A project copy that is dirty in git is refused by `sync` like by `update`. `sync` exits 3 when a skill is refused (not for `behind`, `edited` or `conflict`). `hand update` runs `hand skills sync --fleet` and `hand skills outdated --all` in every fleet with the new binary, after `hand init` has run in every fleet (also when the binary is current), and puts what is still behind or edited, and the scopes whose skills could not be checked, in its help lines (the user scope, `~/.agents`, is not visited); a failure of either is one short help line (the first three lines or 300 bytes of its output) and never fails `hand update`. Each command fetches each distinct source and ref once, so `hand update` fetches a source at most twice per fleet, once for `sync` and once for `outdated --all` (which covers the fleet and every project in one command); every git call stops after 90 seconds and a command after 3 minutes, killing git's process group and deleting the temp folder (on Windows only `git.exe` is stopped, not its helpers, so a helper holding the clone can leave that folder behind after a timeout, which no test covers there; the 3-minute budget still bounds the command), and a source that failed once in a command is not tried again in it. Hand has no restore command: a backup is the previous copy, and copying it back over the roots makes the skill `edited` (its hash is no longer the locked one), which `sync` leaves alone. A state file from before the version 2 lock (`.agents/skills/.hand-skills.json`, marker `managed-by: hand-skills`) is moved into the lock the first time a skills command reads it, for each skill whose copies still match its old checksum; the others are left as unmanaged folders, and the entries that did not move stay in the file (it is removed when none is left), so a later command can still read the source and commit they record. `hand doctor` has a `skills` row for the fleet and user scopes, also outside a fleet (then it checks `$HOME` only): `warn` when a managed skill drifted (a folder missing, changed or unmarked) or a path source is gone. |
| `hand models [--refresh] [HARNESS]` | Show each harness's [model list](vocabulary.md#model-list): `models` rows of harness, model, label, efforts and source, and `listings` rows of harness, version, age and state, with the reason when there is no list. It reads the cache and needs no fleet; `--refresh` first runs each harness's listing command (every harness, or just `HARNESS`) and rewrites its cache. A harness that cannot list is a state, not an error. |
| `hand luvus pin [BIN]` | Pin a copy of a Luvus binary (default: `luvus` on `PATH`) for this fleet, under `luvus/<os>-<arch>/` in the fleet folder. |
| `hand luvus show` | Show the pinned Luvus and the version of the fleet's running server (from a UHP `ping`), with `match: yes`, `no`, `not running` or `unknown`. |
| `hand orient [--since CURSOR]` | Print the bounded fleet summary the supervisor starts a session with. With `--since CURSOR` (an event cursor from `hand orient` or an earlier `--since` run) it prints what changed after it, with the open decisions and unacked reports: see [Supervisor orientation](vocabulary.md#orient). `hand attempt track` prints a `track` table: one row per harness, model and effort, counting the attempts that have ended. Every column except `n` and `median_min` is a share of `n`. It reads the `event` table through the index `event_kind_task` (schema 18): a `hand` older than this refuses a database migrated to it, and going back needs a restored backup (see [Restore a backup](update.md#restore-a-backup)).

- `n`: ended attempts.
- `first_try`: attempts that were the first on their task, with that task `done` and no later attempt. A task finished by its second attempt counts for neither attempt.
- `reattempt`: attempts followed by a later attempt on the same task.
- `stuck`: attempts with a `stuck` report.
- `sent_per`: `attempt.sent` events per attempt.
- `wakes_per`: `attempt.quiet` and `attempt.blocked` events per attempt.
- `median_min`: the median of minutes from the attempt's creation to its first `done` report, over the attempts that have one. It includes waiting on builds, CI and locks. Empty when no attempt has a `done` report.
