# Commands

Run `hand` with no command to list the commands, and a command with no subcommand, such as `hand attempt`, to list its subcommands. Put flags before the positional arguments; only `hand open` also takes `--delivered` after the ref, `hand task done` its `--deliverable`, and `hand task parent` its `--parent` and `--root`; `hand task deliver` takes its values after the ref. `--home DIR`, given before the command, picks the fleet. `-h` or `--help` after a command that takes flags prints them and exits 0.

| Command | Purpose |
|---|---|
| `hand init [--name NAME] [DIR]` | Make a fleet, or refresh, rename or adopt a moved one. Refuses to make a fleet in a folder holding Hand 0.7 data. |
| `hand fleet list` | List the registered fleets and whether each home is found: it reads the bookmarks in `~/.secondhand/index` and each fleet's `fleet.home` record. |
| `hand fleet move (--dry-run\|--yes) [--from OLD] [--rewrite-only] [PATH]` | Rewrite the fleet's recorded home paths and move its folder. The fleet's name follows the folder while it still equals the old folder's base name (on Windows, ignoring case): the move or `--rewrite-only` renames it to the new folder's name in the same transaction and records `fleet.renamed`, so a name that differs from that base, including one set with `hand init --name`, stays. Exactly one of `--dry-run` and `--yes` is required, and so is `PATH` unless `--rewrite-only` is given. `--from OLD` names the home to rewrite (default: the fleet home the command selects, and required when the database records no home); `--rewrite-only` rewrites to the selected fleet home, the folder it runs in or `--home DIR`, and leaves the folder there, which is how a copy on another filesystem is adopted after the original is deleted or moved and `hand init` adopts the copy. `--dry-run` lists every cell that would change, the absolute and `~/` occurrence counts and the result of the verification; it writes nothing to `hand.db`, though it can create or change `hand.db-shm` and `hand.db-wal`, and needs a writable folder. `--yes` rewrites every text column in one transaction in the plain, `file://`, `\/` and JSON `\u002f` spellings (and on Windows slash and ASCII case variants), except the `fleet.moving` and `fleet.moved` event rows, which are history and can keep an older home in them, scans the database independently of the rewrite, reports every hit in those columns and refuses while one remains, naming each cell and the manual fix, runs `foreign_key_check` and `integrity_check`, records the new home, writes a `fleet.moving` marker, closes and moves the folder, points the bookmark in `~/.secondhand/index/<id>` at it and appends `fleet.moved`. `~/<old folder>` becomes `~/<new folder>` only when both folders are direct children of `$HOME`; otherwise it becomes the absolute destination, and a `~/<old folder>` that is not the old home is left for you to edit, which the dry run lists and the move refuses. Letters, digits, `_`, `-`, `.`, `+`, a space and a non-ASCII byte are name bytes, so a path followed by one is a longer name (`fleet-hand.bak`, `fleet-hand backup`), never the fleet, except that a `.` at the end of the cell or before whitespace ends the path; `/` and `\` separate it from what follows. A `hand.db.pre-move-<time>` copy is written before the rewrite. It refuses a live supervisor, attempt, watcher or board, pending supervisor input, an armed timer, a destination that is not empty, the same or a nested path, another filesystem, a fleet missing from the registry, and a folder whose database records another home: `--from` alone does not allow that move, so run `hand fleet move --rewrite-only --yes --from OLD` there first. A move (without `--rewrite-only`) also rewrites its `gitdir:` prefix of every worktree gitfile under `~/.secondhand/worktrees/<fleet id>/` that names the old home, reports the rewritten, already correct and broken worktree counts, and fails when one is left broken; `--dry-run` reports the same counts and writes no gitfile. |
| `hand fleet import [--dry-run] SRC INTO DST` | Copy another fleet's projects and tasks, its `memory/`, `deliverables/`, `plans/`, `inbox/`, `reports/` and `briefs/` files, and its report bodies as archive files, without rewriting history; `--dry-run` prints the manifest and writes no row, file or marker, though SQLite may create `hand.db-shm`/`-wal` beside a database it opens, and it cannot detect an unwritable destination (see [Fleets](fleets.md#import-another-fleet)). |
| `hand project add NAME PATH`, `hand project list` | Register a repository by its absolute path, and list projects. |
| `hand project note NAME TEXT`, `hand project notes NAME` | Append a dated entry to the project's `notes/NAME.md` in the fleet home, created with a `# NAME — notes` title when missing, or print the file as a `notes` block; multi-line text is kept, empty text is a usage error, and an unknown project is refused with the names Hand knows. `notes` shows `no notes` for a registered project without a file. |
| `hand project trust NAME` | Accept the project's current git settings that name a program, after Hand refused to run git because they changed; prints each value. |
| `hand task add [--goal TEXT] [--parent tN] PROJECT TITLE` | Capture a request as an `inbox` task, under another task with `--parent`. |
| `hand task parent tN (--parent tM \| --root)` | Move a task under another one, or make it a root. A task cannot sit under itself or one of its own descendants. |
| `hand task start tN`, `hand task done [--deliverable PATH_OR_URL] tN`, `hand task abandon tN` | Move a task to `active`, `done` or `abandoned`. `--deliverable`, repeatable, records a file or link the supervisor produced itself: an http(s) URL or an absolute path; any other value is refused, and then nothing is recorded and the task stays as it was. `done` and `abandon` on a task with open sub-tasks finish it and print a `warn`. |
| `hand task deliver tN PATH_OR_URL...` | Record a deliverable on an `active` or `done` task, for a late or missing one: one `task.delivered` event per value, the same value rule as `--deliverable`, and the task's status, finish date, plan and reports stay as they were. A task in the inbox or abandoned is refused, and so is a bad value (exit 2), and then nothing is recorded, not even the good values of the same call. A value the task already has as a `task.delivered` event is skipped and listed under `already recorded`, so a backfill can run again; a value that only appears in a report's `Delivered:` line is recorded anyway, and the readers show it once. |
| `hand task list [--status LIST] [--q TEXT] [--since DATE] [--until DATE] [--limit N] [--flat]`, `hand task show tN` | List tasks newest first (default `inbox,active`; `--status` takes the board's words: `inbox`, `active`, `done`, `abandoned`, `finished` for done and abandoned, and `all` alone for every status), or show one with its parent, children, plan, attempt, wait, report, deliverables (newest first) and decisions. The list places each child after its parent, oldest root first, and adds a `parent` column only when a row has a parent; `--flat` prints the plain table, newest first. `--q` searches every status unless `--status` is given, and keeps tasks where every word, in any case, is in the title or goal or is the whole ref (`t12`). `--since` and `--until` take a UTC `YYYY-MM-DD` and filter on the day a task finished (`done` or `abandoned`; its last update otherwise). Rows of finished tasks carry that day in a `finished` column. |
| `hand plan set --body-file PATH tN`, `hand plan show tN` | Add a plan revision (or `--body TEXT`), and show the current one. |
| `hand attempt start --harness H --model M --effort E [--mcp FILE] --prompt-file PATH tN` | Start a worker in a new worktree from the repository's fetched default branch (`origin/HEAD`, else `origin/main`, else `origin/master`, else its current branch; from a remote ref, unpushed local commits are left out, so pass `--base HEAD` to keep them); `--harness` is `claude`, `codex`, `opencode`, `agy`, `copilot` or `omp`, and a start with none is a usage error (see `hand models`; opencode takes no model or effort, and agy no effort) (a model Hand cannot verify starts anyway and the output carries a `warn` field; `copilot` takes `--model auto` and an optional `--effort`, and runs a model its plan lacks on Auto without failing, which Hand notes as `attempt.blocked` when it sees the line at launch, as it does a signed-out Copilot), `--mcp FILE` gives a `claude` worker one MCP config, a path inside the fleet home (see [MCP](vocabulary.md#mcp); other harnesses are refused with exit 2, a link is followed only to a file inside the home and never into `scratch/`, and `--continue` does not inherit it), `--base REF` picks another start point, and `--continue aN` checks out the branch of `aN`, an ended and cleaned attempt of the same task, so pushes reach its PR. Starting a worker ends the task's wait, if it has one (`hand wake --waits`). The pane starts through a hidden `hand attempt _exec` wrapper that makes the attempt's scratch folder and points `TMPDIR`, `TMP`, `TEMP`, `GOTMPDIR` and `CLAUDE_CODE_TMPDIR` at it; `--continue` starts a fresh scratch folder because the one of the attempt it continues is removed by `clean`. |
| `hand attempt track` | Print the track record: a `track` table, below. |
| `hand attempt list [--task tN] [--limit N]`, `hand attempt show aN` | List attempts, or show one with its live agent state, or the last screen the watcher read from one that ended. |
| `hand attempt read [--lines N] aN` | Print a running worker's screen, as an indented multi-line block, and its revision. |
| `hand attempt keys --revision N aN KEY...` | Answer a worker's screen, only if it is still at that revision. Luvus names the keys: `enter`, `esc`, `up`, `down`, `ctrl+c`, a single character; it refuses any other as `unknown key`, so a modified key such as Shift+Left cannot be sent. |
| `hand attempt send --text TEXT aN` | Send a worker a message (or `--file PATH`, or `--file -` for stdin), only while it is at its prompt. |
| `hand attempt stop aN`, `hand attempt clean [--discard] [--keep-scratch] aN` | Stop a worker, and remove an ended attempt's worktree while keeping its branch. Clean also removes the attempt's scratch folder (`<fleet home>/scratch/tN-aM`), which holds a new `claude` worker's Claude Code directory, and any Claude Code directory it finds outside it from the operator's environment (a pane started before this change); each is a `scratch_removed` row with its size. `--keep-scratch` leaves them and prints them as `scratch_kept`; `attempt gc` lists them once the worktree is gone. |
| `hand attempt switch aN --model provider/id [--effort VARIANT]` | Switch an opencode worker's model, only while it is idle or done at its prompt and opencode runs no turn of its session (otherwise it refuses and changes nothing; it checks the prompt again just before it stops the pane, so a message that started a turn in between also refuses). It stops the pane, runs `session.switchModel`, and starts `opencode --standalone --auto --session ID` again in the same worktree with no brief, and waits up to 30 seconds for the new pane to settle; a `hand attempt send` before that can be refused as not at a prompt. The attempt's model and effort are recorded in the same transaction. The worktree is not swept, so the worker's background shells and dev servers in the pane's process tree end with it, as does its unsent text (`warn`), and a terminal that will not close is a `warn` too. A model not in `opencode models` is refused. A switch that fails puts the old pane back; when no pane can start, the attempt is `interrupted`, and the error names `hand attempt clean aN` and `hand attempt start tN --continue aN`. A switch killed between the stop and the new pane leaves the attempt `running` with no pane, and the next command ends it `exited`: recover it the same way. |
| `hand attempt gc [--apply] [--older-than DURATION]` | List the attempt scratch folders (`<fleet home>/scratch/tN-aM`) and the Claude Code scratch directories of worktrees that no longer exist (a dry run); `--apply` removes them, and `--older-than 72h` keeps those with anything modified more recently. Both print a `warn` for each directory they cannot remove and still remove the rest. |
| `hand gc --older-than DURATION [--yes] [SCOPE...]` | Without `--yes`, list the files in the fleet's `reports/` and `shots/` not modified for DURATION (days, like `30d`), grouped by task folder with their size, and the total; nothing is deleted. With `--yes`, scan again and delete the files that qualify then (run the dry run just before, and compare), or only those under the SCOPEs (`reports`, `shots` or a path inside one, after the flags). `memory/`, `briefs/` and worktrees are never listed. |
| `hand report add --status STATUS --file -` | Report from inside a worker's worktree: `progress`, `done` or `stuck`, from stdin, a file, or `--text`. |
| `hand report list [--task tN] [--attempt aN] [--unacked]`, `hand report show rN` | List and read reports. |
| `hand report ack [--by NAME] rN` | Acknowledge a report. |
| `hand decision ask [--file PATH\|-] tN [QUESTION]` | Ask the operator about a task; the first line is the headline (at most 120 characters). |
| `hand decision answer [--by NAME] dN ANSWER`, `hand decision withdraw dN` | Answer or withdraw a decision. |
| `hand decision list [--all]`, `hand decision show dN` | List open decisions (or all), and read one with its answer. |
| `hand skills list [--user]`, `hand skills add [--user] NAME\|PATH\|URL`, `hand skills update [--user] [NAME]`, `hand skills remove [--user] [NAME]` | List and manage skills that are not the two `hand init` ships. `list` prints `name,source,commit,scope,managed` for the skills in the fleet home's `.agents/skills`, and those two as `hand init`, `managed: no`. `add` copies (never links) a skill folder into `.claude/`, `.agents/`, `.grok/` and `.pi/` under `skills/`, writes `managed-by: hand-skills` into its `SKILL.md` frontmatter, and records its source, commit, scope and a checksum of the copy in `.agents/skills/.hand-skills.json`. A `PATH` is a folder holding `SKILL.md`; a `URL` (`https://`, `file://`, `git@`) is a git repository whose root is the skill, named after the repository; a bare `NAME` is `skills/NAME` in `https://github.com/atqamz/hand-skills.git`. Git runs through the same helper as Hand's other git calls: a shallow clone into the temp folder, deleted after, with `GIT_TERMINAL_PROMPT=0` and, when neither `GIT_SSH_COMMAND` nor `GIT_SSH` is set, your `core.sshCommand` (default `ssh`) with `-o BatchMode=yes`, so a private `https://` or `git@` URL fails instead of asking for a password, a passphrase or a host-key answer. A skill folder over 32 MiB (the sum of its files, `.git` aside) is refused; the cap applies to the copy, after the clone, and does not bound the clone. A name must match `[A-Za-z0-9][A-Za-z0-9._-]*`, in the arguments and in `.hand-skills.json`. Hand locks the state file while it reads, changes and writes it, and writes each root's copy next to the target and swaps it in, so a failed `update` leaves every root old; an interrupted one is finished by running `update` again. `update` copies again when the source's commit moved (a path source: when its content changed) and says `current` otherwise; with no `NAME` it takes every recorded skill. `update` and `remove` refuse, with exit 3 and no force, a skill whose `SKILL.md` frontmatter lacks the marker (so `secondhand` and `secondhand-cleanup`, which `hand init` owns, and your own skills), one that changed locally since the copy, and, for `remove`, a marked folder with no record in `.hand-skills.json`; the detail column says which. Remove or add it by hand after moving your edits away. `--user` does the same under `$HOME` (`~/.agents/skills` and `~/.claude`, `~/.grok`, `~/.pi`, the folders `hand init` also writes) and needs no fleet. `hand doctor` has a `skills` row, also outside a fleet (then it checks `$HOME` only): `warn` when a managed skill drifted (a folder missing, changed or unmarked) or a path source is gone. |
| `hand models [--refresh] [HARNESS]` | Show each harness's [model list](vocabulary.md#model-list): `models` rows of harness, model, label, efforts and source, and `listings` rows of harness, version, age and state, with the reason when there is no list. It reads the cache and needs no fleet; `--refresh` first runs each harness's listing command (every harness, or just `HARNESS`) and rewrites its cache. A harness that cannot list is a state, not an error. |
| `hand luvus pin [BIN]` | Pin a copy of a Luvus binary (default: `luvus` on `PATH`) for this fleet, under `luvus/<os>-<arch>/` in the fleet folder. |
| `hand luvus show` | Show the pinned Luvus and the version of the fleet's running server (from a UHP `ping`), with `match: yes`, `no`, `not running` or `unknown`. |
| `hand orient` | Print the bounded fleet summary the supervisor starts every turn with. |
| `hand inbox size` | Show the attachments in the fleet's `inbox/`: how many, their size, the age of the oldest and of the newest, and the trash. |
| `hand inbox prune --older-than DURATION [--dry-run]` | Move the attachments older than DURATION (days, like `30d`) to `inbox/.trash/`, and delete the files in the trash for more than 7 days; `--dry-run` only lists them. See [Clean the inbox](inbox.md). |
| `hand wait [--after CURSOR] [--timeout DURATION]` | Block until a wake event arrives, for a supervisor opened by hand. |
| `hand wake --after DURATION\|--at TIME\|--every DURATION [--while tN] [--waits] [--note TEXT]` | Arm a timer (refused without a running managed supervisor) that wakes it once after a delay, once at an RFC 3339 time, or repeatedly; `--while tN` cancels it when that task is done or abandoned; `--waits` (with `--while`, one-shot, at most 30 days away) marks tN as waiting on an outside party until it fires. A DURATION takes days too (`3d`). See [Timers](supervisor.md#timers). |
| `hand wake list`, `hand wake cancel wN` | List the armed timers, or cancel one. |
| `hand watch [--every DURATION] [--notify=false]` | Run the fleet's watcher. |
| `hand watch stop` | Stop this fleet's watcher, and only if `watch.pid` still names the process that wrote it. A running board starts a watcher again within 30 seconds when the fleet needs one: run `hand board stop` first to keep it down. See [Stop the board or a watcher](autostart.md#stop-the-board-or-a-watcher). |
| `hand supervisor start [--harness H --model M --effort E]` | Start the managed supervisor; with no flags it copies the last one, and with no earlier supervisor it asks for the three flags. A model Hand cannot verify starts anyway, and the output carries a `warn` field; `resume` and `switch` print it too. `copilot` runs workers only and is refused. An `omp` supervisor is found by its launch cwd and marker under the agent folder's `sessions/`, and resumed with `--resume ID`; a custom `--session-dir`, named profile or `PI_CODING_AGENT_SESSION_DIR` breaks that discovery. |
| `hand supervisor resume`, `hand supervisor stop`, `hand supervisor show` | Continue the last session, stop it, or show its state, screen revision and number of queued messages. |
| `hand supervisor send --text TEXT` | Queue a message for the supervisor (or `--file PATH`, or `--file -` for stdin). |
| `hand supervisor keys --revision N KEY...` | Answer the supervisor's blocked screen with `enter`, `esc`, `up`, `down`, `1`, `2` or `3`. |
| `hand supervisor interrupt` | Press Escape in the supervisor's terminal. |
| `hand supervisor force` | When Luvus misreads the supervisor as blocked but its screen shows an empty Claude Code prompt, type the queued messages (or else the wakes) into it. |
| `hand supervisor switch --model M --effort E` | Switch the model or effort after this turn, or `--cancel`. `--harness H` switches to another harness between turns (`claude`, `codex`, `opencode`, `agy` or `omp`; not `copilot`, which runs workers only). |
| `hand board [--addr ADDR] [--peer-addr ADDR] [--iroh] [--update-every DURATION]` | Serve the board for every fleet. `--peer-addr` (loopback only, off by default) opens a second listener for a local tunnel, where every request counts as remote: see [the peer listener](phone.md#the-peer-listener). `--iroh` opens that listener on a free port, starts the `hand-iroh` sidecar as the board's child and shows its state: see [the hand-iroh sidecar](phone.md#the-hand-iroh-sidecar). |
| `hand board stop` | Stop the running board, and only if `board.pid` still names the process that wrote it. Watchers keep running. See [Stop the board or a watcher](autostart.md#stop-the-board-or-a-watcher). |
| `hand open [--print] [REF]`, `hand open tN --delivered` | Open the fleet page, a task, decision, report or attempt, or a task's newest deliverable, starting the board first when none runs. `--print` prints the login link instead, for another device or browser. |
| `hand attach [supervisor]`, `hand attach aN` | Open the fleet's Luvus session, the supervisor's terminal, or a worker's. |
| `hand unit board` | Print the board's systemd user unit (Linux only; on macOS and Windows it exits 2, see [Autostart](autostart.md#run-the-board-at-login)). It starts with the graphical session. Your `PATH`, and a `SECONDHAND_HOME` if set, go into the unit. |
| `hand update [--channel edge\|stable] [--check] [--keep-luvus] [--auto]` | Update the binary from its channel, back up and refresh every fleet, restart each fleet's watcher and the board, pin the tested Luvus, and install the `hand-iroh` sidecar and the Linux `hand-desktop` window the release carries (a current hand still installs a missing or mismatched one). |
| `hand version` | Print the version, the channel (`source`, `edge` or `stable`), the commit, the state schema, the tested Luvus and the tested hand-iroh. |
| `hand doctor` | Check this machine and the fleet without repairing anything, one `check,state,fix` row each, with an `info` row `models NAME` per harness (how many models it lists and from where, the cache's age, or why there is no list); a `modes` row warns on Linux and macOS when the fleet's filesystem does not enforce file modes (a FAT or exFAT volume); exits 1 when a check fails. With no harness installed, a `harness` row warns (exit 0). |

`hand attempt track` prints a `track` table: one row per harness, model and effort, counting the attempts that have ended. Every column except `n` and `median_min` is a share of `n`. It reads the `event` table through the index `event_kind_task` (schema 18): a `hand` older than this refuses a database migrated to it, and going back needs a restored backup (see [Restore a backup](update.md#restore-a-backup)).

- `n`: ended attempts.
- `first_try`: attempts that were the first on their task, with that task `done` and no later attempt. A task finished by its second attempt counts for neither attempt.
- `reattempt`: attempts followed by a later attempt on the same task.
- `stuck`: attempts with a `stuck` report.
- `sent_per`: `attempt.sent` events per attempt.
- `wakes_per`: `attempt.quiet` and `attempt.blocked` events per attempt.
- `median_min`: the median of minutes from the attempt's creation to its first `done` report, over the attempts that have one. It includes waiting on builds, CI and locks. Empty when no attempt has a `done` report.
